# v3.1 One-tap X posts (design)

Status: design, 2026-10-22. No code yet. Rulings are overridable; each notes its cost if wrong.

Why: Backing volume comes from builders posting on X, and builders rarely post. No paid X API: EarnKit drafts, the reply's one https link opens X's composer prefilled, the builder taps Post, and the page link unfurls a card with the numbers. Traders punish shilling, so every rule favors fewer, truer posts.

Reuses: `shareResponse` (302 to `x.com/intent/post`), `benchCard`/`card.png`, the Monday moment (`momentPost`, Task 16 step 7), and `project_updates` (facts, summary, builder note).

## 1. Moments worth posting

Limits: 1 offered draft per person per 7 days, plus 1 builder-asked per 24 h (3 a week max). Same moment kind (not weekly) at most once in 28 days.

| Moment | Trigger (existing data) | Cooldown | Don't post when |
|---|---|---|---|
| Weekly recap | Monday moment; week `hasFacts` and a shown summary (`weekLineRule`) | 13 days since the last tapped weekly, unless the week also has a milestone, `went_live` or `won` | No summary, or the only fact is the streak. The moment still shows; the link is the page. |
| Went live | `went_live` event (week-facts.ts, once per project ever) | Once per project | Site probe flapped (builder_live first day under 2 days old) |
| Won a program | `entry_outcomes` with basis `announcement`, result `won` or `placed` | Once per program | Self-reported only |
| Accepted or funded | `builder_program_status` (self-reported) | Once per program | Builder's own claim; never on the card |
| Streak milestone | Weeks in a row hits 4, 8, 12, 26, 52 (`streakOf`) | Folds into that Monday's recap | Never a post of its own |
| Builder's own news | `tell update { text }` mid-week | 24 h | Text fails `checkUpdate` |
| Backing opened | `raising_on` (EARNKIT_RAISING on) | n/a | Ruling: never its own post (reads as a shill). Turns the card's Backing panel on; the next real moment may come 5 days early. Cost: one launch-day spike. |
| Applied | none | n/a | Never: not traction. |
| First users | none | n/a | No auto trigger (R16b stopped counting people); only in the builder's own note. |

## 2. Writing rules

Source facts only: summary, builder's note, week facts, streak, project name, an announced win and award. Deterministic composer, no new LLM call. Cost if wrong: posts read plain, which beats slop.

- Voice: the builder, plain, past tense. Their note goes in verbatim when it passes `checkUpdate`, and always wins over our wording.
- Length: 60 to 200 characters, plus the page link X adds. No second link.
- Shapes, rotated: never one of the person's last 2 shapes, never the last draft's first word:
  - `name_week`: "<Name>, week <n>: <summary, first letter lowered>"
  - `change`: "<summary>" alone (the card names the project)
  - `note`: the builder's note alone
  - `count`: "<n> weeks shipping <Name> without missing one. This week: <summary lowered>" (milestones only)
  - `live`: "<Name> is live. <n> weeks from first commit."
  - `won`: "<Name> won the <program>[ (<award>)]."
  - `bare`: "Week <n>." (milestones of 12 and up, card does the talking)
- Banned in EarnKit-written text (test-enforced): excited, thrilled, proud to, announce, game changer, game-changing, revolutioniz, seamless, empower, unlock, journey, LFG, WAGMI, moon, gem, alpha, 100x, to the moon, don't miss, buy, back me, back the, ape, "just shipped" twice in a row, hashtags, cashtags, emoji, em dashes, exclamation marks, "on EarnKit".
- Backing in text: never by default; the card implies it (open question 1).

Good, from fixtures:

1. Maya, Recipes, week 6, summary "Added offline mode and fixed several sync bugs.": `Recipes, week 6: added offline mode and fixed several sync bugs.`
2. Next tapped weekly for Maya (shape rotates), summary "Rebuilt search so it works on ingredients.": `Rebuilt search so it works on ingredients.`
3. Dev, note "first paying customer today, $9/mo, from a stranger": `first paying customer today, $9/mo, from a stranger`
4. Sam, Tally, went live, 9 weeks of commits: `Tally is live. 9 weeks from first commit.`
5. Lee, Ledgerline, 12-week streak, summary "Added CSV export.": `12 weeks shipping Ledgerline without missing one. This week: added CSV export.`
6. Lee, announced win: `Ledgerline won the Base Builder Grant ($5,000).`
7. Ana, Pollen, 26-week streak: `Week 26.`
8. Kit, week 3, summary "Cut onboarding to two screens.": `Kit, week 3: cut onboarding to two screens.`

Bad:

1. `Excited to announce Recipes just shipped offline mode! LFG $RCP #buildinpublic`: hype, cashtag, hashtag. A shill.
2. `Week 7 shipping Recipes. earnkit.com/maya`, the seventh time: today's template. No content, so followers mute it.
3. `Recipes is revolutionizing home cooking with a seamless offline-first experience. Back the vision.`: unprovable, AI cadence, asks for money.

## 3. The short link

- Route: `https://earnkit.com/<handle>/post/<code>` (`/b/<handle>/post/<code>` for reserved handles, via `pagePath`). `code` is 10 random base32 chars.
- Table (append to schema.sql, idempotent):
  `CREATE TABLE IF NOT EXISTS post_drafts (code text PRIMARY KEY, builder_id integer NOT NULL, project_key text, moment text NOT NULL, shape text NOT NULL, text text NOT NULL CHECK (char_length(text) <= 240), card jsonb NOT NULL DEFAULT '{}', week date, created_at timestamptz NOT NULL DEFAULT now(), expires_at timestamptz NOT NULL, taps integer NOT NULL DEFAULT 0, first_tap_at timestamptz, visits integer NOT NULL DEFAULT 0, x_visits integer NOT NULL DEFAULT 0, said_posted boolean);` plus an index on `(builder_id, created_at DESC)`.
- GET: the `live` check as `shareResponse` (hidden/unknown 404, rename 308), then 302 to `x.com/intent/post?text=<text>&url=https://earnkit.com/<handle>?m=<code>`, built from the row only (no open redirect), `no-store`.
- Taps: `UPDATE ... SET taps = taps + 1, first_tap_at = COALESCE(first_tap_at, now()) WHERE code = $1 AND taps < 100`. No IP, no user agent stored. One `post_tapped` event on the first tap (new EVENT_TYPES entries: `post_drafted`, `post_tapped`).
- Expiry: 14 days, then a 302 to the page. A code of another builder: 404.
- One-link rule: this is the reply's only https link; the quoted post is text only (X adds the page from `url`).

## 4. The card

The post's page link carries `?m=<code>`; `handleMetadata` points `og:image` to `card.png?m=<code>`. X caches cards per URL, so each post keeps its own card.

- Snapshot: the moment's facts are frozen in `post_drafts.card` when drafted (week, summary, streak, commits that week, rank only from RANK_MIN_POOL). The Backing panel is read live.
- Headline per moment: weekly shows "Week 6" with the summary under it. Went live shows "Live" with the weeks it took. Won shows the program and award. Milestone shows the streak number, very large. Note posts show the week and the summary, never the note again.
- Numbers row: weeks in a row, commits that week, Shipping. With EARNKIT_RAISING on and a coin: the pill `Backing · $SYM`, and from 5 backers a "backers" number (`backersOfCoin`). Ruling: no price; X keeps the image for days and a stale price is a false number. Cost: a weaker trader hook.
- Backing is implied by the pill and backers beside shipping proof; the text never says it.
- Not templated: 3 layouts (number-led, text-led, milestone) by moment, and the real summary differs weekly. Same renderer and `CARD_CACHE`: about one render per post, no new service.

## 5. Measurement

Drafted (row) to tapped (`taps > 0`) to opened from X (`x_visits`: `?m` renders with a t.co referrer, bots filtered, capped) to backers (`newBackers(builderId, first_tap_at)` within 7 days, raising on; correlation only). All on `post_drafts`. The owner sees `/api/stats` keys `posts_drafted`, `posts_tapped`, `post_x_visits`, `backers_after_post` (no test installations).

## 6. Reply copy

Order unchanged (connect, apply, backing, share, ship); drafts live in the share slot. Ruling: went live and won jump ahead of apply for 48 hours (a stale launch post is worthless). Cost: apply waits one reply.

Weekly, with a draft (replaces Task 16 step 7):
```
Week <n> done. You're <still #r | now #r | on EarnKit>: +<pts> points.
Your post for X, with your page card:
"<post text>"
Post it in one tap: <short link>
Does last week look right?
```
Weekly, no draft (nothing new to say):
```
Week <n> done. You're <still #r | now #r | on EarnKit>: +<pts> points.
Your page: <https page>
Does last week look right?
```
Event moment (went live, won, accepted, builder's news):
```
<Name> went live this week. | <Name> won the <program>. | Added to your page.
Your post for X, with your page card:
"<post text>"
Post it in one tap: <short link>
Want a different version?
```
A yes redrafts with the next shape (counts toward limits). `SHARE_NOTE` gains "Show the post text exactly as given. Never rewrite it." `MOMENT_POST_HEAD` and `momentPost` go.

## 7. Tasks

1. Store: schema.sql `post_drafts`, event types, `lib/earnkit/post-drafts.ts` (create with limits, tap, visit). Tests: `post-drafts`, `schema-rerun`, `events`.
2. Writer: `lib/earnkit/post-writer.ts`, pure. Tests: 8 fixtures exact, 3 bad rejected, 26 simulated weeks with no shape or opening repeated in a row, `copy-review`.
3. Moments: `lib/earnkit/post-moments.ts` (triggers, cooldowns). Tests: every section 1 row, including "don't post".
4. Tap route: `app/[handle]/post/[code]/route.ts`, `app/b/[slug]/post/[code]/route.ts`. Tests: `post-route` (target, expiry, hidden, rename, wrong builder, cap).
5. Card: `?m` in `handleMetadata` and `cardResponse`, 3 layouts, visit count. Tests: `card-route` (no Backing when off, no backers under 5, no price, no self-report).
6. Replies: bench-reply.ts, weekly-moment.ts, bench-find, `tell update`. Tests: `v31-reply-copy` exact text, one https link, one question.
7. Stats and docs: stats.ts keys and labels. Tests: `stats`.

## Owner rulings (2026-10-22)

1. Coin launch: one introductory post when the coin first goes live, so traders know a token exists (it may name the ticker once). Never again unless it rides a real win. This replaces "opening Backing is never its own post".
2. 13 days between ordinary weekly posts: yes (default kept; owner did not object).
3. Accepted, funded or won: draft only once the outcome is verified. The agent (most have browser use) checks a public source, such as the program's X post or results page, and passes its URL; EarnKit stores the proof URL with the moment and never drafts on the builder's word alone. Never on the card without proof.
4. Backer count shown from 5 backers: yes.
5. Points: no points lines in these replies (owner removed points lines from the first replies; post replies follow).
