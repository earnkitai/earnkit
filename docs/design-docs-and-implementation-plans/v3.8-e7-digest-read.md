# v3.8 E7: owner digest as a read, revert by bearer, mail deleted

Plan: v3.8 item 10, section 23.2 ("Owner read: plain data plus one line per item"; "Email. None to the owner").
Approval: earnkitai/earnkit#159. Stacked on E6 (`v38/e6-auto-live`): E6 removed the approve email; this removes the
last email and the signed revert link.

## Change

- `owner-digest.ts`: `sendOwnerDigest(now, mailer)` splits into `ownerDigest(now)` (reads only: the same text and
  data, plus `recorded`) and `recordOwnerDigest(now)` (the cron step: writes the `owner_digests` row for the day,
  which is where the next day's window starts; answers `recorded` or `none`). The window rule is unchanged: changes
  since the last digest recorded on an earlier day. A change line names the write to revert:
  `- {title}: {fields} (revert: write {id})`, `(not revertable)` or `(revert unknown)` on a read error.
- `GET /api/programs/digest` (programs bearer): `{ day, lines, changes[{program_id, title, fields, write_id, note?}],
  health, applications, results, recorded }`. `lines` is the digest text one item per line (headings included).
- `POST /api/programs/revert` (programs bearer): `{ write_id }` runs the existing `revertWrite` (single use, latest
  applied write only). 200 / 409 with `state` / 404 / 400. The signed revert link (`revertToken`, HMAC), `revertGet`,
  the confirm page and HTML owner pages are deleted. Revert now follows the API switch: while the programs API is off
  it answers 404 (the old link worked with the API off).
- `mail.ts`, `mail.test.ts` deleted; `RESEND_API_KEY` out of `no-v4.test.ts` `ENV_ALLOWED`, the test guard's
  cleared list, README and the guides. Workflow comments now say a failed run is GitHub's own notice, not EarnKit mail.
- `cron.ts`: `mailer` dep gone; `sendDigest` dep renamed `recordDigest`; the digest step answers `recorded`/`none`.

## Schema

None. `owner_digests.sent_at` now means "recorded at"; the column keeps its name so nothing is migrated.
