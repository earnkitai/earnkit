## 1. The opener has no money line, and Alliance ALL19 is missing

### What happens

1. No ready set forms.
   - `readySet` (`ready-set.ts:41-66`) ranks the candidates (`READY_CANDIDATES` = 6). Base is the only one:
     - Circle is `notEligible` (`ready-set.ts:44`).
     - Alliance never reaches the ctx (point 3).
   - `fitReadySet` (`ready-set.ts:75-93`) moves Base to `out`, because it needs 11 answers, more than the `READY_ANSWERS_MAX` of 4.
   - `readyCommit` therefore stores Base as the also-open lead (`bench-find.ts:1411-1413`) and returns null (`:1414`).
   - The opener's money is built in `readyOpener` from `worthUpTo` (`ready-set.ts:100`) plus the also-open and not-eligible lines. The opener only runs when the set is non-empty, so none of it is said.
2. The reply that does go out is the also-open lead.
   - The path is quiet, so `alsoLeadCommit` (`bench-find.ts:1737-1770`, called at `:2868`) takes the ship or "more" slot.
   - Its text is the proof line, then `alsoLeadLine` (`ready-copy.ts:187-188`), then `ALSO_START_ASK` (`:189`). On repeats it is `alsoAgainAsk` (`:190`) alone.
   - It never calls `moneyFor` or `withMoneyLine`. The session money line ("Open now: $X in grants. Closing soon: ...", `conversation.ts:289`) only comes from `pathCommit` (`bench-find.ts:1013-1017`) and the two other path replies (`:2186`, `:2253`).
   - No total or "what's open" line exists on this route. Only the one program's "pays up to $5,000" is said.
3. Alliance ($400K, closes Nov 18, 15 days out) is cut by a 7-day window at every stage. Each of these alone drops it:
   - `bench-find.ts:718` `INVESTOR_READ_MS = 7 days`, and `:873-876`: `pathPlan` builds `ctx.investors` only from investor cards closing within 7 days. Alliance is not in the ctx at all, so it never reaches `readySet`, `fit.out`, also-open, `worthUpTo` or `bestMove`.
   - `ready-set.ts:60`: readySet's investors are filtered again by `soon(p, INVESTOR_WINDOW_MS)`, which is 7 days (`conversation.ts:170`).
   - `conversation.ts:205`: bestMove does the same (v4.8.1 R1: an investor program is a move only within 7 days, and only after every grant).
   - `moneyLine`'s "Closing soon" applies only under 48 hours (`CLOSING_SOON_MS`, `conversation.ts:258`).
   - Even inside the set, `also` takes only the first 2 of `fit.out` (`bench-find.ts:1417`), and with an empty set only `fit.out[0]` is kept (`:1412`).
   - Today Alliance shows up only in the full programs answer (`ask: programs`, walk S: "Alliance ALL19 | $400K at admission | Nov 18").
   - Its row: `investment = true`, `max_award_usd = 400000`, `chains = {}`, `ends_at` 2026-11-18 23:59:59Z.

### Root cause

The 4-answer cap emptied the set, and the also-open lead that replaced the opener (v4.10.2 Task 5) carries only one program's money. The windows that admit investor programs (7 days) and "Closing soon" (48 hours) are far shorter than Alliance's 15 days. So the biggest open money is invisible until 7 days before it closes.

## 2. "Your score and weeks are updating, so they're not in this reply." reaches the builder

### Where it comes from

- Defined at `bench-find.ts:399` (`UPDATING_LINE`). The agent's half is `UPDATING_NOTE` (`:403`, in `numbers_note`, never shown).
- It is inserted only in `updatingReply` (`bench-find.ts:424-435`). Line `:432` writes it into `show_to_builder`:
  - **find** (`:3518`, `lead: false`): placed before the reply's last paragraph, once a session (`UPDATING_SAID`, `:433`). It is skipped only for a ready view (`isReadyView`, `:427`, `:436`).
    - The also-open lead is kind `apply`, not `ready`, so it gets the line. Run 2 shows the result: lead, then the updating line, then "Want me to start it?".
  - **score** (`:3573`, `lead: true`): the first paragraph of every updating score reply, not once a session.
- Trigger: `tools.ts:1118` `fresh = refresh.started?.within(REPLY_WAIT_MS)`, then `:1128` `updating: true`. In benchScore it is `!fresh && hasNumbers(stored)` (`bench-find.ts:3540`).
- The rest of the path already removes the numbers by itself:
  - `withoutNumbers` (`:415`);
  - `withFacts` drops rank and streak (`tools.ts:2678-2679`);
  - the Monday block waits (`bench-find.ts:2800`, `:2803`);
  - `readyRecord` blanks score, rank and streak (`:1376`).
  - So the line is the only builder-facing trace, and it is pure narration.
- No other file emits it. The only other reference is the merge gate: `fixtures/converse.ts:313-317` `noRecord` treats said `updating` as a reply with no record (exempt from the proof rule).

### Root cause

v4.10.1 Task 3 (R5) chose to say the line to the builder ("exact copy", fix round 1). The numbers were already left out, so the line only describes an internal state.

## 3. Score says 77 and 6 weeks, find's facts say 83 and 7, and 83 is never shown

### Which number each reply shows

**First find, refresh running:**
- Shows: no number (item 2).
- Standing fact: none (`withoutNumbers`).
- Source: none.
- The Monday block is held back because it is updating (`bench-find.ts:2800/2803`, `!o.updating`).

**score, refresh settled:**
- Shows: the Monday block, "Last week": 77, up 7, and 6 weeks.
- Standing fact: "Score 83. 7 weeks ..." (the copy: 69 and 6). No "so far".
- Source of the shown number: `lastWeekOf` (`weekly-moment.ts:176`): the last ranked `builder_scores` day of last week, so 77, the Nov 1 value. The week count is `weekNumber(commitWeeks, last.monday)` (`weekly-moment.ts:136`), which counts up to last week only.
- Source of the fact: `readStanding` (`bench-find.ts:2596`) from `builder_live.parts` (live). `soFar` is false because `momentScoreSaid` is written after `stand` is built (`:2880` vs `:2600-2601`).

**Next find:**
- Shows: `alsoAgainAsk` alone, no number.
- Standing fact: "Score 83 so far this week. 7 weeks ...".
- Source: the same live read. `soFar` is set because 83 differs from the said `moment_score=77`.

**A later score (run 1, call 3):**
- Shows: "Score 69 so far this week. 6 weeks shipping in a row. ..." (production: 83 and 7).
- Source: `standingLed`, now that the share block is gone.

- **The 7 vs 6.** The live streak counts this week as soon as the repo reading has W45 commits: `streak.ts:54` `thisWeekCommits`, then `site-streak.ts:28` adds `isoWeekOf(now)`. The Monday block counts to last Monday. Both are "right", but they are different weeks.
- **Why 83 never shows:**
  - `benchScore` drops the standing paragraph under the Monday block (`bench-find.ts:3563-3564`, `block`).
  - The also-open lead and its repeat are path views with no standing paragraph (`bench-reply.ts:926`: the path is the whole reply).
  - The first find hid all numbers.
  - So in a session that opens updating on a Monday, the only number shown is last week's. The live number lives only in the `standing` fact, where the agent may or may not say it.

### Root cause

Two sources for one idea ("your score"):
- The Monday block is last week's final (`lastWeekOf`).
- Every other reply uses the live `builder_live` score, plus a streak that already includes this week.

The `soFar` patch (v4.10.2 final re-review) labels the second only when it is shown. The also-open lead and the Monday block are exactly the replies that never show it. Score's own `standing` fact also lacks the label, because the moment's `said` key is written after the fact is built.

## 4. "11 answers" is never listed, and each reply asks something different

### The count without the list

- `alsoLeadLine` / `alsoAgainAsk` (`ready-copy.ts:186-191`) say only `answers`.
- The count is `fit.out[0].answers` (`bench-find.ts:1413`), which is `new Set(answerKeys(d.only)).size` (`ready-set.ts:83-86`).
- `d.only` is `builderAsks` (`bench-find.ts:1169-1173`).
- The list exists only after a yes, in `pathRound` (`bench-find.ts:1213-1235`): rounds of at most 4 (`READY_NEED_MAX`), said by `blanksAsk` (`conversation.ts:641-649`) as "Four blanks only you can fill (7 more after these): ...".
- Base's 11 on this copy (walk R, in order):
  - Round 1: team list, usage numbers, demo video, contract address on Base.
  - Round 2: how it makes money, 3-month plan in one line, Base Builder Code, main challenge.
  - Round 3: credits, plus contact name and Telegram (2 answers).
- `ready.programs[].asks` (the per-field list for the agent) is built only in `readyCommit` (`:1444-1455`). That code path isn't reached, so the agent gets no list either. Its `move_up` is a plain apply (`APPLY_NOTE`).

### Why score and find ask different things

The ask is not chosen per tool. benchFind and benchScore share `benchView` and `stateAsk`. The difference comes from three rules:

1. **Order inside `stateAsk`** (`bench-reply.ts:822-829`): `apply`, then `post`, then **`share` (MOMENT_ASK, `:519`)**, then checkin, wallet and the rest, then `ship`/`more`.
2. **The also-open lead runs only on a `ship` or `more` ask** (`bench-find.ts:2868`). So a due Monday block always beats the Base question.
3. **The Monday block is claimed once per week per installation** by the first non-updating reply (`weeklyMoment`, `bench-find.ts:3275-3303`, `takeMoment`). The block is gated off while updating (`:2800`, `:2803`).
   - In the CTO's session the first find was updating, so it said the Base lead.
   - The next call, score, had a settled refresh and claimed the block: "Add last week to your page?".
   - The find after that went back to Base (`alsoAgainAsk`).
   - With no refresh running (walk R and S), find claims the block first instead, and Base comes second.
   - The share offer stays open all week (`openShare`, `share_open`). The builder was asked two different pending questions in a row and answered neither.

### Root cause

- The also-open lead counts answers it never lists.
- The single easy reply is whichever ask outranks the others in that call. The Monday block's place in `stateAsk` depends on who claims it first, and the updating gate decides that.

   - add the session money line ("Open now: $X in grants", `moneyFor`) to the also-open lead;
   - say the total of all open programs the builder could pursue;

2. **Investor windows.** Should a large investor program like Alliance be named before 7 days out?

3. **What score shows on a Monday.** Options:
   - last week's final (the block, 77 and 6);
   - this week so far (83 and 7);
   - or both in the block ("Last week 77, this week so far 83").
   - Related: should the streak count this week before the week ends?

   - drop it and just leave the numbers out (the CTO's ask);
   - or keep it for score only, where the builder asked for the numbers.
5. **"N answers" vs the list.** Options:
   - list all 11 in the lead;
   - list only the first round of 4 with "and 7 more";
   - or keep the count alone.
6. **Monday ask vs the program ask.** When both are due, which is the one easy reply?

   - Options: the Monday ask yields to the program ask, it moves to the reply after a program answer, or it always goes first in the session.
