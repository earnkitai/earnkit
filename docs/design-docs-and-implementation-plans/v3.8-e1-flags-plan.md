# v3.8 E1: the flags helper

**Approval:** Jenil, "Yes, build v3.8" (Nov 24 2026), logged in earnkitai/earnkit#159. Plan: power-user plan v3.8
sections 4 and 20 (L11, rollback by flags); build plan PR table row E1.

**Goal:** One place that says whether a v3.8 behaviour is on, so later PRs (E5 to E18) ship dark and roll back without a
redeploy of different code. EarnKit had no flag system (`controls.ts` is a text cleaner).

**Contract:**

- `EARNKIT_FLAGS`: a comma list of names. Unset or empty means every flag off, which is exactly today's behaviour.
- Names are trimmed and lower-cased; duplicates collapse; a name not in `FLAGS` is ignored (no error, no log), so a typo
  or a retired name left in Railway cannot turn something on or crash boot.
- `FLAGS` is the typed list for this ship: `auto_live`, `x_signin`, `private_rows`, `track_v2`, `draft_check`, `form`,
  `reply_fields`, `copy_v38`, `screen_v2`. `flagOn('typo')` is a type error.
- Read on each call from `process.env` (injectable `env` for tests), not cached at import, matching `people.ts`'s env
  lists. The cost is a split of a short string.
- `EARNKIT_INSTALL_SIGNIN` stays its own variable (it predates this and has its own security gate, E4). Superseded in E4: it became the `install_signin` flag and the variable is no longer read.

**Guards:** `EARNKIT_FLAGS` is registered in `no-v4.test.ts` `ENV_ALLOWED`, and the test guard clears it so no test
inherits a flag from the developer's shell; a test that needs a flag passes `env`.

**Not in this PR:** no code reads a flag yet; each later PR wires its own.
