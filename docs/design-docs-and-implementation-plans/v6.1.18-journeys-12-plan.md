# v6.1.18: journey campaign, round 12 (the owner's three, and sends through EarnKit)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** The owner tested live v6.1.17 (2026-11-12) and found three product bugs: the default reply shows three one-step programs and never says that 18 more are in the full list, UGREEN (one question, closes in 3 days) among them, so only the agent's hidden note knows; a one-program look at PayPal (closes today) for a project with no repo asks for a demo video and lists the missing public repo as a rule the builder confirms; Kiroween's one-program closing reads `Tell me when that is done and I apply.` though the builder submits on Devpost themselves. The owner's goal is as many applications sent as possible, counted: so every send through EarnKit is recorded and visible to the owner, the agent is asked whether a builder-sent form went out, and a form's "how did you hear about us" field says EarnKit.

**Architecture:** The hidden count in `find.ts` (`more` at the selection) and `reply.ts` (`moreInFull`, `defaultRows`, the closing-soon names from `ledger.closing_soon`); the no-repo step in `eligibility.ts` (`NEEDS_CODE` for every `needs_repo` program, `code in a public repo` when `open_source`) and the five catalog files that carry a public-repo rule item the flag already covers, refused from now on by the catalog check in `programs-sync.mts --check`; the builder-submits closing in `reply.ts` (`gapActionOf`, `singleStepClosing` unchanged) fed by `find.ts` (`draftOnly`); the referral field in `prefill.ts`; the "did you send" ask in `ledger.ts` (`sendAsksDue`, table `sent_asks`), `find.ts` (`ask_sent`), `reply.ts` (`sentLines`, agent note); the owner's view in `programs-api.ts` (`applicationsGet`), a new route `app/api/programs/applications/route.ts`, and `owner-digest.ts` (an applications block). Pinned texts updated, never loosened.

**Tech Stack:** as v6.1.17 (Next.js 16.4.1, Postgres, node:test; `DATABASE_URL=postgresql://localhost:5432/earnkit_test`).

**Spec:** this file. Sources: the owner's note (2026-11-12, three findings, quoted in Goal); the live reproduction in the session scratchpad `journeys/lane1k/owner-repro.json` (a no-repo project `Ledgerly`: default reply, PayPal, Kiroween, UGREEN, full list); the owner's question "The goal is to get as many applications in as possible and we need a way to track which ones went through EarnKit".

## Global Constraints

- Builder text: no emoji, no em dash; never score, rank, grade, points, coin, token, streak; every builder line ends with a full stop; never a tool, field or file name; money first, the gap, one action; one `Say` per reply and it is last; one sign-in sentence per reply.
- The default reply stays within `DEFAULT_LINES` (10) lines, the Say included.
- Pinned texts in tests are updated to the new wording, never loosened to regexes.
- Commit messages start with `v6.1.18:`. One implementer per worktree. Docs (`docs/codebase-context/architecture-guide.md`, `code-map.md`) updated in the last task.
- Nothing here changes what the agent may send: a builder-submits program is still drafted for the builder to send.

## Review Focus

1. A project with no repo and a hackathon whose code must be public sees `code in a public repo` as its first step, never as a rule to confirm; a yes to the rules does not make it ready (Task 2 pins it).
2. The more line counts the programs the rank cap hid, not only the ones the line budget hid, and never counts an in-person program twice (Task 1).
3. A builder-submits program's one-program closing never says `I apply`; a program the agent may send still does (Task 3).
4. The "did you send" ask shows once a week per installation and program, stops the moment an applied row exists, and never fires on a program the agent sends (Task 4).
5. The owner's applications list names no email and no sign-in code; it is 404 while the programs API is off and 401 on a wrong token, like `/api/programs/writes` (Task 5).
