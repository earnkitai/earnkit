## Global Constraints

- Builder text: no emoji, no em dash, never score, rank, grade, points, coin, token, streak; every builder line a full stop; never a tool, field or file name; the first reply is money first, the gap, one action; yes means EarnKit does it, so "do n" is offered only where the agent can do the change.
- Pinned texts updated, never loosened. Commit messages start with `v6.1.8:`.
- Docs updated after the last task.

## Review Focus

1. A web2 SaaS with no chain never sees a chain contract as a step; its ready list holds only programs whose rules it can meet or confirm.
2. A project whose repo was not read (reads paused, or private) is gated the same way as one that was read; the reply says the match used what was reported.
3. A Solana project that reports mainnet is not told to deploy on Solana.
4. Relinking after an unlink never turns a win into anything else.
5. The builder's edit of an approved answer leaves no approved short form behind.

### Task 1: the fit

**Rulings:**
- B20: tier for every project: own evidence, else provisional from the read, else provisional from the report (live_url: live; a repo named: building; nothing: null). Null against a `min_tier` is not a fit, reason `needs a {tier words}` (under filter.all's not_fit). Reads paused or private: the reply carries one sentence `Repo reads are paused until tomorrow; matched on what you told me.` or `Private repo: matched on what you told me.` (the existing as_reported sentence, if one exists, is reused, not doubled).
- C54: a project with no chain reported and none in the code: chain-required programs (a `chain` or `contract_on` item) are not a fit (`needs a contract on {chain}`), never a gap; a project with any chain keeps today's chain gaps.
- C55: a reported `mainnet: true` for a chain the code read found without a mainnet signal stands (repo-facts.ts merges: code adds chains and contracts, never removes a reported chain or its mainnet flag); `as_reported` stays false when the repo was read.
- B21: Solana addresses are base58, 32 to 44 characters; EVM addresses 0x plus 40 hex; a rejected address is named in the problems line.
- C58: `description` is optional when `repo_url` is given; the README's first sentence stands in (and the agent note says so).
- C59: one sentence for a fork (`This repo is a fork; programs judge the original.`), an archived repo (`This repo is archived; programs want active work.` and it counts as not live), an empty repo (`The repo is empty, so I matched on what you told me.`). GitHub's API carries `fork`, `archived`, `size`.
- C60: the ranking of ready programs uses the larger of `max_award_usd` and `pool_usd` for the money sort (a $1M pool outranks a $100K award). Pin the VR persona's top three.
- 3.3 (lane 5): long-odds text `few prizes for many entries` only for hackathons (prizes or pool), `many apply, few are taken` otherwise.

Files: `eligibility.ts`, `find.ts`, `find-record.ts`, `repo-facts.ts`, `project-input.ts`, `rank.ts`, `reply.ts` (the one sentence); tests alongside; fixtures for a fork/archived/empty repo in `fixtures/repos`.

### Task 4: the record keeps its word (lane 7)

**Rulings:**
- B15: `linkInstallation`'s migration never downgrades: a result beats applied beats started or skipped; equal statuses keep the newer; a conflicting `i:` row is dropped. Test: a win survives an unlink and relink with a skipped row in between.
- B16, B17: /me shows each answer's short form under it (`Short form, for fields under 300 characters.`), approving approves both, an edit of the text clears the short (the agent redrafts it on the next `record brief`), a short with no approved parent is never used (`prefill.ts`).
- B18: `applied` with `submitted_by: 'agent'` is `auto_applied` only when the policy allowed it at that moment (tonight's auto-applied count below `max_per_night`, the program's category in `categories`, the amount within `max_ask_usd`, `agent_may_submit` on, the program not builder-only, not in person); otherwise it is recorded with `auto_applied: false` and the builder line reads `Sent, but outside your standing approval: {reason}.`
- B19: the team list is shown and editable on /me under the person block.
- C41: project-scoped answers are used only when the project name or project_id matches the record's project; the agent note says to pass project_id.
- C42: a record value longer than the field's max is marked `fit: 'cut'` and the agent is told to cut it; never "as given".
- C43: `auto_apply` on with no category refuses the save with `Pick at least one category.` (with v6.1.7's all-or-nothing).
