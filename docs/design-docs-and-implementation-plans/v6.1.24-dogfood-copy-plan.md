# v6.1.24: dogfood copy (track ownership, archived repo, full list)

**Goal:** After the Nov 23 dogfood of live v6.1.23, three builder-facing lines were wrong or incomplete: track said it "could not read" a public repo when ownership was unconfirmed, an archived repo was only "a live repo", and the default find reply named "N more in the full list" without saying the builder can ask for them. This release fixes those lines.

**Scope:** Copy and the tests that pin it, in `apps/frontend/lib/v5/ledger.ts` (`CANT_CONFIRM_REPO`), `track.ts` and `find.ts` (the matching agent notes), `eligibility.ts` (`ARCHIVED_REPO`), and `reply.ts` (`alsoSentence`). `track started` still refuses when the repo is not shown to be the builder's (L28-3: a claim is keyed by the repo and is never written for someone else's). `/api/stats` does not add `activated`: that key was a v3/v4 funnel count (claimed page + EarnKit-app repo proof + a ship-log week) removed in v5, and there is no correct v6 equivalent that is cheap to restore.

**Copy:**

- Track / find, ownership unconfirmed: `I cannot confirm {host/owner/repo} is yours.` On GitHub: `Sign in with the GitHub account that commits to it, or send it yourself and tell me when it is in.` Off GitHub: `Send it yourself and tell me when it is in.` Never "I could not read".
- Archived repo gap: what `a live repo (yours is archived)`, setup `tell me the active repo`.
- Default Also line: `{n} more in the full list, any time you ask` (no second `Say`, so the one-Say rule holds).

**Version:** `apps/frontend/package.json` `6.1.24`, and the serverInfo pin in `mcp.test.ts`.
