# v2.6: Zero friction — bonus everywhere, "you could", one-yes coin

Status: implemented on branch v2.6-zero-friction (2026-10-06); plan: v2.6-zero-friction-plan.md.
Approved 2026-10-05. Builds on v2.5 (`main` 1823018).

## Goal

A non-technical builder goes from "anything worth building?" to a submitted entry with a coin, in
the fewest steps, with nothing to understand. The hook is money they could win now. The coin is part
of entering, never pitched separately.

## Decisions (owner, 2026-10-05)

- **Builder bonus on every program by default.**
  - A program is out only when its file says `builder_bonus: false`, which rarely or never happens.
  - This replaces v2.5's "public submission pages only" rule and Ruling 9 for programs without a proof pattern.
- **Wording.**
  - With repos, the message keeps the brand hook: matching your projects to money you qualify for.
  - With no repo or GitHub connected, the language becomes "You could…", and the message encourages building with the agent.
  - "Qualify" stays; it is the install hook.
- **The no-repo headline** is "$X is open right now."
- **Wallet.**
  - It is asked once, at submission, and becomes the coin's creator reward recipient.
  - It is remembered per installation and prefilled after that.
  - With no wallet, there is no coin; the builder gets one line saying why. No custody, no placeholder wallet.

- **"You could" only when there is no repo:** no repos are reported or found and no GitHub user is given. A test pins both branches.

## 3. Submission and coin: one yes

**Coin row at submission (one line):**

```
Your entry gets a coin, $TIPJAR: you earn 40% of its trading fees, and it enters the builder bonus.
Wallet for fees and any bonus: 0xAB…12 (used last time) — or tell me another.
```

- **No remembered wallet:** the second line is the ask: "Which wallet should get your coin's fees and any bonus?"
- **A yes confirms both** the ticker and the wallet. Skipping stays one word, and the row then says "skip: no coin, no builder bonus."
- **The wallet is remembered** for the installation on every submission, not only on campaign entries, and is prefilled next time. *Final review:* the line says "(used last time)" (M8), and `launch_token` never uses the remembered wallet, only the call's or the entry's own (Ruling 28). *Ruling 30:* `record_submission` doesn't read it either: `prepare_submission` returns the shown wallet as `shown_wallet`, the agent passes it back as `payout_wallet`, and without it the entry gets no coin.
- **No wallet given:** the entry is recorded and the coin is skipped. The note says "No coin yet: send a wallet with launch_token to add it before <round end>."

**Ownership check (`earnkit.txt`)**
- It needs only the `token: <code>` line. The code is bound to the installation and repo, not the ticker, so editing the ticker never needs a new push.
- `payout_wallet` is no longer needed in a public file for coins. Campaign entries keep v2.4's rule.
- The file is read through the GitHub contents API, which has no raw-CDN cache delay. The raw URL is the fallback when the API is rate-limited.
- A coding agent writes and pushes the line itself. The builder is never asked to edit files.

**Live link: no longer a coin gate**
- A coin needs a public repo with real code: at least one commit by the repo owner, and the repo isn't empty or a fork with no new commits.
- A working live link stays a traction signal (live 20 points). It isn't required to launch.
- *Owner approved (2026-10-05):* this replaces v2.3's "project runs" gate.

**Submission proof becomes a bonus check, not a gate**
- **Public submission page** (`submission_proof` pattern set): EarnKit checks the page, as in v2.5.
  - The page loads but doesn't link the entry: not eligible.
  - The page can't be fetched (blocked or 4xx/5xx from bot protection, such as DoraHacks' 405): the builder's confirmation counts, and the entry is marked "unverified page" on the owner's review page.
- **No pattern:** the builder's confirmation at `record_submission` counts. The agent records "submitted on <program site>"; there is no upload and no link.
- **Unchanged safety net:**
  - the coin launched through EarnKit before the round ends;
  - repo ownership;
  - one eligible entry per repo per program;
  - traction ranking;
  - the 48h owner review and veto.
- **Policy page:** "Programs without public entry pages: the builder confirms the submission; the owner reviews the top 10 before paying."

**After submission (new builder-facing reply)**

```
Entered in Arc Microgrants. Your coin: tokens.fun/coin/0x… · you earn 40% of its fees.
Builder bonus: 0.18 ETH so far · ends Oct 14 · earnkit.com/bonus/arc-microgrants-2026-10-01
```

- *Final review (Ruling 29):* every builder-facing round date is the first message's label, the program's real local deadline (Arc: Oct 14, 11:59 PM ET).

- The leaderboard link appears here and in the bonus alerts.
- **Alert wording:**
  - "Fees to claim: $X on tokens.fun"
  - "Bonus paid: 0.12 ETH (as WETH) to 0xAB…12"

## 4. Bonus everywhere: accounting

- **Rounds:** every active program has rounds. Windowed programs get one round per window; rolling programs get calendar months (as in v2.5).
- **Opt-out:** programs with `builder_bonus: false` book deposits to the Safe, and post-end deposits go to the Safe as before.
- **Program file schema:** add an optional `builder_bonus: boolean`, default true. `submission_proof` stays optional.
- **`/api/stats` and the policy page** are updated to say the bonus is on every program unless it is opted out.

## 5. Owner testing without polluting production

- **`EARNKIT_TEST_INSTALLATIONS`** is a comma-separated list of installation ids. These are excluded from `/api/stats`, never ranked and never paid.
- **Coins they launch are real**, so the runbook says to use a throwaway repo.
- **The runbook gets a "test the journey" checklist:** install, first message, build, submit, coin, the after-submission reply, and the leaderboard showing the entry as a test.

## 6. Cost

- No new services.
- Fetching through the GitHub API uses the existing token, at most one call per launch. (Ruling P2: this is the ownership-file fetch; the repo and commit reads already existed, and the fork compare runs only for forks.)

## 7. Testing

- **Unit tests:**
  - bonus cell cases;
  - the with-repo template keeps "matches you to $X in open money you qualify for";
  - the no-repo template uses "$X is open right now" and "You could";
  - wallet remembered and prefilled on non-campaign entries;
  - a ticker-free token code;
  - the contents-API read with raw fallback;
  - the repo-with-code gate;
  - proof: unreachable page → confirmation counts, flagged; mismatch → not eligible;
  - `builder_bonus: false` books to the Safe;
  - test installations excluded from stats and ranking;
  - `local_repos` with `url`.
- **e2e:** the v2.5 lifecycle e2e plus one program without a proof pattern that pays a confirmed entry.
- **Copy review:** every changed builder string is short, money first, no emojis, never "vault", no affiliation.

## Out of scope

- Hosting or deploying for builders.
- Custody or placeholder wallets.
- New programs after Oct 15 (curation, separate).
