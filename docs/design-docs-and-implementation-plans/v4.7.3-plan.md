# v4.7.3 Stripe launch-ready: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Stripe connect launch-ready and fix two pieces of reply copy, all from the owner's review of v4.7.2.

**Spec:** the owner's review (screenshot, 2026-10-31, 11:19 AM), "Three Stripe fixes would make it launch-ready, plus two copy tweaks":
1. "Use a separate secret to encrypt stored Stripe keys, instead of deriving it from the sign-in secret. Right now, one leaked secret exposes both sign-ins and every builder's Stripe data."
2. "Only accept read-only Stripe keys. Keys that can move money are already refused, but keys that can change customers or products still get through."
3. "Make the key field a password input and remove the key from anything that gets saved, plus make the connect link work only once."
4. "Split a16z's $1M from the '$105.5K in grants' total, for example '$105.5K in grants, plus a16z up to $1M investment'."
5. "Show the 'Want the steps...' ask in full once, then shorten it on later replies so it doesn't feel canned."

**Architecture:**
- **Separate secret:** `secret-box.ts` takes its secret per purpose. The `stripe` purpose reads only `EARNKIT_STRIPE_SECRET`, with no fallback to `EARNKIT_AUTH_SECRET`. While it is unset, Stripe is off: no link, no ask, a connect that is refused, and a daily read that is skipped. Production has 0 `stripe_connections` rows (checked 2026-10-31), so nothing needs re-sealing.
- **Read-only check:** every write permission is probed by updating an object that can't exist (`POST /v1/<resource>/<fake id>` with an empty body). A key without that write permission gets 403. A key with it gets 404 (no such object) or 400, so nothing is ever created or changed.
- **One-use link:** a link used for a successful connect is spent. Its hash goes in `wallet_proof_uses`, the table the wallet link already uses, under its own `stripe:` namespace.

**Tech Stack:** Next.js 16, TypeScript, Postgres, node:test via tsx.

## Exact copy

- **Stripe off** (`EARNKIT_STRIPE_SECRET` unset), on the connect page and the POST: `Stripe connect isn't available right now. Try again later.`
- **Link already used:** `This link was already used. Ask your agent for a new Stripe link.`
- **Open money paragraph** (replaces v4.7.2's): `Open now: {total} in grants, plus {investment}, {amount} investment, {when}. {grant}, {amount}, {when}. [{grant2}, {amount}, {when}.]`
  - With no total (no grant listed): `Open now: {investment}, {amount} investment, {when}. …`
  - With no investment: v4.7.2's line, `Open now: {total} in grants. {grant}…`.
  - Expected on the owner's account: `Open now: $105.5K in grants, plus a16z speedrun SR008, up to $1M investment, closes Nov 1. Arc Microgrants, 500 USDC × 8 grants, closes Nov 1. Base Builder Grant Program, $5,000, rolling.`
- **Needs ask, first showing for a program:** unchanged from v4.7.2. It is the why paragraph, then `Want the steps to get {name} ready for {program}?`, or with no known gap `Want me to check {program}{'s} requirements for {name}?`.
- **Needs ask, later showings** (the program's `needs_unanswered` is 1 or more):
  - No why paragraph in the reply. The why stays in `move_up.why`.
  - The question is `Want the {program} steps?`, or with no known gap `Want me to check {program}{'s} requirements?`.
- **Possessive:** `{'s}` is `'` after a title ending in "s" and `'s` otherwise, so it reads "Arc Microgrants' requirements".

## Review Focus

1. An `rk_live_` key with any write permission that the probe list covers is refused, and a key with read only passes. A 401, a 5xx, a thrown call, or any status other than 403/400/404 refuses the key with `unreachable`.
2. With `EARNKIT_STRIPE_SECRET` unset:
   - no Stripe ask or link is ever offered
   - the page and the POST show the off copy
   - the daily read stores nothing
   - `seal` never falls back to `EARNKIT_AUTH_SECRET`
3. After a successful connect, the same link shows the used copy on GET and refuses on POST. A failed paste (a wrong key) leaves the link usable.
4. The raw key appears nowhere outside the sealed column: no DB table, no console output, and no response body. A test scans them all after a connect and after a refused connect.
5. A builder with a fit, and the v4.7.2 first-showing replies, are unchanged except for the money paragraph's new investment position.
