# v3.8 G-A item 7: BNB Chain in the chain registry

## Problem

The v3.8 acceptance run G-A could not write Binance Wallet x BNB Chain's Agent ID Hackathon: `bnb` is not a
registered chain, so `ProgramFile` refuses `chains: ["bnb"]` ("not a known chain (chains.ts)"). The only way
through was `any_chain: true`, which is wrong for a program that requires BNB Chain.

## Change

- `lib/v5/chains.ts`: a `bnb` entry, "BNB Chain", EVM. Mainnet (BNB Smart Chain) id 56, hosts
  `bsc-dataseed.bnbchain.org`, `bsc-dataseed.binance.org`, `bscscan.com`; testnet id 97, hosts
  `bsc-testnet-dataseed.bnbchain.org`, `data-seed-prebsc-1-s1.bnbchain.org`, `testnet.bscscan.com`. Explorer
  `https://bscscan.com`; `explorer_api: null` because there is no keyless Blockscout instance for BSC (same as
  Avalanche and Monad), so contract reads (`lib/v6/explorers.ts`) stay off for it. RPC `https://bsc-dataseed.bnbchain.org`.
- `chainSlugOf(input)`: the slug a name means, any case, with dashes, underscores and spaces alike. Aliases: `bsc`,
  `bnb chain`, `bnbchain`, `bnb smart chain`, `binance smart chain` → `bnb`. "Binance Chain" is left out on purpose:
  it was the separate Beacon Chain, not BSC.
- Aliases apply only where a person or agent types a chain: `project-input.ts` `networkOf` (so `bsc`, `BNB Chain`,
  `bsc-testnet` read as `bnb`) and /me `chains_claimed` (saved as the slug). Program files, the write API and stored
  rows keep one slug per chain; an alias there is still refused, so the catalog never holds two names for one chain.
- `repo-facts.ts`: viem's `bsc` and `bscTestnet` imports signal `bnb`. Hosts and deploy folders
  (`broadcast/<script>/56/`) work through the registry. Text chain-id detection needs 3+ digits, so a bare `56` in
  code is not a signal (same as Ethereum's 1 and Optimism's 10): no new false positives.

## Not changed

- No schema change, no flag: the registry is code, and nothing changes for existing chains.
- No keyless contract reader for BSC (none exists). If one is wanted later it goes in `explorer_api`.

## Tests

`lib/v5/bnb-chain.test.ts` (fails on main, passes here): the registry entry and ids; alias reading; the Agent ID
program with `chains: ["bnb"]` passes `ProgramFile`, `programProblems` and `apiRuleProblems` (and `["bsc"]` is still
refused); agent-reported chains by alias, network word and chain id; repo detection by viem import, RPC host and the
testnet explorer host, and a deploy folder for 56. `me-routes.test.ts`: `chains_claimed` "BSC, BNB Chain, base" saves
`["bnb", "base"]`.
