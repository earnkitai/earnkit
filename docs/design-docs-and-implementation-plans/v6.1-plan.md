# EarnKit v6.1: the record, GitHub identity, the four tools and /me. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a builder one private record (facts, links, documents, approved answers, standing approval) keyed to their GitHub account and read by any of their agents; let `find` fill forms from it, name blockers and claim applications so nothing is submitted twice; give programs the `screen` tool over the v6.0 evidence reader with a queue, outcomes and cross-program counts; add the catalog fields that make blockers and bars possible; and put the only new web UI, `/me`, behind a GitHub sign-in.

**Architecture:** Everything new lives in `apps/frontend/lib/v6/` beside the v6.0 evidence reader, and the v5 tools are changed in place where the design says so (`find.ts`, `track.ts`, `prefill.ts`, `reply.ts`, `mcp.ts`, `ledger.ts`, `program-file.ts`, `eligibility.ts`). A ledger row's owner becomes a string key, `i:<installation id>` until the installation is linked and `b:<builder id>` after, so one builder with two agents has one ledger and an unlinked stranger keeps v5's behavior exactly. The record is one JSON column on `builders`, validated by a strict zod schema with a per-path `meta` block (`set_by`, `set_at`, `approved_at`). GitHub sign-in is a plain OAuth code flow against `github.com/login/oauth` with `read:user`, state signed with `EARNKIT_AUTH_SECRET`, and a 30-day session cookie for `/me`; when the two OAuth env vars are unset the sign-in surfaces say so and `find` offers no link, so the release deploys before the owner's OAuth step. `screen` writes a job and its applicants to Postgres; the daily cron and an owner-triggered call work the queue through `readEvidence` and `place`, so no new scheduler exists. No LLM, no new dependency, no new paid service.

**Tech Stack:** TypeScript, Next.js 16 route handlers and server-rendered pages (no client state beyond plain HTML forms), node:test with the per-file test database, postgres.js, zod 4, the v6.0 reader (`readEvidence`, `place`, `reviewerLine`, `builderLine`), GitHub OAuth (`https://github.com/login/oauth/authorize`, `https://github.com/login/oauth/access_token`, `https://api.github.com/user`).

**Spec:** `docs/design-docs-and-implementation-plans/v6-design.md` (approved 2026-11-06), sections 4, 5, 6, 8, 9, 10, 13, 14, 16. SDD ledger: `v6.1-sdd-ledger.md` beside it. v6.0 (sections 7 and 11) is live as origin/main b3ec8db1.

## Review Focus

1. An unlinked installation, sign-in not configured, must get exactly the v5 `find` reply: no sign-in line, no record words, same closing line (Task 4 test `unlinked without oauth is v5`).
2. A second `track started` on the same builder, project and program within 24 hours, from a different installation of the same builder, must answer `already_started` and record nothing; after 24 hours with no `applied` the claim is released and the next `find` names it (Task 4 test `a second claim is refused across the builder's agents`).
3. An unapproved answer in the record must never reach a `fields[]` value: the field is `from: 'builder'` with the kind named in `record_missing`, even when the agent wrote the text five minutes ago (Task 4 test `unapproved answers are not fitted`).
4. `/me` actions with a missing or foreign session cookie, or a wrong csrf token, must change nothing and answer 403; deleting a record must remove the builder, their sessions, link codes, record, ledger rows and unlink their installations in one transaction (Task 6 tests `me refuses without a session` and `delete removes everything`).
5. A `screen` call from an installation that is not a reviewer for that program must be refused with one line and write no job; a reviewer's results must contain no pitch text, no program names other than their own and no builder record fields (Task 5 tests `screen needs a reviewer` and `results carry public evidence only`).
