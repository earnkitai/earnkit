# v3.8 flags-on suite

Approval: Jenil approved building v3.8 (earnkitai/earnkit#159). The shipping flags (`PREVIEW_FLAGS` in
`lib/v5/flags.ts`) are switched on later by setting `EARNKIT_FLAGS`; this change makes the whole suite pass with
them on as well as off, so that switch is made on a green suite.

## Contract

- `pnpm test` is unchanged: flags off (test-guard clears `EARNKIT_FLAGS`).
- `pnpm test:flags-on` runs the same files with one more preload after test-guard,
  `lib/v5/fixtures/flags-on.ts`, which sets `EARNKIT_FLAGS` to `PREVIEW_FLAGS.join(',')`. No new env var, no
  production code reads anything new; adding a flag to `PREVIEW_FLAGS` adds it to the run.
- A test passes in both runs. Three kinds of change, no assertion loosened:
  1. **Copy and shape follow the active flags.** A line from the copy table is asserted through `copy()`
     (`COPY_V37`/`COPY_V38`); other flag-dependent text or JSON is asserted per flag with `flagOn(...)`, both
     values written out.
  2. **Setup does what an agent does with the flags on.** `lib/v5/fixtures/send.ts` exports a `track` with the
     same signature: with `track_v2` on an applied carries a proof (E9); with `draft_check` on an agent's applied
     the gate refuses is sent the real way (E11): a passing check of a draft built from the form's required
     fields (after a started when no unsent row holds one), then applied with that draft as `final`. Flags off it
     is `track`. Tests of the gate or of proof call `../track` directly.
  3. **Tests of the off path say so.** A test whose subject is flag-off behaviour (main's approval path while
     `auto_live` is off, a 404 while a page's flag is off) sets `EARNKIT_FLAGS` itself and restores it.
- A failure that is not intended behaviour (crash, wrong data or count, broken cap, leak, an ask for what
  EarnKit can find, an empty builder line) is fixed in code; the PR lists each.
- L23-16 (find.test.ts) no longer depends on what earlier tests in the file seeded.

## Not in scope

Switching any flag on in production; the gate scripts in /workspace/cto/gates (this replaces them in-repo).
