# v4.10.1 Honest ready set Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Fix the six problems from the owner's 2026-11-02 production dogfood of v4.10: no false "Ready", no unasked required fields, honest money, a repeat reply that keeps its details, no contradictory score within one session, and program writes that go live only when their link checks out.

**Architecture:** The root causes, with file:line references and the tests that pin current behaviour, are in `docs/design-docs-and-implementation-plans/v4.10.1-findings.md` (sections 1 to 6). Every implementer reads its task's section first.

**Tech Stack:** Next.js 16, TypeScript, Postgres, node:test via tsx.

**Spec:** The owner's dogfood report (2026-11-02, summarised under each task) and the v4.10 target conversation (`v4.10-target-conversation.md`). Owner answer 2026-11-02: an API write goes live only if its link checks out; otherwise it is pending for the owner.

## Global Constraints

- Copy: short, money first, no emojis, never em dashes, never "coin" or "points". Exactly one easy reply, last. Never claim the builder qualifies or that an application was sent. Under 48 hours, say the hours left.
- Honesty: never say "Ready" or "every other answer is filled" unless it's true. An answer the agent would have to invent is a need, never a draft.
- The set's single ask stays: at most 4 items, using `move_up.answers` keyed by kind (at most 8 entries, 1000 characters each). Anything past 4 is named in the program's line ("and N more").
- No new paid service, cron, or server LLM call. Email goes only to the owner (`owner-mail.ts ownerMail`).
- Tests: `cd apps/frontend && node lib/earnkit/fixtures/test-db-template.mjs && DATABASE_URL=postgresql://localhost:5432/earnkit_test npx tsx --test --import ./lib/earnkit/fixtures/test-guard.ts <files>`. Known failures that may stay: R9 "Bench", and v4-nudges "fix round 1 (2, 4)" and "fix round 2: not counted yet".
- Stage explicit paths only. Never commit zz-* files. Commits end with "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>".

## Rulings (controller, 2026-11-02; the owner can reverse them)

- R1: Base's GTM plan stays agent-drafted (v4.8 ruling); the agent drafts it from the project. Revenue is filled from verified revenue when held, else asked. The main challenge (multi_choice) and the credits wanted are asked.
- R2: Contact details are filled from what EarnKit holds (X handle, banked contact answers, an opted-in email). The rest are asked once as one item that names them ("your name, email and Telegram"). Once given, they are banked and never asked again.
- R3: "Worth up to" leaves out long shots. Investor programs stay in it. When the set has a long shot, the opener can say "plus a $100K long shot".
- R4: A new program, or a write that changes `submission_url`, goes live only when the submission link's registrable domain equals the official site's domain (`official_url`, a new write field), or is the same as an already-live program's for that ecosystem. Form platforms (forms.gle, docs.google.com, typeform, tally, questbook, airtable) never count as checking out on their own. Anything else lands pending, and the owner gets one email with an approve link. The link opens a confirm page and approval is a POST, so email link scanners can't approve. It is signed with HMAC from an existing secret (`EARNKIT_AUTH_SECRET`). Updates to other fields on a live program stay live.
- R5: Score: when find's refresh hasn't finished within its wait, the reply doesn't state a score or week count; it says the numbers are updating. The next reply has the fresh numbers. A reply never shows a number the same session's next call contradicts.

## Review Focus

- A program whose only unfillable field is optional: it is still "Ready".
- A builder who already answered the contact item for another program: never asked again (bank).
- A set that is all long shots: the money line still reads honestly, with no "$0".
- An approve link used twice, expired (7 days), or with a bad signature: no double write, and a plain error page.
- A Monday week rollover in the score fix: covered with a pinned clock.

### Task 1: Honest needs (findings 1 and 2)

The owner's words: "Circle is marked Ready, but it isn't. Its form asks about your Circle and Arc integrations, a roadmap and milestones... the agent would have to invent those answers." And: "Base has 8 required personal fields (name, email, Telegram, revenue and others) that are neither asked for nor filled in."

- Readiness counts a required field as a need when the agent can't truthfully draft it. Align it with the prepare coach (`coach.ts askableKeys` / `AGENT_DRAFTS`) so the ready path and prepare agree. Circle's integration, roadmap and milestone fields become needs.
- Contact and revenue fields are filled or asked as R1 and R2 say. `heldAnswers` gains the held sources listed in finding 2.
- Fix the `answers.other` collision from finding 2: two different fields must never get the same answer.
- "Every other answer is filled" appears only when every required field of every program in the set is filled or drafted after the ask.
- Tests: Circle on the real program file reads "Needs …" naming its fields, never "Ready". Base names the contact item and the challenge. A banked contact answer isn't asked again. Two "other" fields get distinct answers.

### Task 2: Money and the repeat reply (findings 3 and 5)
