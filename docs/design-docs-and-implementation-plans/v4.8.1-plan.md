**Rulings (controller, 2026-11-01; the owner can reverse any of them before merge):**
- **R1. Investor programs and long shots never lead on their own.** They lead only when the builder picked them, is already past the hook on them, or there is no grant move at all. This follows the owner's investor decision ("if they consciously choose it"). It reverses the approved conversation A's a16z opener, and the owner's report asks for exactly that. Cost if wrong: an investor deadline is never pushed. Mitigation: the money line names the soonest investor program and its deadline.
- **R2. Deadlines are worked out from the time left, never a calendar day in the program's zone.** EarnKit doesn't know the builder's zone, but "in 20 hours" is true everywhere.
- **R3. The money total comes back once per session**, as part of the first path reply.
- **R4. The repeat pointer always carries its reason**, and is never the same paragraph twice in a session.
- **R5. Chain fit copy says what the program looks for**, never "needs".
- **R6. Secret-looking strings are scrubbed from every MCP tool argument** before any handler sees them.

**Architecture:** these are all changes to existing v4.8 code: `conversation.ts` (bestMove, closeWords, submitBy, pointer, fit words), `bench-find.ts` (callers, money line), and `app/mcp/route.ts` plus a new `lib/earnkit/secrets.ts` (the scrub). No schema change.

**Tech Stack:** Next.js 16, TypeScript, Postgres, node:test via tsx.

### Task 2: Deadline words from the time left (R2) and the money line (R3)

**Files:**
- Modify: `apps/frontend/lib/earnkit/conversation.ts` (`closeWords`, `submitBy`)
- Modify: `apps/frontend/lib/earnkit/bench-find.ts`, so the first path reply of a session carries the money line
- Test: `apps/frontend/lib/earnkit/v481-fixes.test.ts`

**Deadline copy.** `closeWords(endsAt, zone, now)` keeps its signature but returns:
- under 1 hour left: `in under an hour`
- under 48 hours left: `in {n} hours` (whole hours, rounded down; `in 1 hour` for 1)
- otherwise: the program-zone day (`Nov 5`), as now

`closes {closeWords}` therefore reads "closes in 20 hours". Every caller that put "closes" or "by" before the old words still reads right. Check each caller and list it in the report.

`submitBy(endsAt, zone, now, abbr)` returns `{day}, {clock} {abbr} (in {n} hours)` under 48 hours, for example `Nov 1, 11:59 PM PT (in 20 hours)`, and `{day}, {clock} {abbr}` otherwise. `{day}` is always the program-zone date ("Nov 1"), never "today" or "tomorrow". Without `abbr`: `{day}`, plus ` (in {n} hours)` under 48 hours.

**Money line.** The first path reply in a session (hook, gap, draft or the session opener; never the setup steps, a held submit question, or a direct `ask` answer, which already has its tables) carries, as its own paragraph just before the last paragraph:

`Open now: {total} in grants.[ {Investor} (investor program, {amount}) closes {closeWords}.]`

- `{total}` is `moneyText(openMoneyUsd(cards, now))`, the same figure as `/api/stats`. When it is 0, the line is left out.
- The investor clause names the soonest-closing open investor program the builder hasn't applied to, declined or been led on, but only when it closes within `INVESTOR_WINDOW_MS`. Otherwise the clause is left out.
- It is said once a session. Store the said key `money:total` with `markSaid`/`saidSql`.

### Task 3: A pointer with its reason, never twice (R4) and fit copy (R5)

**Files:**
- Modify: `apps/frontend/lib/earnkit/conversation.ts` (the pointer at `point = reply === 'start' ? …`, around line 309; `fitWords` at line 862)
- Modify: `apps/frontend/lib/earnkit/bench-find.ts:1133` (`pathClosedCommit`'s `again` text)
- Test: `apps/frontend/lib/earnkit/v481-fixes.test.ts`

**Pointer copy.** The first time in a session the path's step is pointed back to:

`{Program} is still your best move: {money}, {why}. {ask}`

- `{money}` is the program's amount cell ("up to $5,000"). If it is unknown, it is left out along with its comma.
- `{why}` is, in this order: `one step away` (gap stage, one gap); `{n} steps away`; `your draft is ready` (draft or submit stage); `closes {closeWords}` (a dated program, when nothing above applies).
- `{ask}` is the stage's existing easy reply ("Want me to start?", "Go?", "Reply "sent" once it's in.").

The second and later times in the same session:

`Still {Program}. Reply no and I'll line up the next program.`

A no here goes through the existing no handling (it parks the program and hands off to find).

Both lines are keyed in the session's said set (`point:{programId}` and `point2:{programId}`). The second line can show more than once, because `gateFailures` allows a step at most twice. If the gate fails on a third showing, the third and later showings use `Reply "more" and I'll show every program open now.` instead.

`pathClosedCommit`'s `again` text uses the same pointer function.

**Fit copy.** `fitWords` for `kind: 'chain'` returns `Not yet: they look for apps on {chain}`.

### Task 4: Secret scrub on every tool call (R6)

**Files:**
- Create: `apps/frontend/lib/earnkit/secrets.ts`
- Modify: `apps/frontend/app/mcp/route.ts` (inside `withAliases`'s parse, before the transport sees the body), and the reply path so the scrub line leads the tool's reply
- Test: `apps/frontend/lib/earnkit/v481-secrets.test.ts` (new)

**Interfaces:**
- `scrubSecrets(value: unknown): { value: unknown; removed: number }` is pure. It walks objects and arrays and replaces each match in every string with `[key removed]`.
- `SECRET_PATTERNS: RegExp[]` covers:
  - Stripe: `\b(?:sk|rk|pk)_(?:live|test)_[A-Za-z0-9]{8,}\b` and `\bwhsec_[A-Za-z0-9]{16,}\b`
  - GitHub: `\bgh[opsur]_[A-Za-z0-9]{30,}\b` and `\bgithub_pat_[A-Za-z0-9_]{30,}\b`
  - Anthropic: `\bsk-ant-[A-Za-z0-9_-]{20,}`
  - OpenAI: `\bsk-(?:proj-)?[A-Za-z0-9_-]{20,}`
  - AWS: `\bAKIA[0-9A-Z]{16}\b`
  - PEM: `-----BEGIN [A-Z ]*PRIVATE KEY-----[\s\S]*?-----END [A-Z ]*PRIVATE KEY-----`
  - Raw 64-hex strings are not matched, because they collide with transaction hashes.
- `SCRUB_LINE = 'That looked like a secret key, so I removed it and saved nothing. If it was a live key, roll it now in that dashboard. Never paste keys in chat; I'll send a private link when one is needed.'`

**Behavior:**
- Only `tools/call` params' `arguments` are scrubbed, in single and batch JSON-RPC bodies.
- When `removed > 0`:
  - the route logs `[mcp] scrubbed {n}` and never the value;
  - the tool's first text content is prefixed with `SCRUB_LINE` and a blank line. A JSON text reply gets the line as a top-level field `scrub_note` instead, if the reply is JSON. Read how replies are shaped in `mcp.ts` and choose one, then say which in the report.
- A body that isn't JSON passes through untouched, as now.

- [ ] **Step 1: Failing tests.**

  - A tx hash `0x` followed by 64 hex characters and a GitHub URL are untouched.
  - Nested arrays and objects are scrubbed.
  - `removed` counts every match.
  - A route-level test (or a test of the exported helper the route uses) shows a `tools/call` body with `rk_live_…` in a nested argument reaching the server scrubbed. The reply carries `SCRUB_LINE`. The log never contains the key.
