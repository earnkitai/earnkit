# v4.2 Journey Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every problem the ten v4 builder journeys surfaced, so a public builder goes from install to token and first application without a dead end, a pitch in place of an answer, or a wrong fact.

**Architecture:** Reply-layer fixes in `apps/frontend/lib/earnkit` (bench-find, bench-reply, builder-token, wallet-offer, reply-facts, prepare), plus stats for analytics. jenil.ai's token lookup is a separate repo (`~/Code/jenil.ai`), Task 8.

**Tech Stack:** Next.js 16, TypeScript, Postgres, node:test via tsx (`pnpm --filter frontend test`), jenil.ai: vitest.

**Spec:** `docs/design-docs-and-implementation-plans/v4-builder-tokens.md` (approved copy and rulings). Evidence: `v4.2-journey-findings.md` (F1-F18) and `v4.2-root-causes.md` (file:line and smallest fix per finding; read your finding's section first).

## Global Constraints

- Copy rules: short, money first, no emojis, never em dashes, the word "token" (never "coin", "bet", "buy"), no jargon (no "points", "fee locker", "Clanker"), warm encouraging mentor tone.
- Markdown on Grok Bot; plain "Label: value" lines on WhatsApp-style agents (`reply-format.ts` surfaceOf). Every new reply goes through the existing formatter.
- One question per reply, at the end.
- Never launch a real token in tests; the deploy client is mocked as today.
- A builder's "no" to the token is never re-asked by EarnKit. Only the builder's own "launch my token" reverses it.
- Approved copy in the spec stays verbatim; new copy below is exact.

## Review Focus

1. A token question asked during step 3 (offer pending, no wallet yet) must not create a second question or launch anything. Pinned in Task 1.
2. A builder who said no and later says "launch my token" launches once, and a repeat says it's already live with the link. Pinned in Task 1.
3. Setup done with zero fits (no repo, no facts) still shows open programs with what each needs, never "doesn't fit". Pinned in Task 2.
4. A legacy builder offered the token once and saying nothing is never offered again. Pinned in Task 6.
5. Stats never count test installations' tokens. Pinned in Task 7.

Exact copy (`{trade}` = tradeUrl, `{page}` = earnkit.com/<handle>, `{w}` = short wallet 0xab…cd):

- No token, offer pending or none, not declined: "Your token is how people who believe in your work can back it. Anyone can trade it, and 40% of every trade's fee goes to your wallet, claimed for you. It lives on Base, whatever chain you build on." then, if the wallet step is open: "It goes live when you sign. Rather skip it? Just say no." else if no wallet: "Sign with your wallet and it goes live: {link}" else (wallet, no offer): the Task 6 offer question.
