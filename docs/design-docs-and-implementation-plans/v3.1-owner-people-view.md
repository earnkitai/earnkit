# v3.1 owner people view (farm watch)

Owner ask (2026-10-23): before launch, see each person's X, GitHub and wallet in one place, with signals that
help spot people who may farm for $EARN. Private to the owner, on jenil.ai. Flags are never public, never
scored, never move rank (same rule as Backing). No new paid services; background work daily at most.

## EarnKit side (repo earnkitai/earnkit, Next.js app in apps/frontend)

1. **X account age and followers at sign-in.** `x-oauth.ts` `me` asks `user.fields=profile_image_url,created_at,public_metrics`.
   `xUserFrom` also returns `createdAt: string | null` (ISO, parsed safely) and `followers: number | null`
   (`public_metrics.followers_count`, non-negative integer). Wherever the signed-in X user is written to
   `builder_profiles`, also write `x_created_at` and `x_followers` (+ `x_checked_at = now()`). Missing values stay NULL.
   No backfill (reading other users needs X's paid API).
2. **GitHub account age.** Daily cron step: for each `builder_profiles.github_login` not in `github_users`, read
   `https://api.github.com/users/<login>` (`created_at`) and insert into `github_users`. Reuse any existing GitHub
   user-read helper (policy.ts already uses github_users). Cap per run (e.g. 50), skip on errors, fail quietly.
3. **Wallet history.** Daily cron step: for each `person_wallets` row with `signals_checked_at IS NULL`, read Blockscout
   (reuse the `blockscout` helper in campaigns.ts) Etherscan-style `/api?module=account&action=txlist&address=<w>&sort=asc&page=1&offset=20`.
   Store `first_tx_at` (the earliest tx time, NULL if none) and `funder` (the `from` of the earliest tx whose `to` is
   the wallet, lowercased, NULL if none) and `signals_checked_at = now()`. Re-check rows with `first_tx_at IS NULL`
   after 7 days. Cap per run, fail quietly. Known limit: smart wallets funded by internal calls show no funder.
4. **Schema** (append-only, idempotent, schema.sql): `ALTER TABLE builder_profiles ADD COLUMN IF NOT EXISTS x_created_at timestamptz, x_followers integer, x_checked_at timestamptz`;
   `ALTER TABLE person_wallets ADD COLUMN IF NOT EXISTS first_tx_at timestamptz, funder text, signals_checked_at timestamptz`.
5. **The view** `owner_people` (CREATE OR REPLACE VIEW, append-only in schema.sql), one row per builder profile:

   | column | source |
   |---|---|
   | builder_id, slug, hidden | builder_profiles |
   | installation_ids int[] | the builder's installations (test installs live in an env var SQL can't read, so jenil.ai gets the ids) |
   | x_handle, x_user_id IS NOT NULL AS x_proven, x_created_at, x_followers | builder_profiles |
   | github_login, gh_created_at | builder_profiles + github_users |
   | wallet, wallet_recipient (recipient_at IS NOT NULL), wallet_proven_at, wallet_first_tx_at, wallet_funder | the builder's recipient wallet, else newest proven (person_wallets) |
   | funded_by_slug | slug of ANOTHER profile that owns `wallet_funder` as a proven wallet, else NULL |
   | points_total, points_weeks, last_points_week | builder_points |
   | joined_at | builder_profiles.created_at |
   | last_seen_at | max installations.last_seen_at over the builder's installations |

   Then a guarded grant: `DO $$ BEGIN IF EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'earnkit_ro') THEN GRANT SELECT ON owner_people TO earnkit_ro; END IF; END $$;`
   The view runs with the owner's rights, so earnkit_ro sees only these columns. No emails, no tokens, no IPs.
6. Tests for xUserFrom parsing, the wallet step's parsing (earliest tx, funder only when `to` is the wallet), and the view (DB tests follow the repo's existing DB-test pattern).

## jenil.ai side (repo jenil04/jenil.ai)

A `/people` page, owner role only (the /us partner role must not open it), reading `owner_people` through `earnkitSql()`.
One row per person, newest joined first, hidden profiles last and dimmed. Columns: profile (slug linking to
https://earnkit.com/<slug>), X (@handle, proven or not, age, followers), GitHub (login linking to github.com, age),
wallet (short 0x12ab…abcd linking to basescan, recipient or not, age of first tx), points (total, weeks), joined, last seen.
Flags column (computed in jenil.ai, pure function, tested):
- `new X` X account under 90 days
- `new GitHub` GitHub account under 90 days
- `fresh wallet` no tx history, or first tx under 30 days before the wallet was proven
- `funded by @slug` the wallet was first funded by another profile's wallet
- `no X proof` X handle without x_user_id
A count line on top: "N people · M flagged". Optional MCP read tool `get_people` (read key) returning the same rows + flags,
so Grok Bot can watch it. Follow the repo's existing page, chart and tool patterns.
