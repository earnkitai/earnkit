# v2.12.2: show the work behind a reported GitHub login

Spec: `v2.12.1-where-you-stand.md` (the first reply leads with the builder's work; anything the agent
reported is shown as not yet confirmed, never scored).

## Problem

A fresh install whose agent sends only `identity.github_login` got "I couldn't find anything you've
made yet." on every find and score, even when that login has public repos.

Why: discovery lists a person's repos only after their login is proven (a sign-in, the App, a proof
line, or an X field match after a claim). A login the agent reported is never proven at first, so
nothing was proposed, nothing was read, and the reply had no projects. The proven-login gate is right
for verifying and merging. It was also applied, wrongly, to showing.

Smaller gaps found on the way:

- find never passed the reported login to the program matcher, so "Ways to earn" could not tie a
  program to one of their repos.
- Inside the 8-second on-demand refresh, the proof-line check (which wants 15 s) always threw, so the
  refresh's discovery aborted for anyone with proposed repos.
- Repo names came out lowercase ("hello-world").

## Fix

1. Discovery (`discovery.ts discoverOne`): with no proven login, but a reported one that no other
   profile has proven, one GitHub person query lists that login's newest 25 own public repos (no
   forks, no templates) and proposes them, plus their homepages, as not-yet-confirmed sources. They
   are never verified, never merged and never scored. Proving the login later verifies the same rows.
   It runs only within the GitHub budget and before the deadline, and the refresh never fails find.
2. The first reply: when every project is code only, "You've made 3 projects on GitHub: Hello-World,
   Spoon-Knife and linguist. None is live yet." (at most 3 named, names as GitHub writes them).
3. The one yes: a code-only project can get "Want me to put Spoon-Knife online? It takes a few
   minutes and you won't have to do anything." (after any app the agent named), but only when it
   shows a sign of being a website: a homepage, or web code as GitHub's main language (HTML, CSS,
   JavaScript, TypeScript, Vue, Svelte, Astro, MDX). Otherwise the step stays "Send me a link". It
   uses the existing GitHub Pages path.
4. The on-demand refresh skips the proof-line check when time is short instead of aborting. When it
   skipped a check, the discovery queue row stays open (reason `proof_line`), so the next cron run
   does the check; the refresh does not rerun discovery for it. The proof-line and remote checks
   read the agent's own repos first, so the 25 server rows never crowd them out.
5. find passes the reported login to the program matcher (flag on, own installation, only when the
   agent gave no GitHub user or repos), so a program can be shown as a fit for a reported repo. A
   fit confirms nothing. That matching is quiet: a failed read is never shown to the builder, and a
   login with no repos counts as no repos given.

Flag off: unchanged.

## Risk

Anyone can report someone else's GitHub login and see that person's public repos listed as "not yet
confirmed" in their own private reply. Accepted because:

- the repos are public already;
- nothing is verified, merged or scored from a reported login, and an unclaimed person has no public
  page;
- the read is skipped when another profile has proven that login.

Cost: one more GitHub GraphQL call per person per discovery run (at most once a day per person), and
find's matcher may now read GitHub for identity-only finds (under the existing `githubMatching`
limit).
