# v3.8 E16: limits and install docs

**Approval:** Jenil, "Yes, build v3.8" (Nov 24 2026), logged in earnkitai/earnkit#159. Plan: power-user plan v3.8
section 22 (L8 install docs, L9 rate limits) and 23.3 (style); build plan row E16.

**Goal:** a new builder installs EarnKit from earnkit.com/llms.txt alone (or /docs#install), and sign-in attempts are
limited per address.

**Install docs (L8):**

- `site-copy.ts`: `DOCS_NEXT` (what happens next, three lines), `DOCS_SEES` (what EarnKit can and cannot see),
  `DOCS_DELETE` (how to delete everything, the /me button's own words). Rendered under the install steps on /docs and
  quoted word for word in llms.txt, which already had one install entry per client (`AGENTS`), the MCP URL for any
  other client and the first ask.
- Caps: the 230-word docs cards cap is unchanged. The new section has its own cap (under 120 words). The whole /docs
  page cap moves from 470 to 580 for it.

**Limits (L9):** `LIMITS.installConsent` is 30 Connect presses per IP an hour on the install consent page. Over it,
the page is `INSTALL_PAGES.limited` (429, nothing connected, try again in an hour). Existing limits already cover the
rest: installs per client and per network (`installClient`, `installHour`, `installBlock`), OAuth authorize,
/link and X sign-in (`linkGet`), and ten screens a day (`screenJobs`). Private program rows per builder belong to E8,
which is held.

**Not in this PR:** a per-builder private-row limit (E8); X in the docs' sign-in line (X sign-in is behind `x_signin`,
so the docs say GitHub only until it ships).

**Rollback:** redeploy. No schema, flag or env change; the consent limit only runs with `install_signin` on.
