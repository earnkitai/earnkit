## Use

    pnpm tsx scripts/track-import.mts --file <export.json> --owner b:<builder id> [--map <grant>=<program id|https link>]... [--apply]

Dry run plans inside a READ ONLY transaction that is rolled back (the people-backfill convention); `--apply` writes the
same plan in one transaction; a second apply reports every row unchanged.

## Mapping

- Program: the catalog program with the grant's id, else the one whose source or submission link is the grant's url,
  else `unresolved` until `--map` names its catalog program (by id, or by an https link matched as above). Two grants on one program: the second is `not_imported`.
- Stage: found/researching -> held (stage found); drafting/held -> held; registered -> held (stage registered);
  submitted -> applied; interview -> applied (stage interview); accepted/won -> won (dollars only for cash; credits keep
  no dollar amount, their value goes in the note); rejected -> rejected; duplicate -> not imported. A send's proof is
  the ledger reference (`Jenil AI ledger <id>, submitted <date>`).
- Hard rows (`HARD_ROWS`): Fe skipped (registered only, FE-041); PayPal Allowance applied Nov 12; Tavily kind credits;
  Aiven at interview; soonami in progress (applied, stage interview; not a win); Delphi skipped and Ship or Die entered
  with Pip & Crew, both missing from the export and imported only with `--map` (no source gives their link).
- A date-only deadline is kept as words in the note, never stored as an instant: its zone is not known (the Fe error).
  So closed past deadline derives only for catalog programs (which carry ends_at and tz).

## Writes

`applications` (one row per program, no project; an existing row of the owner's on that program is updated),
`application_history` (source `import`). No schema change.
