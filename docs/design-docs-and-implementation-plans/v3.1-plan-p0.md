# v3.1 P0: the founder as power user. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every ranked reply leads with the builder's best program and a one-yes draft. Monday brings a ready X post and the money action. Points arithmetic, Originality, the grid, the v2 entry machine and off-thesis programs leave the visible surface. The owner's production frictions (F1 to F4) are fixed first.

**Architecture:** All logic stays in `apps/frontend/lib/earnkit/`, reached through the MCP tools (`find`, `score`, `prepare`, `tell`) and the cron. The ranked reply is still built in `bench-find.ts benchView` and rendered by the pure `bench-reply.ts benchReply`. Programs are JSON files synced to Postgres. Drafting moves out of the 600-line `prepare_submission` into a new focused module (`draft-application.ts`) that reuses `prepareSubmission`, `shipLogFacts` and a new pure `submit-kit.ts draftKit`. The Builder Codes check reuses `repo-proof.ts appClient` (the read-only App's per-repo token) and caches its verdict in one new table.

**Tech Stack:** Next.js 15, TypeScript, Postgres (`postgres` tagged template), zod, node:test through tsx (`fixtures/test-guard.ts`, a database per file), `fixtures/mcp-call.ts mcpCall` for reply assertions.

**Spec:** `docs/design-docs-and-implementation-plans/v3.1-founder-power-user.md` sections 3.2, 3.3, 3.4 (3.1 is the owner's runbook pass; P1 and P2 are out of scope). Owner rules: `v3.1-brief-for-next-session.md`. Owner frictions F1 to F4 (production Grok Bot run, 2026-10-21) arrived through the coordinator and are Tasks 1 to 4.

## Global Constraints

- Copy: short, money first, no emojis, never an em dash, sentence case; every agent reply has one https link and one question; "points" never "EARN points"; "Backing" never "community round"; "of N builders" never "this week" after "builders"; no period directly after a link.
- Never invent a program fact; every program JSON passes `pnpm programs:check`; `verified_at` is the day the source was read.
- Backing, coins and points never move Shipping or rank; `earnkitai/earnkit` never gets a Backing offer.
- `db/schema.sql` is append-only and idempotent (`schema-rerun.test.ts` must pass); no new paid service, no new cron.
- `RANK_MIN_POOL = 10` (F3) in `rank.ts`; the builder JSON (`/api/builders/<handle>.json`) keeps the numeric rank.
- Tests: `node:test` via tsx, a `*.test.ts` beside the source. One file:

- Reply assertions go through `mcpCall`; a reply is checked with the `links`/`questions` helpers as in `v3-apply.test.ts` (at most one `https://`, at most one `?` outside links).
- Commit after each task on `v3.1-founder-power-user`; messages end with a blank line then `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; no push.
