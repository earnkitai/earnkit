# v4.7.1 Money always shows: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the gaps the 2026-10-30 dogfood of v4.7 found on the owner's own account.
- "What can I earn" showed no money. With no fit, the reply led with a Monday check-in, even though 5 programs were open and 2 closed in about 2 days.
- A second find said "EarnKit · 6 weeks in a row".
- The "why" repeated the check-in.
- `/api/stats` still reports `points_total` (90) and a second money figure (`open_pools_usd` 139000).
- A yes to the old v4.0 setup step can still launch a token.
- A Stripe restricted key with write access is accepted.
- `/install` returns 404.

**Architecture:**
- Ranked replies always carry a money paragraph.
  - With a fit, it is the fit, as today.
  - With no unapplied fit, it is the open grants closing soonest (`alsoOpen` order by deadline, up to 2). The ask then becomes `check_fits` (the existing kind and note) once, with its own why line.
- The quiet reply's old `standingLine` ("EarnKit · 6 weeks in a row") gives way to v4.7's standing paragraph.
- Stats drop the points field and the deprecated pool figure.
- The legacy token yes becomes the normal offer.
- Stripe connect probes for write access with a request that can't create anything.

**Tech Stack:** Next.js 16, TypeScript, Postgres, node:test via tsx.

## Exact copy

- **Open money paragraph** (ranked, no unapplied fit, at least one open grant):
  - `Open now: {title}, {amount}, {when}.`
  - When there is a second grant, the same line repeats for it after a space.
  - `{amount}` and `{when}` use the same cells as `alsoLine` (`upToCell(prizeOf)`, `fundWhen`).
- **check_fits ask:**
  - Why line: `None of these fit {name} on what EarnKit can see yet.`
  - Question: `Want me to check what {name} would need for {first title}?`
- **Stripe write-access refusal:** `This key can change your Stripe account. Make a restricted key with read access only, then paste it here.`

### Task 3: Stripe keys must be read-only

**Files:**
- Modify: `apps/frontend/lib/earnkit/stripe.ts` `checkKey`.
  - After the account read succeeds, probe write access with `POST /v1/refunds` and `POST /v1/payouts`, each with no parameters (the two endpoints that move money; neither creates anything without its required params).
  - Stripe rejects each before creating anything:
    - a key with write access gets `400` (missing param)
    - a read-only restricted key gets `403` (permission)
  - Both must be `403` to pass. A `400`, any other status, or a network error refuses the key, with the exact copy for `400` and the existing error copy otherwise.
  - Nothing is stored on refusal.
- Modify: `app/connect/stripe/key/route.ts` if the error mapping lives there.
- Modify: `app/connect/stripe/page.tsx` instructions, if they don't already say read-only.
