# v4.9 Programs API for the Grok Bot: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner's Grok Bot, which researches programs on X, add, update and close EarnKit programs on its own through one authenticated API, so the list stays current without a deploy.

**Spec:** the owner's request, 2026-11-01: "It would be even better ideally if you create an API I can write to using my Grok Bot which researches on X for me and finds programs across different categories: hackathons, grants, investment etc sorted so it can continually and autonomously update the programs. … We should generally always have up to date programs."

**Rulings (controller; the owner can reverse them before merge):**
- **R1. Writes go live at once** when every check passes (the owner asked for autonomy). Every write is kept in an audit table, and the owner can switch the API off with one variable.
- **R2. The API writes the same program format as `programs/*.json`** (`ProgramFile`), checked by the same rules as `pnpm programs:check`, so an API program behaves exactly like a file program.
- **R3. Curated files win.** The API can't overwrite or close a program whose row came from a file or a sponsor (`source` `file` or `sponsor`). It returns 409. It can only change programs it created (`source = 'api'`).
- **R4. Proof fields stay owner-reviewed.** The API refuses `proof_hosts`, `x_handles` and `logo`, because those decide what counts as a builder's proof or need a file upload. The owner adds them by file.
- **R5. Categories.** `category` is one of `grant`, `hackathon`, `investment` or `bounty`. It is optional in files, which keep working. When it is absent, it is derived: `investment: true` gives investment; otherwise a pool with no per-winner amount, or `in_person`, gives hackathon; otherwise grant.
- **R6. The secret.** `EARNKIT_PROGRAMS_TOKEN` (at least 32 characters) is compared in constant time. When it is unset, every API route returns 404. The owner sets it; the build never does.

**Tech Stack:** Next.js 16 route handlers, TypeScript, Postgres, zod (program-file.ts), node:test via tsx.

## Global Constraints

- **Test command:** `cd apps/frontend && DATABASE_URL=postgresql://localhost:5432/earnkit_test npx tsx --test --import ./lib/earnkit/fixtures/test-guard.ts <files>`.
- **Known failures:** R9 "Bench", security-headers 5.12, and v4-nudges "fix round 1 (2, 4)".
- **Before merge:** `npx next build` passes, and the owner says go.
- **Costs stay flat:** no new service, no paid API, no new cron.
- **Never log secrets or request bodies.** Log only the program id, the action and the result.
- **Repo:** no zz-* files, explicit staging only, and the Co-Authored-By line on every commit.

## Review Focus

1. A request without the token, with a wrong token, or while the token is unset never writes. It gets 401, 401 and 404 respectively, and the timing doesn't reveal the token.
2. An API write can never change or close a file-made or sponsor program, and can never set proof fields.
3. An API program that passes the checks shows up in `find`, `list_programs`, the landing page and /api/stats exactly like a file program, and a deploy's `programs:sync` never wipes it.
4. A malformed or hostile body (huge, deeply nested, wrong types, past deadline, an optimism.io link, a link that doesn't load) is refused with a reason, and nothing is written.
5. Two writes of the same program in a row are idempotent: the second is reported as "unchanged".

### Task 2: The write API

**Files:**
- Create: `apps/frontend/app/api/programs/write/route.ts` (POST)
- Create: `apps/frontend/lib/earnkit/programs-api.ts`, with the logic, testable without HTTP

**Interface:** `POST /api/programs/write`

Headers: `Authorization: Bearer <EARNKIT_PROGRAMS_TOKEN>` and `Content-Type: application/json`. The body is one of:
- `{ "action": "upsert", "program": <ProgramFile JSON> }`
- `{ "action": "close", "id": "<program id>", "reason": "<text, at most 200 characters>" }`

**Responses (JSON):**

| Status | Body | When |
|---|---|---|
| 200 | `{ ok: true, id, result: "created" \| "updated" \| "unchanged" \| "closed", category, live: boolean }` | success |
| 400 | `{ ok: false, problems: string[] }` | invalid program |
| 401 | | missing or wrong token |
| 404 | | token unset |
| 409 | `{ ok: false, problems: ["<id> is curated by EarnKit; send a new id or ask the owner"] }` | curated program (R3) |
| 413 | | body over 256 KB |
| 429 | | over the rate limit |

**Checks, in order (stop at the first failing group):**
1. Feature on, token right, body at most 256 KB, JSON parses.
2. `ProgramFile.safeParse` passes, and the fields R4 forbids are absent.
3. `programProblems(p)` is empty.
4. API-only rules:
   - `id` matches `^[a-z0-9-]{3,64}$`
   - `verified_at` is within the last 7 days and not in the future
   - an `active` program has `ends_at` null or in the future
   - `source_url` and `submission_url` are https and not on a shared or optimism host
5. The existing row, if any, has `source` `api` (R3).
6. `source_url` and `submission_url` both load. Reuse the link checker other EarnKit code already uses; grep for the live-link check. Use a 5-second timeout. An `upcoming` program may share one URL for both.

Then `upsertProgram(p, 'api')`, and write a row to `program_writes` with the body. On "unchanged" (a deep-equal row), skip the write and still log the audit row.

**Rate limit:** 120 writes per rolling hour. Reuse the repo's existing rate limiter if there is one.

**Off switch:** `EARNKIT_PROGRAMS_API=off` returns 404 even when the token is set.
