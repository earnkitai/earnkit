## Owner ruling: one link, then a proof branch

The owner weighed four ways to prove the one project is the builder's (a gist, GitHub sign-in on the
claim page, a commit of earnkit.txt, a temporary branch) and chose the proof branch (2026-10-16): no
second sign-in, no file in the builder's repo, nothing for the builder to do, and the builder is told.

The first reply carries ONE link: `https://earnkit.com/claim/<code>` (Sign in with X, as today).

While the main project is a GitHub repo and not Bench-confirmed:
1. find gives a coding agent `proof: { repo, branch: 'earnkit-<code>', push, remove, agent_note }`.
   `push` is `git push origin HEAD:refs/heads/earnkit-<code>`: a branch at the current commit, no file,
   no commit. The code is 12 lowercase base32 characters, HMAC(EARNKIT_AUTH_SECRET, a random seed);
   only the seed and the code's sha256 are stored (`proof_branches`). It is bound to the person and this
   exact repo key, valid one hour, single use. A new code is issued only when none is open for the key,
   and at most once a day per person across all keys (ruling b). An agent that can't build gets no code
   and the line "Open this project in your coding agent to finish." (ruling c).
2. The builder reads one line: "I'll check Recipe planner is yours with a quick temporary branch on
   GitHub. It's removed right after."
3. EarnKit reads `GET /repos/{owner}/{repo}/git/ref/heads/earnkit-<code>` with its own GITHUB_TOKEN
   (redirects refused) on find and score (at most once a minute per code, claimed atomically) and in the
   hourly cron (with the run's budget and deadline); then the repo itself (the same key, never a fork or
   a template); then who pushed the branch (the repo activity API). A User's repo confirms only when its
   owner pushed it; an organization's repo for any pusher. A pass uses the code, verifies the repo source
   with proof `proof_branch`, records the pusher as the person's proven GitHub login (basis
   `proof_branch`), rescores the person at once (on the Bench, ranked, Started row), and the next reply
   tells the agent once: "Confirmed. Delete the branch now: git push origin :refs/heads/earnkit-<code>".
4. Exclusive: a repo another person already holds is never confirmed again and gets no code: "<project>
   is already on the Bench under another account." Discovery never revokes a `proof_branch` repo.
5. The branch never shows within the hour (no push access, an org repo without rights): one plain line,
   no loop, no proof line, until a new code may be issued a day later: "I couldn't show Recipe planner
   is yours. Ask your agent to use a project you can push to."
6. A coin (ruling a, fix round 2): the proof keeps GitHub's numeric repo id and owner. The token launch
   gate trusts it only when it is under 30 days old and a launch-time read of the repo shows the same id,
   still not a fork, and (a User's repo) the same owner. Otherwise the gate asks for a fresh proof branch
   ("I'll check <repo> is yours with a quick temporary branch on GitHub..."), never an earnkit.txt line.
   Discovery spares a `proof_branch` repo only from the not_owner verdict: a repo now derived, or whose id
   changed, is revoked; and its repo_owner verdict never verifies a repo another person holds. "Another
   person" compares group roots, so a person's own linked installation never counts.

No earnkit.txt line is pushed for the Bench under the flag (proofFor returns nothing). Builders with no
project skip the proof. No new go-live keys: GitHub sign-in is not needed for onboarding.

## Friction (fixed)

- Once claimed, every find/score reply shows `Your page: https://earnkit.com/<handle>`.
- A Bench branch of the server instructions: call find first; show show_to_builder as written; follow agent notes; a yes or no to the last line goes to tell move_up; score when they ask where they stand; never name tools, fields or files.
- `build_offer` carries no separate agent_note under the flag (move_up is the one route).
- Honest build copy: say it takes a few minutes and asks one or two things; never "you won't have to do anything" when a wallet is asked.
- The last line is always one question. Programs shown only when they fit the project (chain or any_chain); with none, the last line is the next Bench step.
- Profile while Confirming: no score ring or "Shipped 0" grid; one calm Confirming card ("Getting Recipe planner on the Bench. This takes one sign-in.") on the owner's own page and a neutral "Joining the Bench soon" for visitors; the Started card merges into its week's card as a chip.
- With EARNKIT_RAISING off, the landing hero and How it works don't mention raising.

## Security (fixed)

Strip HIDDEN characters before scanning, and re-scan the final text so every link in it equals a checked own link. Test the U+FEFF input.

## O5: the second first-run audit (N1 to N16)

Source: onboarding-audit-2.md. Controller rulings: the first find answers in under 3 s whatever the repo
(heavy GitHub reads run on in the background; the reply waits at most 1.5 s for each); a project the
branch can't prove says so at once (a 404, or a User's repo under another login; `tell proof { pushed:
false }` for a refused push); the note says to wait a minute and call find once more; a new public repo is
named at once (one cheap repo read sets `builder_sources.public_at`); a grants yes that finds nothing
keeps grants quiet a week and the next ask is one small thing to ship; with no project only ideas the
offered starter can enter; a builder with no wallet always gets a way out (every starter deploys a
contract, so the plain free-wallet line). Copy per the audit; one link in a first reply, one question last.

O5 fix round 1: before a code, one cheap repo read outside any lock, its verdict kept a day per person
and key (`standing_seen.repo_probe`; a coin launch reads again): a 404 says "EarnKit can't see <project>.
Use a public project.", a fork or template "<project> is a copy of another repo. Use your own project.",
a User's repo under another login "<project> is under someone else's GitHub account."; no code for any.
The proof check starts with the refresh and every wait ends by the call's start + 1.5 s. A match cut by
the wait is kept (`standing_seen.bench_match`, one hour) for the next reply. A tell reply the builder sees
ends on one question (a grants yes that finds nothing asks the next step).

Known limits:
- A person's proven GitHub login (else the reported one) is the only login compared: a builder proven as
  account A can't put a User repo under their other account B on the Bench (it reads as "under someone
  else's GitHub account").
- A kept 404 or copy verdict lasts a day: a repo made public (or no longer a fork) waits up to a day.
