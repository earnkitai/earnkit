## Owner ruling: one link, X then GitHub

The first reply carries ONE link: `https://earnkit.com/claim/<code>`. The claim page:
1. Sign in with X (as today).
2. Then, on the same page, "Show <project> is yours": Sign in with GitHub (OAuth App, no scopes).
   GitHub confirms the main project when the signed-in account owns the repo or can push to it
   (`permissions.push` or admin). That also proves the GitHub login (github_signin).
3. Done: "Recipe planner is on the Bench." with the page link.

No proof line is pushed by the agent under the flag; the agent never writes to the builder's repo to prove ownership.
Builders with no project: step 2 is skipped. An org repo GitHub can't show access to gets one plain line and no loop:
"GitHub didn't show that you can change this repo. Ask your agent to use a project in your own GitHub account."
Go-live needs GITHUB_OAUTH_CLIENT_ID and GITHUB_OAUTH_CLIENT_SECRET on Railway (callback https://earnkit.com/github/verify/callback).

## Blockers (all fixed)

| # | Fix |
|---|---|
| B1 | No project and no open build program: still offer the starter build ("Want me to build a tip jar and put it online? You'll be on the Bench today."). Never pitch a program that needs a live product to a builder without one. |
| B2 | The claim link is on every first reply while unclaimed, project or not. Full https via siteUrl(). |
| B3 | Proof via the claim page (ruling above); no silent push. While Confirming the reply says what to do: "Open your link and sign in with GitHub to show <project> is yours." |
| B4 | No build offer (or any ask) while a build is in progress: "Building <name>. I'll be back with the live link." |
| B5 | Org-repo loop: the plain line above; never send the builder back to a proof line. |
| B6 | The main project can change until it is confirmed: a newer project from the agent, or `not_mine` on the current one, replaces it. Set-once applies only after confirmation. |

## Friction (fixed)

- Once claimed, every find/score reply shows `Your page: https://earnkit.com/<handle>`.
- A Bench branch of the server instructions: call find first; show show_to_builder as written; follow agent notes; a yes or no to the last line goes to tell move_up; score when they ask where they stand; never name tools, fields or files.
- `build_offer` carries no separate agent_note under the flag (move_up is the one route).
- Honest build copy: say it takes a few minutes and asks one or two things; never "you won't have to do anything" when a wallet is asked.
- The last line is always one question. Programs shown only when they fit the project (chain or any_chain); with none, the last line is the next Bench step.
- Profile while Confirming: no score ring or "Shipped 0" grid; one calm Confirming card ("Getting Recipe planner on the Bench. This takes one sign-in.") on the owner's own page and a neutral "Joining the Bench soon" for visitors; the Started card merges into its week's card as a chip.
- With EARNKIT_RAISING off, the landing hero and How it works don't mention raising.
- GitHub sign-in page copy: "Sign in with GitHub to show <repo> is yours. It then goes on the Bench." / "Only continue if your agent gave you this link."

## Security (fixed)

update-text.ts parser differential: U+FEFF (and other HIDDEN characters) ends the link scan but is deleted by the cleaner, joining an unchecked tail to a stored link. Strip HIDDEN characters before scanning, and re-scan the final text so every link in it equals a checked own link. Test the U+FEFF input.

The audit's paths A to F re-run on a fresh install show no blocker and no friction item, each first reply has exactly one link and ends with one question, and the owner's own install on production goes: install, one link, two sign-ins, on the Bench.
