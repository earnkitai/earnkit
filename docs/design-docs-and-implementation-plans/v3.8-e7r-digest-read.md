# v3.8 E7r: the owner digest as a read, revert by bearer (mail kept)

Plan: `/workspace/cto/earnkit-power-user-plan-v3.8.md` item 10 and section 23.2. Build-plan row E7. Approval:
earnkitai/earnkit#159. Supersedes #165, which was stacked on #164 and deleted `mail.ts`. Main's program approval path
still sends its email through `mail.ts`, so the deletion has to wait.

## What changes (additive)

- `GET /api/programs/digest` (programs bearer; 404 while the API is off, 401 on a wrong token) returns
  `{ day, lines, changes: [{ program_id, title, fields, write_id, note? }], health, applications, results, mailed }`.
  `lines` is the digest text, one item per line, without the title line. A revertable change ends with
  `(revert: write <id>)` instead of a signed link. `mailed` says whether today's email already went.
- `POST /api/programs/revert` with an `Authorization` header: `{ "write_id": "<id>" }` under the programs bearer runs
  the existing single-use `revertWrite`. It answers 200 `{ id, result: reverted | closed }`, 404 when no applied write
  has that id, 409 `{ error, state }` (done, superseded, curated, no_earlier), and 400 for a bad body.
- `owner-digest.ts`: `sendOwnerDigest`'s gathering moves into `gatherDigest(now, asWrite)`, which only reads.
  `ownerDigest(now)` is the read; `sendOwnerDigest` is the same email as before.

## Unchanged (identical to main)

- The daily digest email: same text, signed revert links, idempotency key, `owner_digests` recording, and 'mail off'
  when `RESEND_API_KEY` is unset.
- `revertGet` and the signed link's `POST ?t=` (any request without an Authorization header), and the confirm page.
- `mail.ts`, `RESEND_API_KEY`, and the program approval email.

`RESEND_API_KEY`, the digest email (the cron records the day instead), the signed revert link, the confirm pages, and
