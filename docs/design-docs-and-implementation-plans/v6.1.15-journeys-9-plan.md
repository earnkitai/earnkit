**Rulings:**
- A `client_id` that is an https URL is fetched as a client metadata document (RFC draft client-id-metadata-document). The fetch is a GET with a 5 s timeout and a 10 KB cap. Redirects are not followed. Only https is allowed, and only public addresses: never localhost or private ranges. The content type must be JSON. Review Focus 18.
- The document's `client_id` must equal the URL; the `redirect_uri` must be listed in it; `client_name` comes from it, through the same `clientNameOf` and `reservedClientName`.
- Cache: 1 hour per URL for a good document, 5 minutes for a failure.
- The authorization-server metadata advertises `client_id_metadata_document_supported: true`.
- A document that fails any check gives the page `Connecting EarnKit failed. Your agent's client document could not be read.`
- Task 14 removes the `Register automatically` instruction Task 13 added to the Claude tab.

**Interfaces:**
- `safeFetchJson(url: string, deps?: { resolve?: Resolver; transport?: Transport; timeoutMs?: number; maxBytes?: number }): Promise<unknown>` (safe-fetch.ts, exported). It reuses `safeFetch`'s public-address check and pinned lookup. It throws `RedirectError` on any 3xx (never followed) and `SafeFetchError` for a non-https URL, a private or loopback address, a body over `maxBytes` (default 10,240), a timeout (default 5,000 ms), a content type that is not `application/json` (parameters allowed), or invalid JSON.
- `CIMD_FAILED = "Connecting EarnKit failed. Your agent's client document could not be read."` (oauth.ts, exported).
- `cimdClient(url: string, deps?): Promise<ClientPayload>` (oauth.ts): fetch through `safeFetchJson`, then check that `doc.client_id === url`, that `doc.redirect_uris` is a list of allowed URIs (`isAllowedRedirectUri`, at most 10 as Task 8's rule), and that `clientNameOf(doc.client_name)` passes `reservedClientName`. It returns `{ r: doc.redirect_uris, cn }`. Any failure throws `new OAuthError('invalid_client', CIMD_FAILED)`. Results are cached in a module `Map<string, { at: number; ok: ClientPayload } | { at: number; failed: true }>`: 1 hour for ok, 5 minutes for failed, at most 1,000 entries, oldest dropped first.
- `clientOf(clientId)` (Task 8): an `https://` client_id goes to `cimdClient`; a random id reads `oauth_clients`; a signed id from before v6.1.15 verifies as today. The CIMD branch is checked first only for a value that parses as an https URL, so a registered id never reaches it.
- `authorizationServerMetadata(origin)` gains `client_id_metadata_document_supported: true`.
- Limits: `registrationLimitKey` and `clientLimitKey` take the CIMD URL's host as the client key (`client:host:{host}`), so one hosted service's users share its per-client ceiling as `HOSTED_REDIRECTS` clients do. `hostedRedirectHost` reads the document's redirect URIs.
