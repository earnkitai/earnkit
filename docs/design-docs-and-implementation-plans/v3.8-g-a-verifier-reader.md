# v3.8 G-A (PR A): the official-page reader

Growth's acceptance run G-A wrote 20 programs through `POST /api/programs/write` with the official-page check fields.
Only 4 went live (H4 failed). This PR fixes items 1 to 5 of the G-A fix list. They share one path: the read of the
official page (`safe-fetch.ts`, `official-page.ts`, `programs-api.ts`). Items 6 (soonami submit host), 7 (BNB Chain)
and 8–9 (digest, organizer re-mark) are separate PRs.

## Design

**Reader (`safeReadPage`, safe-fetch.ts).** Every `safeFetch` guard is unchanged: https on 443 only, a domain name, every resolved address public with the connection pinned to it, one same-site redirect. A new `page` mode returns any non-3xx answer with its status and reads the body up to `PAGE_MAX_BYTES` (4 MB) within `PAGE_TIMEOUT_MS` (10 s); a longer body is cut at the cap, never refused.
- **User-agent ladder:** the first GET goes as `VERIFIER_UA` = `Mozilla/5.0 (compatible; EarnKit-verifier/1; +https://earnkit.com/docs#verifier)`. On a wall it retries once as `VERIFIER_BROWSER_UA`, a Chrome string that still ends in the same EarnKit-verifier contact suffix.
- **What counts as a wall:** 403, 405 or 429, or any answer whose short page carries challenge markers (`wallMarker`: AWS WAF, Cloudflare, DataDome, Imperva, PerimeterX), or a short 202.
- **Results:** a wall that survives the retry throws `PageBlockedError`. A 5xx throws `PageShellError` carrying what the server sent.

**Why the whole page is assembled before the search, not searched chunk by chunk.** A quote spans tags (`<strong>500-20,000 USDC</strong> per project`), hidden elements must be dropped first, and entities must be decoded. All of that needs the HTML, not the raw byte stream.
- Chunks are joined as bytes and decoded once, so a multibyte character or a quote split across chunk boundaries is handled (tested with `€` cut between chunks).
- 4 MB is a bounded memory cost on an owner-only, rate-limited route.

**Inline tags (found during the rerun).** Devpost renders amounts as `$<span>10,000</span>`. `visibleText` turned every tag into a space, so the page read "$ 10,000" while a person sees "$10,000". `pageText` now asks `visibleText` for `joinInline`, which removes inline tags (span, strong, a, em, …) after hidden elements are dropped. Hidden inline text still never counts, and block tags still separate words.

**Thin pages and shells (`readOfficial`, official-page.ts).** Thin means a visible text under 1,000 characters on a page that has scripts. (A short static page is simply short; the existing tests' pages are that.) Thin pages and 5xx shells are also searched in two more places:
- **Embedded data:** `embeddedText` reads `__NEXT_DATA__`, JSON-LD and the RSC `self.__next_f.push` strings. RSC references such as `$L29` are dropped.
- **A platform source:** `PLATFORM_SOURCES` is a table, one row per platform. Binance: article code → CMS API (JSON). ETHGlobal: event → `/prizes`. Both are read through the same guarded reader.

A walled page with a working platform source is checked like any page, so its quotes are verified. Embedded data counts as page text only on thin pages: it is what the page draws with JavaScript. On a normal page, hidden text still never counts.

**Still walled (programs-api.ts `officialCheck`).** The write goes live `info_only` with reason `official page blocked our reader; quotes not verified` only when one of these holds:
- the host is on a program platform (`PROGRAM_PLATFORMS` = `API_SUBMIT_HOSTS` without the form hosts, plus devpost.com), or
- `organizerStatus` confirms the domain (a recorded handle, or an earlier confirmed program).

Otherwise it is refused, and the reason names the ways forward (handle, a readable `official_url`, `track add_private`).
- **Why accept unverified quotes:** `info_only` forces `submit: builder` and drops `form`, so no agent sends and no prefill happens. The program is listed for the builder to check.
- **Wrong quotes:** a readable page with a wrong quote is refused as before; the A1 test passes on main and on this branch.
- **Missing quotes on a thin page or shell:** the refusal adds a private-row hint.
- **Response:** the success JSON now carries `reason` whenever a label applies.

**Link probe.** In the automated lane, `writeRefusal` no longer probes the URL that `officialCheck` reads itself; that read has the better rules (wall retry, shells). Otherwise ETHGlobal's 500 would be refused before the check ran.
- `HttpStatusError.wall`: a probe now reads 16 KB of a non-2xx answer, so a challenge page at any status counts as a wall for the write's probe and for the daily `probeLink`. Without this, a DoraHacks program would go stale the next day. A plain 405 is still a 4xx.

**Shorteners.** `SHORT_LINKS` (submit-hosts.ts) lists `forms.gle`, which may land only on `https://docs.google.com/forms/…`.
- `expandShortLink` follows one guarded redirect at a time (`redirectTarget`, at most 3 hops) while the link stays on the shortener. The landing page is never requested, and the `usp` parameter is dropped.
- Writer's links: a `forms.gle` `submission_url` or `form.url` is replaced by the form URL before any check, so it is probed and stored as the form. One that lands elsewhere is a 400.
- Page links: up to 5 `forms.gle` links on the official page are expanded for the info-only comparison.
- bit.ly is not expanded: it can land anywhere, so its link is judged as sent.

**Copy.** `INFO_ONLY_NOTE` (agent-facing) and `INFO_ONLY_SEND` (builder-facing) said "the link is not on the official page", which is not true for a walled page. They now say EarnKit couldn't confirm the link. `/docs#verifier` (the address in the user agent) and llms.txt `## Reader` explain the reader honestly, including the browser-style retry.

## Flags and safety

There is no flag: these are verifier fixes. With `EARNKIT_FLAGS` unset, writes without the check fields keep the held lane. The only change there is that a `forms.gle` link is stored as its form, and the form host is still held for approval, as before. No schema change and no new env var.

## Tests

`lib/v5/official-reader.test.ts` has 20 tests. It uses a fake transport that serves trimmed fixtures (`lib/v5/fixtures/pages/`), never the network. Each item's route test fails on main (verified by running the route tests against main's reader with the same fixtures) and passes here.
