# v2.14 One account: X at install, one proof, a ship log that writes itself

Status: approved by the owner (2026-10-18: "rest is all approved", with "keep it free"). Branch v2.14 from main ff8c46b6.

## Why

Most of v2.12 to v2.13.4's bugs and security findings came from bolting identity on after an anonymous install
(claim links, page groups, merges, R1 to R10, probation, notices, detach, the join registry) and from two proof
paths (proof branch for public repos, the App for private ones) plus discovery clues. The weekly update depends
on agents that can schedule, so most weeks would be empty. v2.14 removes the causes.

Owner rulings (2026-10-18): X at install; the GitHub App as the only proof; delete what the flags hide; replies as
a short state machine; the ship log written by EarnKit from the repo; private repos show facts only unless the
builder turns titles on; free (no AI summaries, no new paid service); the quick wins below.

## 1. X is the account, at install

- The MCP connector install's OAuth authorize step (today anonymous auto-approve, app/oauth/authorize) becomes
  "Sign in with X" (the existing X OAuth, x-oauth.ts). The access token issued to the agent is bound to the X
  account (x_user_id) from its first call.
- Person = X account. Every agent signed in with the same X is the same person; a reconnect is the same person.
  No claim codes, no claim page, no joins, no probation, no notices, no detach, no page groups or re-rooting for X.
- The profile page is earnkit.com/<x-handle>, created at first sign-in from the X profile (name, photo, handle).
- Shared clients (one agent serving many builders) keep today's per-call behaviour (no person binding).
- Preflight (task 1, before anything else): confirm Claude (Desktop, Code, web), Cursor and ChatGPT complete a
  browser sign-in during connector OAuth. A client that can't gets a one-time "Sign in with X" link in the first
  reply (the only fallback; it binds that installation to the X account the same way).
- Migration: existing claimed pages keep their handle and data; existing installations bound to a claimed page
  are bound to that X account; anonymous installations without a claim stay anonymous until they sign in.

## 2. One proof: the read-only GitHub App

- "Install EarnKit on your repo (read-only, one click)" is the only way a repo is proven, public or private,
  personal or org. The install proves access (the installation lists the repo and the installer owns the account
  or administers the repo, as github-app.ts appProof does) and gives EarnKit read access through installation
  tokens (minted per call, never stored or logged).
- Readings (commits per week, commit titles for the ship log, releases, the repo read) use the installation's
  token, so each builder has their own GitHub rate limit; the shared GITHUB_TOKEN is used only for public reads
  of things not yet installed (e.g. showing a reported public repo before it's proven).
- Removed: the proof branch (proof_branches, proof-branch.ts flows), the proof line, owned-repo discovery and the
  x_match / top-contributor clues, and the GitHub sign-in proof. Existing verified sources stay verified.
- The I1 private-name rule stays: a private repo's name shows publicly only when the builder's own agent named it.

## 3. The ship log writes itself (free)

- Each week (the existing Monday weekly facts step) EarnKit composes the entry for every project with the App
  installed: the week's top commit or PR titles (up to 3), cleaned (no merges, "wip", bot authors, version bumps,
  duplicates; trimmed; passed through the existing update-text filter for links, secrets and mentions), plus the
  verified fact chips already computed.
- On for everyone with a proven repo; no yes, no scheduling, no agent needed.
- Private repos: facts only (chips) by default. The builder can turn titles on: tell updates { titles: true }.
- The builder's agent may still add one line to the week ("tell update { text }" keeps working as an addition)
  or hide a week. The text filter applies to both.
- No AI summaries and no paid service: titles only.

## 4. Replies as a short state machine

Five states, each with one stand line, the money section, and exactly one question (the copy lives in one table,
bench-reply.ts):

| State | Stand line | The one question |
|---|---|---|
| Not signed in (fallback clients only) | "You're not on the Bench yet." | the sign-in link + "Want me to put your work on the Bench once you're in?" |
| Signed in, no project | "You're not on the Bench yet." | "What's your GitHub, or a link to something you've made?" |
| Project, App not installed | "<Project> isn't counted yet." | the install link + "Want me to count it once that's done?" |
| Proven | "<Project> is on the Bench: <rank>." | the next step (enter a fitting program, a community round, or put it online) |
| Shipping weekly | "<Project> is on the Bench: <rank>. <streak>." | the best way to move up |

Money ("Ways to get funded") always shows; one link and one question per reply; "community round", never "raise".

## 5. Delete what the flags hide

The Bench is the product. Retire EARNKIT_BUILDER_SCORE and EARNKIT_BENCH (always on) and delete the flag-off
paths: the v2.12 profile and leaderboard views, the builder bonus code (production owes nothing), the tip-jar
starter offer, the old find fields' special handling (keep accepting them, mapped once), and dead tests. Keep the
tables (no destructive migrations). EARNKIT_RAISING stays (legal switch).

## 6. Quick wins

- Self-host the fonts (next/font/local) so Google Fonts can't fail a build.
- One test database (or schema) per test file, so files never race.
- Agent-input tests go through the real MCP layer (tools/call), never only the handler.
- Keep the program list small and curated (owner adds programs).

## Cost

No new paid service. GitHub reads move to per-installation tokens (more headroom, same price: free). X sign-in
uses the existing X app. No AI calls.

## Acceptance (owner, on production)

1. Add EarnKit to a fresh agent: the install asks to sign in with X; after it, the first reply already shows your
   page link (or "not on the Bench yet"), the money section and one question.
2. Add it to a second agent with the same X: it's the same page, nothing to approve or merge.
3. Install the EarnKit app on earnkitai/earnkit: the next reply says it's on the Bench with a rank.
4. The next Monday: the profile shows that week's entry written from the commits (facts only for a private repo
   unless titles are on); nobody scheduled anything.
5. Every reply has one link and ends with one question.
