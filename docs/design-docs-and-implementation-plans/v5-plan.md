# EarnKit v5: the grant inbox. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace EarnKit's v4 surface with one job: a repo in, pre-filled applications, gap-closers and a private ledger out, through two MCP tools, with no setup step and a program pipeline that stays broad and fresh.

**Architecture:** v5 is built fresh in `apps/frontend/lib/v5/` (small, single-purpose modules, each with its own test file), porting code from `lib/earnkit/` only where a task names the file to port from. The `app/` routes the design keeps are switched to `lib/v5` as tasks land; everything else under `lib/earnkit/`, `app/`, `scripts/`, `infra/`, `contracts/`, `archive/` is deleted in one cut task near the end, so the build stays green at every task boundary and no task has to untangle v4's import graph. The database schema is rewritten (`db/schema.sql`) to the v5 tables, additive to production: v4 tables stay untouched and unread.

**Tech Stack:** Next.js 16 (App Router), TypeScript, postgres.js, zod 4, `@modelcontextprotocol/sdk` (Streamable HTTP, stateless), node:test with the per-file test database (`lib/earnkit/fixtures/test-db*.mjs`, moved to `lib/v5/fixtures/` in Task 10). No LLM, no chain RPC, no object storage.

**Spec:** `docs/design-docs-and-implementation-plans/v5-design.md` (approved 2026-11-03). The SDD ledger is `v5-sdd-ledger.md` beside it.

## Review Focus

1. A private repo with no `repo_url` and only agent-reported chains must still get `ready` and `gaps`, marked `as_reported: true`, never a crash or an empty reply (Task 4 test `reported-only project matches`).
2. A `track won` with no `amount_usd`, a negative amount, or an unknown `program_id` must be refused with a plain note and write nothing (Task 6 test `won needs a positive amount`).
3. A program whose `ends_at` passed between the daily probe and the builder's call must not be in `ready` (Task 4 test `closed by deadline is never ready`).
4. An API write that changes `form` goes to pending, and `GET /api/programs` keeps serving the live program unchanged until approval (Task 2 test `form change waits for approval`).
5. The first `find` ever on an installation returns `since` empty (no "2 new programs" built from the whole catalogue) and sets `last_find_at` (Task 7 test `first find has no since`).
