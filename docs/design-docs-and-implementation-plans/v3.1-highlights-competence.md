# v3.1 Highlights: builder competence (2026-10-25)

Owner rulings (2026-10-25), binding:
- The old card was "utterly stupid": monitoring trivia, jargon, commit counts.
- Highlights show what ecosystems and investors value about the **builder's competence**, chain-agnostic.
- **Never anything coin related**: no coins, tokens, test coins, factory launches, fees, backers.
- **No Base-specific rows**: Builder Code is out of Highlights (it stays in replies); "On Base since" and
  "Wallet proven by signature" are out.
- Contracts deployed is a good signal: keep it, across chains.

## The card

At most 5 rows, in this order; a row with no data is left out (never a placeholder). Every row links to its proof
where a visitor can open it.

| # | Icon | Title | Sub | Link |
|---|---|---|---|---|
| 1 | live | `Live at <host>` (unchanged liveItem) | unchanged liveSub | the site |
| 2 | contract | `<N> contract(s) on <chain>` or `<N> contracts on <K> chains` | `Since <Mon YYYY>` (earliest) | explorer page of the earliest |
| 3 | products | `Shipped <N> products` (only N >= 2) | the hosts, oldest first, comma separated, at most 3 then "and N more" | the oldest product's site |
| 4 | consistency | `Shipped in <N> of the last 52 weeks` (N >= 1) | `Building <name> since <Mon YYYY>` (repo created_at; omit name when PRIVATE_NAME; empty sub when unknown) | the repo while public |
| 5 | won | won/accepted program items only (programLabel), never "Applied to" | month | program guide |
| 6 | experience | `Writing code since <YYYY>` | `On GitHub since <Mon YYYY>` | https://github.com/<login> |

Experience is a filler: it only shows while fewer than 5 of rows 1 to 5 exist (slice keeps the first 5).
Removed from Highlights: codeItem (Builder Code), walletItem, repoItem's commit count, "Applied to" items, the
contractItem's "On Base since". The start item for unconfirmed builders stays as it is.

## Contracts deployed (new)

- **Whose:** contracts a wallet the builder proved by signature (person_wallets) created itself: a top-level
  transaction from the wallet with no `to`, status success (the receipt's contractAddress). Factory launches never
  count (they are not top-level creations by the wallet).
- **Chains:** read on every chain in `WALLET_CHAINS` = base (base-mainnet, basescan.org), ethereum (eth-mainnet,
  etherscan.io), arbitrum (arb-mainnet, arbiscan.io), optimism (opt-mainnet, optimistic.etherscan.io), polygon
  (polygon-mainnet, polygonscan.com). Alchemy answers "X is not enabled for this app" for a network the owner has not
  switched on (today only base, ethereum, arbitrum are on): that chain is skipped quietly (no log noise beyond one line),
  and turns on by itself when the owner enables it in the Alchemy dashboard.
- **Not coins:** a contract whose `decimals()` and `totalSupply()` both answer (eth_call, non-empty 32-byte result)
  is a token and never counts.
- **Used:** a contract counts only when at least one other address sent it a transaction
  (alchemy_getAssetTransfers toAddress = contract, category external, excludeZeroValue false, maxCount small,
  any `from` different from the deployer). This drops test deploys.
- **Caps:** per wallet per chain at most `READ_CAPS.walletPages` pages and `WALLET_CREATIONS_MAX` creations (as
  alchemyCreations today). Reads stop at the discovery deadline (ScoreDeadline).
- **Store:** new table (append to db/schema.sql):
  `wallet_contracts(chain text, address text, wallet text, created_at timestamptz, counts boolean, read_at timestamptz,
  PRIMARY KEY (chain, address))`, with an index on wallet. `counts` = not a token and used. A re-read upserts.
- **When:** in discovery's proven-wallet step (discovery.ts, the T7 loop), so it runs at proof time (wallet-proof.ts
  discoverNow) and in the daily discovery. Keep the existing Base `claim` of wallet creations working (score code uses
  it), but feed it from the same read so Base creations are read once.
- **Highlight:** counts the builder's wallet_contracts rows with counts = true (join person_wallets on wallet).
  Single chain: `3 contracts on Base`; several: `12 contracts on 3 chains`. Chain labels: Base, Ethereum,
  Arbitrum, Optimism, Polygon. Never a wallet address in the text.

## Products shipped (new)

Distinct hosts of the builder's verified site sources (any project) that have read up at least once, same rules as
liveItem (hostOf, a hidden repo's GitHub-hosted site left out), ordered by first up day. Shown from 2 hosts.

## Consistency

From ProfileData.grid (last52 weeks, on = a week with code): N = weeks on. The sub reuses the repo reading's
created_at as repoItem does.

## Experience

github_users.created_at for builder_profiles.github_login (people-signals.ts already fills github_users). Shown only
when the login is proven (builder_profiles.github_login is only set from a verified source).

## Copy rules

Sentence case, no em dashes, no emojis, numbers with toLocaleString('en-US'), singular forms ("1 contract",
"1 product" never shown since products needs 2).
