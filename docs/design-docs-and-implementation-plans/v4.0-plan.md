# v4.0: builder tokens in EarnKit. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Setup becomes three steps (X, GitHub, wallet), the wallet step launches the builder's one token unless they say no, the builder page shows the approved Token card, builders hear their community support in plain words every week, and the owner gets one email when the Safe holds $5,000 or more.

**Architecture:** All logic stays in `apps/frontend/lib/earnkit/`, reached through the MCP tools and the hourly cron. The setup asks live in the pure `bench-reply.ts` (`stateAsk`, `STATE_COPY`) fed by `bench-find.ts benchView`; the token is `builder-token.ts` (done, Task 2); replies are rendered per surface in `reply-format.ts`. The old per-project coin offers are unwired and deleted.

**Tech Stack:** Next.js 16, TypeScript, Postgres (`postgres` tagged template), zod, node:test through tsx (`fixtures/test-guard.ts`), `fixtures/mcp-call.ts mcpCall` for reply assertions.

**Spec:** `docs/design-docs-and-implementation-plans/v4-builder-tokens.md` (rulings and approved copy, word for word). tokens.fun's side is plan v4.1 (`minidevai/tokens.fun`, branch `v3-earnkit-revamp`).

## Global Constraints

- Copy is the spec's approved copy, word for word; tone a friendly, encouraging mentor; no emojis; never an em dash.
- "token", never "coin", in every new or changed builder-facing line; "holders" and "Trade" on the Token card; never "bet".
- The token is never the pitch: no token line before setup step 3, never in the intro.
- One token per builder and per X account (`builder_tokens`, Task 2); a no is kept forever; nothing launches twice.
- Builder tokens launch only while `EARNKIT_BUILDER_TOKENS=on` (off by default; the owner turns it on at go-live).
- Rich markdown (tables, lists, bold) only for rich surfaces; WhatsApp agents get plain "Label: value" lines.
- `db/schema.sql` append-only and idempotent; no new paid service, no new cron (steps join `runCron`).
- Tests: one file: `DATABASE_URL=postgres://localhost:5432/postgres node apps/frontend/lib/earnkit/fixtures/test-db-template.mjs && DATABASE_URL=postgres://localhost:5432/postgres npx tsx --test --import ./apps/frontend/lib/earnkit/fixtures/test-guard.ts apps/frontend/lib/earnkit/<file>.test.ts`. Full: `DATABASE_URL=postgres://localhost:5432/postgres pnpm test` (2829 pass at Task 1). Also `cd apps/frontend && npx tsc --noEmit -p .`.
- Commit after each task on `v4-builder-tokens`; messages end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; no push until the release PR.
- Model per task: Opus for money, launch, auth and reply copy; Sonnet otherwise.

## Review Focus

1. The builder signs the wallet page but the agent never calls `tell`: the token still launches (the hook is in the wallet proof, not the reply). Pinned in Task 4 test (c).
2. A builder who said no before signing: the proof launches nothing. Pinned in Task 4 test (d).
3. A second wallet proof (a wallet change) never launches a second token, and a declined builder stays declined. Pinned in Task 4 test (e).
4. A legacy install with no claimed X account never sees the token sentence and never launches. Pinned in Task 4 test (f).
5. A WhatsApp agent never receives `|` table rows or `**`. Pinned in Task 6 test (b).
