# v2.8 Win Engine: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The site sells installs in one screen (money hero, one premium builder bonus pill, a programs carousel, "How you earn", a real footer, a fixed install modal); the token becomes the builder bonus ticket and launches on the builder's confirmation "yes"; an application coach turns a few short answers into a strong application for every program and reuses them across programs; a submit kit hands each answer to the program's form in the way that platform allows; "Also qualifies" shows up to 3 more payouts per project; outcomes start being captured.

**Architecture:**
- **Part A (Tasks 1 to 5) is the site and the agent text.** It ships on its own: no schema change, no new tool.
- **Program files stay the single source.** New optional fields (`kind` and `guidance` per form field, `judging`, `form`, `submit_host`, `submit_api`, `results`, `any_chain`, the `rated_by: "earnkit"` rating) sync to additive `programs` columns or ride inside the existing `submission_requirements` JSON. Adding a program means filling its file.
- **Pure modules carry the novel logic:** `coach.ts` (field kinds, guidance, questions, pre-submit check, draft table), `submit-kit.ts` (host registry, prefilled links, the kit), `also-qualifies.ts`, `outcomes.ts` (matcher). Tools only read, call them, and write.
- **One new tool, `confirm_entry`, is the confirmation step.** It records the entry, launches the token on "go", stores the application snapshot and the answer bank, and is the only place a submit kit is returned. `record_submission` stays the "I submitted" call (proof, Also qualifies).
- **Bonus eligibility is enforced in SQL:** a launched EarnKit token, a complete entry (the v2.7 C7 gate, moved here), a counted submission, and never a skipped confirmation.

**Tech Stack:** Next.js 16 (App Router), React 19, Tailwind 3, postgres.js, zod v4, node:test via `tsx --test`, the `typescript` compiler API (already a root devDependency) for the source scan.

**Spec:** `docs/design-docs-and-implementation-plans/v2.8-win-engine.md` (approved 2026-10-07, binding).

**Execution method (chosen by the owner):** subagent-driven. A fresh implementer works on each task, a fresh reviewer checks it before the next task starts, and a whole-branch review runs at the end.

**Plan format note (Ruling 0, as in v2.5 to v2.7):** every task gives exact interfaces, behaviours, values and test cases. Full code is given only for novel logic:

## Plan Rulings (spec gaps)

- **Ruling 1 (plan), where the entry and the token live before `record_submission`.**
  - The confirmation "yes" (or "skip") goes to a new tool, `confirm_entry`. It creates the entry: a `projects` row, found or inserted through the same `ownEntry` rule `recordSubmission` uses (same installation, program and normalized repo, or the same name without a repo), with `bonus_repo_key` set. The token's claim, `token_url`, `coin_address` and `creator_wallet` live on that row, exactly as today.
  - New additive columns mark it: `projects.confirmed_at` (when the builder passed the confirmation) and `projects.confirm_choice` (`'go'` or `'skip'`).
  - `record_submission` later finds the same row through `ownEntry` and updates it (answers, proof, `builder_submitted`). For a row with `confirm_choice` set it never runs a token flow; it reports the row's token.
  - A `record_submission` for an entry that never passed `confirm_entry` (an older agent) keeps v2.7's token path, minus the C7 readiness gate (Ruling 2).
  - Campaign programs are refused by `confirm_entry` ("EarnKit campaigns are entered in one step"); they keep v2.4.
  - The new row counts against `recordSubmission`'s 20 a day; a launch counts against `tokenLaunch`'s 3 a day, as now.
- **Ruling 2 (plan), the C7 gate moves to bonus eligibility.**
  - New column `projects.complete_at`: set (once, never cleared) the first time the entry's stored answers and links pass `prepareSubmission(...).ready`, by `confirm_entry` or `record_submission`.
  - `eligibleSql` and `bonusEligible` require `complete_at` before the round's end, next to the existing coin and submission conditions.
  - Backfill, the one data update: `UPDATE projects SET complete_at = coin_launched_at WHERE complete_at IS NULL AND coin_launched_at IS NOT NULL`. Every token launched before v2.8 passed v2.7's C7 gate or predates it, so no existing entry loses eligibility.
  - The token flow drops `entryMissing` and `notReadyAgentNote` from the launch path (the functions stay, used by the new eligibility note).
- **Ruling 3 (plan), "skip" is final for the bonus.** `confirm_choice = 'skip'` excludes the entry in `eligibleSql` and `bonusEligible`, even if a token is launched later. `launch_token` on a skipped entry is refused with "This entry was entered without a token." A builder who changes their mind confirms again with "go" through `confirm_entry`, which flips `confirm_choice` to `'go'` only while the row has no `submission_confirmed_at`; after submission the choice is locked.
- **Ruling 4 (plan), the ordering rule in code.**
  - `prepare_submission` never returns a kit, a prefilled link, a field-by-field paste list, agent fill steps or an api payload, and stops returning `submission_url`. `get_program` keeps its program links (program facts, not a kit with final answers).
  - `confirm_entry` without `builder_confirmed: true` and a `decision` returns the confirmation offer, not a kit.
  - On `go`, a **fixable** token problem (no wallet; ticker taken; ownership line not found yet; a transient gate or network failure) returns the problem and **no kit**: the agent fixes it (or asks for the wallet) and calls `confirm_entry` again.
  - On `go`, a **lasting** problem (the agent said it can't push; no public repo; this repo's token is entered in another program; token launches unavailable; the program is `token_policy: 'off'`; the daily launch limit) returns the kit with one plain line saying why there is no token. The entry is never bonus-eligible without a launched token (Ruling 2's SQL).
  - On `skip`, the kit is returned and the entry is never bonus-eligible (Ruling 3).
- **Ruling 5 (plan), one token per repo and Also qualifies.** The repo's token belongs to the first program it launched in (owner decision A). A later program's confirmation has no token offer; it reads `Builder bonus counts in Arc Microgrants.` then `Ready to submit?`. Its `go` records the entry with no token and returns the kit. That entry is never bonus-eligible in the later program (no coin on its row), which is the intended behaviour.
- **Ruling 6 (plan), the answer bank and its privacy.**
  - New table `answer_bank (installation_id, project_key, kind, answer, program_id, updated_at)`, primary key `(installation_id, project_key, kind)`. `project_key` is the normalized repo, else `name:<lowercased trimmed name>`.
  - Written by `confirm_entry` from the confirmed answers (one row per field kind, the latest wins). Kind `other` is never banked (it is program-specific). Each answer at most 4096 characters (`SUBMISSION_VALUE_MAX`).
  - Read only for the same installation. Never shown on a public page, in `/api/stats`, on an admin page, in the bonus board, or in a log line (`console.error` calls in these paths log ids and error classes only). The application snapshot on `projects.application` follows the same rule: no public or admin page reads it.
- **Ruling 7 (plan), what the agent can do.** `prepare_submission` and `confirm_entry` take `agent: { browser?: boolean; can_push?: boolean }`.
  - `browser` (default false): the agent has a browser tool that drives the builder's own logged-in browser. Without it, `agent_fills` falls back to `copy_paste`.
  - `can_push` (default true): the agent can push to the repo. `false` means no token launch is attempted and the builder sees `To launch your token, open this in Claude Code or Cursor.` The entry still records.

```ts
// human-text.ts
import ts from 'typescript';
import { readdirSync, statSync } from 'node:fs';
import { join, relative } from 'node:path';

export const EM_DASH = '—';

/**
 * v2.8 Ruling 16 (plan): the human text in one source file: string literals, template literal
 * parts and JSX text. Comments are trivia, so the scanner never sees them. Pure.
 */
export function humanStrings(path: string, source: string): { text: string; line: number }[] {
  const kind = path.endsWith('.tsx') ? ts.ScriptKind.TSX : ts.ScriptKind.TS;
  const file = ts.createSourceFile(path, source, ts.ScriptTarget.Latest, true, kind);
  const out: { text: string; line: number }[] = [];
  const add = (n: ts.Node, text: string) =>
    out.push({ text, line: file.getLineAndCharacterOfPosition(n.getStart()).line + 1 });
  const walk = (n: ts.Node) => {
    if (ts.isStringLiteral(n) || ts.isNoSubstitutionTemplateLiteral(n)) add(n, n.text);
    else if (ts.isTemplateHead(n) || ts.isTemplateMiddle(n) || ts.isTemplateTail(n)) add(n, n.text);
    else if (ts.isJsxText(n) && n.text.trim()) add(n, n.text);
    ts.forEachChild(n, walk);
  };
  walk(file);
  return out;
}

const SOURCE_DIRS = ['apps/frontend/app', 'apps/frontend/lib', 'apps/frontend/scripts'];
const TEXT_FILES = ['apps/frontend/public/llms.txt', 'programs/README.md', 'README.md', 'apps/frontend/README.md'];
const skip = (p: string) =>
  /\.test\.tsx?$/.test(p) || p.includes('/fixtures/') || p.includes('node_modules') || p.endsWith('/human-text.ts');

/** Every file Ruling 16 scans, repo-relative. */
export function humanTextFiles(root: string): string[] {
  const files: string[] = [...TEXT_FILES];
  const walkDir = (dir: string) => {
    for (const name of readdirSync(join(root, dir))) {
      const rel = `${dir}/${name}`;
      if (skip(rel)) continue;
      if (statSync(join(root, rel)).isDirectory()) walkDir(rel);
      else if (/\.(ts|tsx|mts)$/.test(name)) files.push(rel);
    }
  };
  SOURCE_DIRS.forEach(walkDir);
  for (const name of readdirSync(join(root, 'programs'))) if (name.endsWith('.json')) files.push(`programs/${name}`);
  return files.map((f) => relative(root, join(root, f)));
}
```

```ts
// carousel.ts: v2.8 Ruling 20 (plan). Pure, so the scroll math is tested without a DOM.
export function scrollStep(a: { scrollLeft: number; clientWidth: number; scrollWidth: number; cardWidth: number; gap: number; dir: 1 | -1 }): number {
  const max = Math.max(0, a.scrollWidth - a.clientWidth);
  return Math.min(max, Math.max(0, a.scrollLeft + a.dir * (a.cardWidth + a.gap)));
}

export function arrowState(a: { scrollLeft: number; clientWidth: number; scrollWidth: number }) {
  if (a.scrollWidth <= a.clientWidth) return { prev: false, next: false };
  return { prev: a.scrollLeft > 0, next: a.scrollLeft + a.clientWidth < a.scrollWidth - 1 };
}
```

```ts
const DIGIT = /\d/;
const LINK = /https:\/\/\S+/;
const CLAIM = /\b(users?|customers?|revenue|volume|growth|transactions|downloads|installs)\b/i;
const NUMBER_KINDS: FieldKind[] = ['traction', 'use_of_funds', 'milestones'];

const short = (label: string) => label.replace(/\s*\([^)]*\)\s*$/, '').replace(/[?:.]\s*$/, '').slice(0, 40);

export function bankFill(reqs: SubmissionRequirement[], answers: Record<string, string>, bank: Map<FieldKind, string>) {
  const out = { ...answers };
  const from_bank: Record<string, string> = {};
  for (const r of reqs) {
    const k = kindOf(r);
    if (k === 'other' || out[r.key]?.trim()) continue;
    const banked = bank.get(k);
    if (banked) out[r.key] = from_bank[r.key] = banked;
  }
  return { answers: out, from_bank };

export function questionsFor(a: { reqs: SubmissionRequirement[]; answers: Record<string, string>; first: boolean }): Question[] {
  const empty = a.reqs.filter((r) => r.required && !a.answers[r.key]?.trim() && !AGENT_DRAFTS.includes(kindOf(r)));
  const out: Question[] = [];
  for (const kind of QUESTION_ORDER) {
    const reqs = empty.filter((r) => kindOf(r) === kind);
    if (reqs.length === 0) continue;
    if (kind === 'contact') {
      const labels = reqs.map((r) => short(r.label).replace(/^(your|the)\s+/i, '').toLowerCase());
      const list = labels.length > 1 ? `${labels.slice(0, -1).join(', ')} and ${labels.at(-1)}` : labels[0];
      out.push({ keys: reqs.map((r) => r.key), kind, text: `Your ${list}?` });
    } else {
      const g = guidanceFor(reqs[0]);
      out.push({ keys: reqs.map((r) => r.key), kind, text: g.questions[0] ?? `${short(reqs[0].label)}?` });

export function preSubmitCheck(a: { reqs: SubmissionRequirement[]; answers: Record<string, string>; judging: Judging | null }): Fix[] {
  const fixes: Fix[] = [];
  const val = (r: SubmissionRequirement) => a.answers[r.key]?.trim() ?? '';
  for (const r of a.reqs) if (r.required && !val(r)) fixes.push({ key: r.key, rule: 'empty', text: `${short(r.label)}: still empty.` });
  for (const r of a.reqs) {
    const v = val(r);
    if (!v) continue;
    const limit = guidanceFor(r).limit_words;
    if (limit && words(v) > limit)
      fixes.push({ key: r.key, rule: 'over_limit', text: `${short(r.label)}: ${words(v)} words; keep it to ${limit}.` });
    else if (r.max_chars && v.length > r.max_chars)
      fixes.push({ key: r.key, rule: 'over_limit', text: `${short(r.label)}: ${v.length} characters; keep it to ${r.max_chars}.` });
  }
  for (const r of a.reqs) {
    const v = val(r);
    if (v && !DIGIT.test(v) && (NUMBER_KINDS.includes(kindOf(r)) || CLAIM.test(v)))
      fixes.push({ key: r.key, rule: 'no_number', text: `${short(r.label)}: add a number (users, volume or revenue).` });
  }
  const all = a.reqs.map(val).join('\n');
  if (!LINK.test(all)) {
    const target = a.reqs.find((r) => ['links', 'demo_video', 'how_it_works'].includes(kindOf(r))) ?? a.reqs[0];
    fixes.push({ key: target.key, rule: 'no_proof_link', text: 'Add one proof link (live app, demo or contract).' });
  }
  for (const c of a.judging?.criteria ?? []) {
    const hit = c.words.some((w) => new RegExp(`\\b${w}`, 'i').test(all));
    if (!hit) fixes.push({ key: '', rule: 'criterion', text: `No answer shows ${c.text.toLowerCase()} yet.` });
  }
  return fixes.slice(0, MAX_FIXES);
```

```ts
    const badChoice = r.type === 'choice' && !(r.options ?? []).includes(v);
    if (!param || badChoice || r.type === 'file') left.push(r.key);
    else pairs.push([r.key, param, v]);
  }
  return { pairs, left };
}

function build(base: string, sep: '?' | '&', paramOf: (p: string) => string, form: FormData, reqs: SubmissionRequirement[], answers: Record<string, string>) {
  const { pairs, left } = fillable(form, reqs, answers);
  const over: string[] = [];
  const url = prefill(base, sep, pairs.map(([, p, v]) => [paramOf(p), v]), over);
  const overKeys = pairs.filter(([, p]) => over.includes(paramOf(p))).map(([k]) => k);
  const order = reqs.map((r) => r.key);
  return { url, left: [...left, ...overKeys].sort((a, b) => order.indexOf(a) - order.indexOf(b)) };
}
```

```ts
const DAY = 86_400_000;

export function alsoQualifies(a: {
  enteredProgramId: string; chains: Chain[]; programs: AlsoProgram[]; enteredIds: Set<string>;
  bank: Map<FieldKind, string>; answers: Record<string, string>; now: Date;
}): AlsoRow[] {
  const rows = a.programs
    .filter((p) => p.id !== a.enteredProgramId && !a.enteredIds.has(p.id))
    .filter((p) => p.status === 'active' && p.source === 'file' && !p.campaign && p.existing_work !== 'new_work_only')
    .filter((p) => p.ends_at === null || p.ends_at.getTime() - a.now.getTime() >= 2 * DAY)
    .filter((p) => p.any_chain || p.chains.some((c) => a.chains.includes(c)))
    .map((p) => {
      const filled = bankFill(p.requirements, a.answers, a.bank).answers;
      const empty = p.requirements.filter((r) => r.required && !filled[r.key]?.trim());
      const contact = empty.some((r) => (r.kind ?? 'other') === 'contact') ? 1 : 0;
      const left = empty.filter((r) => (r.kind ?? 'other') !== 'contact').length + contact;
      return { p, left };
    })
    .sort((x, y) =>
      x.left - y.left ||
      (y.p.pool_usd ?? -1) - (x.p.pool_usd ?? -1) ||
      (x.p.ends_at?.getTime() ?? 8.64e15) - (y.p.ends_at?.getTime() ?? 8.64e15));
  return rows.slice(0, MAX_ALSO).map(({ p, left }) => ({
    id: p.id, title: p.title, prize: prizeOf(p), ends: endsOf(p), left,
  }));
}
```
