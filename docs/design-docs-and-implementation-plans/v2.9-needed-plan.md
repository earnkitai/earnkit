# v2.9 Needed, not optional: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the lazy builder what an agent alone can't: accurate fit (owned, real products only, with checked links and contracts), a token any agent can launch (GitHub sign-in proof, offered right after the match), a live link on earnkit.com, fees that claim themselves, and a weekly email, while EarnKit's money figure, legal page and tool text get simpler.

**Architecture:**
- **Part A (Tasks 1 to 4) is matching.** New pure logic lives in `verify.ts` (placeholder links, cache rules), `match.ts` (`ownerOk`, `productScore`, `applyBuilderFacts`, the new `matchRepo` rules) and `guide.ts` (`rowDifficulty`). `match-projects.ts` gathers the facts, bounded per call. Builder statements live in two new tables written by one new tool, `tell_earnkit`, which replaces `report_outcome` (the tool count stays 9 with the sponsor tool, 8 without).
- **Part B (Tasks 5, 6) is the token.** `github-verify.ts` plus two routes add a scopeless GitHub sign-in as ownership proof; `token-gate.ts` accepts it in place of the proof line. The first reply closes with a token offer that `launch_token` can answer without an entry (it makes a draft entry).
- **Part C (Tasks 7, 8) is hosting.** A Cloudflare Worker (source and tests in `infra/host-worker/`, never deployed by this plan) serves `<slug>.earnkit.com` from R2. The Railway app receives one zip per deploy at `app/api/host/upload`, checks it and writes to R2 with EarnKit's key. Expiry runs in the existing hourly cron.
- **Parts D to F (Tasks 9 to 11)** extend the existing hourly `claimFees`, add the weekly email to the same cron, and simplify money, legal and tool text.
- **Every new piece is off when its env vars are absent** (R2, GitHub OAuth, Resend), and every free tier has a hard cap in code (`free_tier_usage`).

**Tech Stack:** Next.js 16 (App Router), React 19, postgres.js, zod v4, viem, node:test via `tsx --test`. New dependencies (both MIT, zero transitive deps, no service): `fflate` (zip reading with size checks) and `aws4fetch` (SigV4 for R2's S3 API). Cloudflare Worker source in TypeScript with local structural types (no `@cloudflare/workers-types`, no `wrangler` in the test path).

**Spec:** `docs/design-docs-and-implementation-plans/v2.9-needed.md` (approved 2026-10-08, binding). The matching details it cites ("the matching audit") are the read-only audits of 2026-10-08; this plan copies what it needs from them, so the audits are not required reading.

**Plan format note (as v2.5 to v2.8):** every task gives exact interfaces, behaviours, values and test cases. Full code only for novel logic: `placeholderHost` and the check cache (T1), `ownerOk` and `productScore` (T2), `applyBuilderFacts` (T3), `rowDifficulty` and `alertable` (T4), the nonce SQL and `ownershipPasses` (T5), `tokenOffer` (T6), the Worker's routing (T7), the zip checks, abuse scan, slug and expiry (T8), the claim loop's owners and the gas check (T9), `takeFreeTier`, `digestDue` and `digestBody` (T8, T10), `openMoneyUsd` (T11). Implementers write the rest to these interfaces, following the modules they extend.

## Global Constraints

- **Goals, in order:** installs, then token launches. Persona: a lazy builder who only wants money.
- **Zero extra spend.** Free tiers only, with hard caps in code so a bill can never start:
  - R2: total stored under 8 GB (`HOST_LIMITS.totalBytes = 8_000_000_000`; R2 free is 10 GB); R2 write operations (Class A) at most 900,000 a calendar month (`R2_WRITES_MONTH_MAX`; free is 1M).
  - Resend: at most 100 emails a UTC day and 3,000 a calendar month (`RESEND_DAY_MAX = 100`, `RESEND_MONTH_MAX = 3000`).
  - The Worker runs on the free plan (stops at 100k requests a day, never bills).
  - No new service, no new cron, no new Railway variable that costs money. GitHub OAuth, probes and RPC reads are cached; RPCs are public endpoints.
- **Gas:** EarnKit sponsors gas for token launches only (tokens.fun pays it). No wallet top-ups, no gas drip, no paymaster. Contract deploys stay the builder's own.
- **Alerts:** the email is weekly only (Mondays from 14:00 UTC), opt-in only, never empty, with one-click unsubscribe (`List-Unsubscribe`).
- **Hosting:** earnkit.com subdomains only (`<project>-<user>.earnkit.com`, one level). Reserved names (`www`, `docs`, `api`, `mcp`, `app`, `mail`, `admin`, `status`, plus every existing DNS record) never route to the Worker. Every hosted response carries `Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-modals; form-action 'self'`. Files are deleted 7 days after the site's program ends (a site with no entry: 7 days after upload). Static only: no server code, no custom domains.
- **Never launch a real token or broadcast a transaction in tests.** Token deploys use the existing fakes (`ToolContext.tokenDeps`, the mocked tokens.fun in the journey tests); chain writes use the existing anvil-only tests; Resend, R2, GitHub and RPCs are injected fakes. Any other `fetch` in a test gets a 503.
- **Never print secrets.** No log line, reply, error or test output contains `CAMPAIGN_PAYOUT_PRIVATE_KEY`, `R2_SECRET_ACCESS_KEY`, `GITHUB_OAUTH_CLIENT_SECRET`, a GitHub user token, `RESEND_API_KEY`, `CRON_SECRET`, `ADMIN_VETO_SECRET`, a nonce or an upload token. `console.error` in new paths logs ids and error class names only.
- **Keep operator and deployer keys off Railway.** The only wallet key on Railway stays `CAMPAIGN_PAYOUT_PRIVATE_KEY`. New Railway variables are API keys only (R2, GitHub OAuth, Resend).
- **Builder copy (every string a builder can see):** short, money first, tables or tight lists; no emojis; never "coin", "vault" or "Clanker"; never an em dash anywhere (builder text, agent text, pages, docs, program files); never a tool, field or file name.
- **UX rule:** the token is the only skippable step. "skip" appears in builder text only inside a token offer. No reply asks the builder to skip anything else.
- **"40%" appears once per entry flow:** at whichever token offer the builder answers (the first reply's or the confirmation's). A second offer in the same flow names the token without the figure.
- **The split stays:** builder 40%, Safe 30%, builder bonus 20%, MINI 10% (`policy.ts FEE_SPLIT_BPS` unchanged). No bonus pool seeding, no EarnKit-funded campaign, no change to the public /programs pages, no shareable or stakeholder pages.
- **Facts only.** Program facts come from the program's source; chain RPC defaults come from each chain's official docs (left unset when the docs state none). Never invent one.
- **Revenue:** `fee_claims` is an ops log, never revenue. `fees_to_safe_eth` in `/api/stats` is unchanged. Creator and MINI claims are never added to any revenue figure.
- **Schema:** every `db/schema.sql` change is idempotent and additive (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`). Never rename or drop a column (`installations.fit_chains` stays, unused). No data backfill. Each task that touches the schema adds its block to `scripts/db-check.mts` (tables exist, defaults, a second run of `schema.sql` survives).
- **Unchanged rules:** the bonus eligibility SQL, one token per repo, the 48 h review, sponsor campaigns dormant, Campaign #1 closed, `bonusOn`, the ordering rule (the submit kit only after the confirmation step).
- **Branch:** `v2.9-needed`, from the v2.8.1 head (`v2.8.1-friction` d55a976, or `origin/main` once v2.8.1 is merged), in a new worktree (superpowers:using-git-worktrees). Never push, merge or deploy without the owner's go. Never deploy the Worker.
- **Commands** (repo root):
  - one file: `pnpm exec tsx --test apps/frontend/lib/earnkit/<file>.test.ts`;
  - DB-gated tests (skip without it, local Postgres only): prefix `DATABASE_URL=<local Postgres>`;
  - Worker: `pnpm exec tsx --test "infra/host-worker/src/**/*.test.ts"`;
  - all: `pnpm -s test` (T7 extends the root `test` script to include the Worker glob);
  - typecheck: `pnpm -C apps/frontend exec tsc --noEmit`; lint: `pnpm lint`;
  - `pnpm -s programs:check`; `DATABASE_URL=<local> pnpm db:check`;
  - build: `DATABASE_URL=<local> pnpm -C apps/frontend build`.

## Plan Rulings (spec gaps)

- **Ruling 1, the 6-signal score's inputs.** `active`: a commit by the builder (author = `github_user`) in the last 90 days, one `GET /repos/{r}/commits?author=<user>&since=<now-90d>&per_page=1` per scored repo; for a local repo, `last_commit_at` within 90 days. `young`: `created_at` within 365 days, or `active`. `original`: not `fork`, not `is_template`, no `template_repository`, and name, description and topics don't match `TUTORIAL` (Ruling text in T2). `readme`: a root README of at least 1,536 bytes (tree size, free) whose first 2 KB (one raw fetch) is not a framework default (`DEFAULT_README`). `deployed`: the live link passes the probe, or a contract address found in the files matching already read has code on a detected mainnet. `owned`: `ownerOk`. A local repo has `readme: false` (EarnKit never reads it) and `owned: true` unless its GitHub `url` names another owner than a known `github_user`.
- **Ruling 2, where a GitHub repo and a local report meet.** One key, `repoKey(url)` = lowercased `owner/repo` (`campaigns.ts normalizeRepoUrl` minus the scheme), else `name:<lowercased trimmed name>`. GitHub facts win; the local report only adds a live link or chains GitHub lacks, and those count as claims (Task 3).
- **Ruling 3, `tell_earnkit`'s inputs.** `program_status: [{ program_id, status, project_id?, prize_usd? }]` and `repo_facts: [{ repo, mainnet_chains?, testnet_chains?, live_url?, has_users?, not_mine? }]` (the audit's schema), plus `weekly_email: { answer, email? }` from Task 10. `won`, `placed` and `lost` are self-reports (`lost` is stored as `not_selected`), keyed by `project_id`, else the installation's newest entry in that program; neither found is a plain error. `applied` stores the program's current round label (`roundLabel(program)` = `<starts_at ISO or ''>|<ends_at ISO or ''>`), so it lapses when the program's window changes or its `opened_at` is later than the statement.
- **Ruling 4, `match_floor` and `match_precision`.** Additive `programs` columns written only by `programs:sync`, so `upsertProgram` never touches them. A new column `projects.product_score` holds the entry repo's score at confirmation (from the repo-facts cache; null when unknown, then it never counts toward a floor).
- **Ruling 5, the sign-in nonce.** Table `github_verify_nonces`; the raw nonce (32 random bytes, base64url) is only in the link; the row keeps `sha256(nonce)`. Bound to `(installation_id, project_id, repo_key, purpose)` where `purpose` is `entry`, `pickup` or `host`; a `pickup` nonce has no `project_id`. Consumed by the callback with one atomic `UPDATE ... WHERE used_at IS NULL AND expires_at > now() RETURNING`. The scopeless GitHub token is used for at most three reads and never stored or logged.
- **Ruling 6, `github_verifications` columns.** The spec's `(repo_key, login, project_id, verified_at)` plus `installation_id` (pickup and hosting need it without an entry) and `account_created_at`, `public_repos` (the hosting gate, read from `GET /user` in the same callback). Additive.
- **Ruling 7, the `__Host-` cookie rule.** EarnKit sets no cookie today (the OAuth flows are stateless; the sign-in's state is the nonce). The rule becomes a test: no response EarnKit's code builds has a `Set-Cookie` without the `__Host-` prefix, and `next.config.ts` keeps HSTS without `includeSubDomains`.
- **Ruling 8, how an agent gets an upload URL with no new tool.** `prepare_submission` takes `host: true` (the builder has no live link and the project builds to static files). The reply carries `host`: the sign-in link when this installation has no passing GitHub verification for the repo; `{ unavailable: <plain reason> }` when the gate, the limits or a disabled feature say no; else `{ upload_url, expires_at }` (one-time, 15 minutes). `upload_url` is `https://earnkit.com/api/host/upload?t=<token>`.
- **Ruling 9, the kill switch and the end page.** R2 holds `sites/<slug>/<path>` and one state object `state/<slug>.json` (`{ "status": "live" | "review" | "killed" | "ended", "login": "<github login>" }`). The Worker reads the state on a cache miss only; responses cache 300 s, so a takedown shows within 5 minutes. `review` and `killed` serve the taken-down page, `ended` the "This site has ended" page, both 410 with the same headers.
- **Ruling 10, the expiry of a site.** `expires_at` = the latest `ends_at` among the programs the site's repo entered, plus 7 days. A rolling entered program (no `ends_at`) that is still active keeps `expires_at` null; once every entered program is ended or closed, the hourly cron sets it to `now + 7 days` once. No entry: upload time plus 7 days. Recomputed on every deploy and every time `confirm_entry` or `record_submission` records an entry for that repo.
- **Ruling 11, the abuse badge.** Injected at upload into every `.html` file just before `</body>` (appended when there is none): `Built with EarnKit by @alice. Report abuse.` with links to `https://earnkit.com`, `https://github.com/alice` and `mailto:abuse@earnkit.com?subject=<slug>`. Inline styles only (the Worker's CSP is not a style policy).
- **Ruling 12, the token offer in the first reply.** Shown only when all hold: a fit row whose repo is owned and product tier, status `likely` or `after_step` with effort of hours or less; the program is offerable (not sponsored, not an investment, not entered, applied or not interested), its `token_policy` is not `off`; the repo has no token (`repoCoinPrograms`) and has not declined twice (`token_declines`); launches are configured (`tokenLaunchesAvailable`). The proposal comes from `proposeToken` (the existing ticker check, `ctx.tokenDeps.check` in tests). The builder's answer goes to `launch_token` with `offer: { program_id, repo_url, project_name }` and `decision`.
- **Ruling 13, where the email question goes.** Once per installation (`installations.digest_asked_at`), in the reply of the call that recorded the installation's first entry (`confirm_entry` "go" or "skip", or `record_submission`), and only while Resend is configured. The answer goes to `tell_earnkit`'s `weekly_email`. The address: the one the builder gives, else the `email` answer of that entry (kind `contact`, type `email`), except on shared clients, where no saved address is reused or shown (v2.8.1 M4): the question asks for an address and the agent passes what the builder types.
- **Ruling 14, the email's window and caps.** A subscription is due when it opted in, never unsubscribed, and `last_sent_at` is before this week's Monday 14:00 UTC, from that moment until the next Monday 14:00. Over the day's cap, the rest wait for later runs (the same day after midnight UTC, or the next day). The cap counter is taken before each send; a failed send is not retried that run and keeps its slot (never over the cap). An empty digest sets `last_considered_at` and is not sent.
- **Ruling 15, the one money figure.** `openMoneyUsd(programs)` sums `max_award_usd` of open, curated, non-campaign programs (sponsor-sourced ones excluded, investments included, as the spec's "$1.1M+" over today's catalogue: 1,000,000 + 100,000 + 30,000 + 25,000 + 10,000 + 5,000 + 500 = $1,170,500 shows as "$1.1M+"). `moneyText(usd)` rounds down with `+` when rounding dropped value. The with-repo first reply uses the same function over the matched rows the builder qualifies for. `/api/stats` returns `open_money_usd` and the new `open_money_text`; `open_pools_usd` and `open_pools_plus` are removed (docs.earnkit.com switches to `open_money_text`: owner go-live step before the deploy). `pool.ts openFigure` is deleted; pool lines on cards stay (per-program facts, not a total).
- **Ruling 16, the legal merge.** `/terms` renders three sections from components moved out of the old pages, with anchors `#policy`, `#risk-disclosure`, `#sponsor-terms`. `next.config.ts` `redirects()` sends `/policy`, `/risk-disclosure`, `/sponsor-terms` to `/terms#<anchor>` with `statusCode: 301` (Next's `permanent: true` would be 308). Every internal link to the old paths moves to `/terms#<anchor>`.
- **Ruling 17, the MINI fallback recipient.** `policy.ts MINI_FEE_RECIPIENT` is set only after the implementer confirms, read-only (`cast call <locker> "tokenRewards(address)" <a launched EarnKit token>` against `https://mainnet.base.org`), that slot 2 of a real EarnKit token is that address (tokens.fun's buyback wallet, expected `0x6DCeEAFA8b06977e5bD2F2D9B0cF949f640f47D1`). If it can't be confirmed, the constant is `null` and a token whose locker read fails gets no MINI claim (logged once per run). Slots per tokens.fun `lib/fees/recipients.ts`: 0 Safe, 1 creator, 2 MINI buyback, 3 builder bonus.
- **Ruling 18, chain RPCs.** `rpcFor(chain)` reads `BASE_RPC_URL`, `ARC_RPC_URL`, `MONAD_RPC_URL`, `TEMPO_RPC_URL`, `AVALANCHE_RPC_URL`, `ROBINHOOD_RPC_URL`, else a public default the implementer copies from each chain's official docs (WebFetch, link in a comment). A chain whose docs state no public mainnet RPC has no default; its contract checks read "couldn't check" (never a pass), so `needs_contract` stays unmet until the owner sets the variable.

## Review Focus

1. **A builder whose repos are clones, forks, templates or EarnKit's kits** (GitHub user with `earnkitai/chain-kits` in the commit search, a fork with commits, a "todo-app" tutorial, plus a local remote `github.com/earnkitai/starter-agent-service`). Expected: no row, no `matches` entry, no token offer, no `fit_repos` entry, and the reply says none of their repos fits. Owned by T2 (test 2.9).
2. **The sign-in link used the wrong way:** opened twice, opened after 15 minutes, completed by a GitHub account that can't push, or replayed with another repo in the query; and two builders on one shared Grok Bot installation. Expected: one verification at most per nonce, only for its own entry and repo; the second builder's entry never inherits the first's proof. Owned by T5 (tests 5.3 to 5.6).
3. **A hostile or sloppy zip:** `../` or absolute paths, backslashes, a symlink entry, a bomb (small zip, declared or real size over the cap), duplicate names, `INDEX.HTML`, and a site wrapped in one top folder (`dist/index.html`). Expected: traversal and links refused; inflation stops at the cap without reading the rest; the single top folder is stripped; names are case-preserved but extensions checked case-insensitively. Owned by T8 (tests 8.2, 8.3).
4. **Probes and RPCs that hang, 429 or 5xx during `list_programs`.** Expected: the reply still comes within the matching budget, the link reads as unverified (never a tool error), the failure is cached 1 hour only, and the budget (5 probes, 6 getCode) is never exceeded even with 8 repos. Owned by T1 (tests 1.6, 1.7) and T2 (test 2.8).
5. **The weekly email under concurrency and provider errors:** two cron runs in the same hour, Resend 429 or 500, the day cap reached mid-run. Expected: never two emails to one subscription in a week, never over 100 a day or 3,000 a month, a failed send keeps its slot and waits for the next run. Owned by T10 (tests 10.5, 10.6).

export function applyBuilderFacts(f: RepoFacts, said: SaidRepo | undefined): (RepoFacts & { claims: Claim[] }) | null {
  if (!said) return { ...f, claims: [] };
  if (said.not_mine) return null;
  const chains: Detection = structuredClone(f.chains);
  const claims = new Set<Claim>();
  for (const c of said.testnet) chains[c] = { mainnet: false, testnet: true, evidence: chains[c]?.evidence ?? 'the builder said testnet only' };
  for (const c of said.mainnet) {
    if (said.testnet.includes(c) || chains[c]?.mainnet) continue;
    chains[c] = { mainnet: true, testnet: chains[c]?.testnet ?? false, evidence: 'the builder said mainnet' };
    claims.add('mainnet');
  }
  let homepage = f.homepage;
  if (!homepage && said.live_url) {
    homepage = said.live_url;
    claims.add('live');
  }
  if (said.has_users) claims.add('users');
  return { ...f, chains, homepage, claims: [...claims] };
}

// guide.ts. v2.9 A4: a row's difficulty = max(program level, distance). Pure.
const ORDER: Level[] = ['Easy', 'Medium', 'Hard'];
const maxLevel = (...ls: Level[]) => ORDER[Math.max(...ls.map((l) => ORDER.indexOf(l)))];
export const harder = (l: Level): Level => ORDER[Math.min(2, ORDER.indexOf(l) + 1)];

export function programLevel(p: RowProgram): { level: Level; estimate: boolean } {
  let level = p.difficulty.level;
  if (p.tag === 'needs a live product') level = maxLevel(level, 'Medium');
  const counted = p.past_rounds.find((r) => r.submissions && r.winners);
  if (p.investment || (counted && counted.winners! / counted.submissions! < 0.01)) level = 'Hard';
  return { level, estimate: p.difficulty.estimate };
}

export function rowDifficulty(p: RowProgram, v: Pick<Verdict, 'missing' | 'effort'>, o: { liveVerified: boolean; hasUsersClaim: boolean }) {
  const prog = programLevel(p);
  const distance: Level = v.effort === 'weeks' ? 'Hard' : v.effort === 'hours' || v.effort === 'days' ? 'Medium' : 'Easy';
  let level = maxLevel(prog.level, distance);
  if (v.missing.includes('real_users')) level = maxLevel(level, o.liveVerified || o.hasUsersClaim ? 'Medium' : 'Hard');
  if (p.match_precision != null && p.match_precision < 0.05) level = harder(level);
  return { level, estimate: prog.estimate && level === prog.level };
}

export function alertable(p: NewProgram, repos: FitRepo[], skip: { entered: Set<string>; hidden: Set<string> }, now: Date): boolean {
  if (skip.entered.has(p.id) || skip.hidden.has(p.id)) return false;
  if (p.ends_at && p.ends_at.getTime() - now.getTime() < 3 * 86_400_000) return false;
  const facts = toProgramFacts(p); // the ProgramFacts matchRepo reads
  return repos.some((r) => {
    if (!r.product || r.product.tier === 'noise') return false;
    if ((p.any_chain || p.investment) && r.product.tier !== 'product') return false;
    const f = applyBuilderFacts(toRepoFacts(r), r.said ?? undefined);
    if (!f) return false;
    const [v] = matchRepo(f, [facts]);

    if (!close) return false;
    const row = rowDifficulty(p, v, { liveVerified: r.live_verified, hasUsersClaim: Boolean(r.said?.has_users) });
    return row.level !== 'Hard' || ((p.max_award_usd ?? 0) >= 10_000 && r.product.tier === 'product');

export async function takeFreeTier(name: keyof typeof FREE_CAPS, n: number, now = new Date()): Promise<boolean> {
  const { cap, period } = FREE_CAPS[name];

    WHERE free_tier_usage.used + ${n} <= ${cap}

const DAY = 86_400_000;
export function weekStart(now: Date): Date {
  const d = new Date(Date.UTC(now.getUTCFullYear(), now.getUTCMonth(), now.getUTCDate(), 14));
  const back = (d.getUTCDay() + 6) % 7; // days since Monday
  let start = new Date(d.getTime() - back * DAY);
  if (start > now) start = new Date(start.getTime() - 7 * DAY);
  return start;
}

export function digestDue(s: { opted_in_at: Date | null; unsubscribed_at: Date | null; last_sent_at: Date | null; last_considered_at: Date | null }, now: Date): boolean {
  if (!s.opted_in_at || s.unsubscribed_at) return false;
  const start = weekStart(now);
  if (s.last_sent_at && s.last_sent_at >= start) return false;
  return !(s.last_considered_at && s.last_considered_at >= start);
}
