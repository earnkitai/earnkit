# v3.8 E2: the no-token guard

**Approval:** Jenil, "Yes, build v3.8" (Nov 24 2026), logged in earnkitai/earnkit#159. Plan: power-user plan v3.8
section 23.3 (no token wording, ever) and the hard rule "never launch a token"; build plan row E2 and risk 7.

**Goal:** One test that fails the build if token-launch, token-offer, `$EARN` or airdrop wording comes back anywhere a
builder, an agent or a reader of the repo sees it. Before this, `site-copy.test.ts` and `pages.test.ts` banned the
word on the site and /terms only; nothing scanned README.md, integrations/**, the tool descriptions as served, or the
code that holds the replies.

**Two checks (`lib/v5/no-token.test.ts`):**

1. `LAUNCH` (launch or offer a token, token sale/drop/reward/allocation/bonus/holder/ticker, `$EARN`, airdrop,
   tokenomics, memecoin, Clanker, fee locker, trading fees) over every file under `apps/frontend/{lib,app,scripts,db}`
   (source and tests, so the frozen replies the tests pin are covered), README.md and integrations/**.
2. The bare word `token` over the text an agent or visitor reads: site copy exports, llms.txt, the server instructions
   and `tools/list` (descriptions and input schemas, through the real MCP server), README.md and integrations/**.

**Allowlist (narrow, pinned):**

- Credential phrases for check 2: OAuth, bearer, CSRF, access, refresh, form, session, GitHub, API or auth token.
  `GITHUB_TOKEN` and `TokenFi` never match the word boundary.
- `launch_token` in `old-tools.ts` (OLD_TOOLS keeps it only to refuse an old call) and `mcp-route.test.ts` (pins that
  refusal), as exact (file, match) pairs.
- Third-party data: the recorded repos (`fixtures/repos/**`) and one starter template path in `lib/v6/boilerplates.json`
  (`airdrop-card.tsx`, used to tell boilerplate from a builder's code; never shown).
- A test fails when an allowlist entry no longer matches, so stale entries get removed.

**Not scanned:** `programs/*.json` (the programs' own words; Uniswap's grant lists airdrops among things that may need
legal review) and `docs/` (history; older design docs describe the removed v2 to v4 token flow).

**Hits fixed:** one, a comment in `site-copy.test.ts` that quoted the old terms clause. No product copy, tool
description, llms.txt, README or integration text had token wording.

**Not in this PR:** the build plan's no-approval guard (to land skipped until E6). The suite skips nothing by rule, so it
lands with E6 instead. jenil.ai's own copy of this test is J1.
