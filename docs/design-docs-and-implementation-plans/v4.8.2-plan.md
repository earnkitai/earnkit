### Task 2: Closing soon in the money line (R3)

**Files:** `conversation.ts` (`moneyLine`), `bench-find.ts` (where the investor clause is chosen, `moneyFor`), and tests.

**Copy:**

`Open now: {total} in grants. Closing soon: {A} ({amountA}, {in N hours})[ and {B} ({amountB}, {in N hours})].`

- `{A}` and `{B}` are `programName` titles, soonest first.
- An investor program's amount reads `investor program, up to $1M`.
- When an amount is unknown, the parenthesis holds only the time.
- When no program qualifies, the "Closing soon" sentence is left out. When the total is 0, the first sentence is left out.

**Who qualifies:** open programs closing within 48 hours that are:
- not the reply's own program;
- not applied to, declined, parked or drafted;
- not unlisted or upcoming.

The investor-clause rule from v4.8.1 still applies: a stored path's program is excluded only when picked or past the hook. At most 2 programs are named.

### Task 3: Agent-facing program data says hours left (R4)

**Files:** `apps/frontend/lib/earnkit/tools.ts` (around 1134 and 1206, and every other program object in a tool's structured output), `programs.ts` (around 387, 513 and 744, wherever an object goes to MCP output), `deadline.ts` (`hoursLeft`), and tests.

**Behaviour:**
- Each program object in MCP tool output gains `closes_in: string | null`. It holds `hoursLeft` words under 48 hours, and is null otherwise or for rolling programs.
- Under 48 hours, `summary`'s close part (the text after ` · ` that starts with `closes`) becomes `closes {closes_in}`. For example, `500 USDC × 8 grants · closes Nov 1, 11:59 PM ET` becomes `500 USDC × 8 grants · closes in 14 hours`.
- `deadline` (ISO) stays, because agents may compute with it.
- Site pages (app/) and emails are unchanged.
- Grep every `summary:` in tool outputs and list each site in the report, changed or not, with the reason.
