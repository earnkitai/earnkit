# v6.1.5: the first run's remaining rough edges

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Close the rough edges the 2026-11-09 live first-run audit left after v6.1.3 (findings 8, 11, 13 to 17 of the audit report) and pin the v6.1.4 zero-remote case.

**Architecture:** Small, independent edits to the reply text, the track tool, the link confirm page, the landing chip and the server instructions. One schema addition (`installations.last_gaps`) so track can remember what the last find called a gap. No new tools, no new routes.

**Tech Stack:** Next.js 16 app in `apps/frontend`, Postgres via `lib/v5/db.ts` (`sql()` tagged templates), node:test with `pnpm -s tsx --test --import ./apps/frontend/lib/v5/fixtures/test-guard.ts <file>`, `export DATABASE_URL=postgresql://localhost:5432/earnkit_test`.

**Spec:** this file (the audit report lives in the session scratchpad; its findings are restated verbatim where a task needs them). `docs/design-docs-and-implementation-plans/v6-design.md` is the design behind find, track and the record.

## Global Constraints

- Builder text (`show_to_builder`, pages): no emoji, no em dash, never the words score, rank, grade, points, coin, token, streak. Every builder line ends with a full stop. Never name a tool, a field or a file in builder text.
- The first reply stays money first, gap, one action ("say yes"). Do not touch the drafted line shapes (R2c) or the closing block.
- Agent notes may name tools and fields; builder lines never do.
- Tests pinned to reply text (`reply.test.ts`, `find.test.ts`, `journey.test.ts`, `mcp.test.ts`) are updated to the new text, never deleted or loosened to regexes that would pass on the old text.
- Schema changes go in `apps/frontend/db/schema.sql` as `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` (the migrate script replays the whole file).
- Commit messages start with `v6.1.5:`.
- After the last task: `docs/codebase-context/architecture-guide.md` and `docs/codebase-context/code-map.md` describe the new column and the chip rule.

## Review Focus

1. A track `started` for a program the last find did not mention (the builder named it directly): no gap remark, the plain "Started." line.
2. A track `started` after a `find` with `filter.all`: the remark uses every gap verdict, not only the two shown.
3. An installation that never called find: `last_gaps` null, track reads it as empty.
4. The chip when every open program is an investment: null (no chip), not "$0 in grants and prizes open now".
5. The confirm page when the request origin is a preview host: the "/me" address uses that host, never a hard-coded one.

**Findings (audit 8, 13, 14, 15, 16), each with its ruling:**

- 8. The confirm page said `You can unlink it any time on your record page.` and never named EarnKit. Ruling: the page gets a first line `EarnKit` (a `<p>` above the question, same muted colour as the footnote, font-size 14px, letter-spacing 0.04em) and the sentence becomes `You can unlink it any time at {host}/me.` where `{host}` is `publicOrigin(request)` without its scheme (Review Focus 5). `confirmPage(live: Live, origin: string)`.
- 13. `, a long shot: an investment program with no stated amount` read as a label glued to the money. Ruling: the long shot leaves the head and becomes its own sentence right after the head sentence: `{n}. {title}, {money}, closes {x}. Long odds: {long_shot}.` (capital L, full stop). Nothing else in `readyLine` moves.
- 14. The no-project list (`openList`) had lines without full stops and no action for the builder. Ruling: every program line ends with a full stop (`Title, $X, closes in 3 days.`), the overflow line reads `and {n} more.`, and after the list comes the line `Tell me which project and I'll match it.`; the sign-in line (unlinked) stays last.
- 15. `/docs`: `Nothing is sent that you did not approve.` and `/terms`: `An answer your agent wrote is never sent until you approve it on /me.` hold only once signed in. Ruling: docs sentence becomes `Once you are signed in, nothing is sent that you did not approve.`; terms sentence becomes `Once you are signed in, an answer your agent wrote is never sent until you approve it on /me. Before that, your agent acts on what you tell it in the chat.`
- 16. `SERVER_INSTRUCTIONS` never mentions the sign-in link or the unlinked state and says `record and repo values as given` while fields carry `from: 'earnkit' | 'record' | 'agent' | 'builder'`. Ruling: replace `Draft every form from find's fields: record and repo values as given, approved answers fitted by cutting, never by adding.` with `Draft every form from find's fields: 'earnkit' and 'record' values as given, 'agent' values you draft from the field's sources, 'builder' values you ask the builder for once, all together; approved answers fitted by cutting, never by adding.` and append the sentence `When find's reply carries a sign-in link, show it once as the reply gives it; until the builder signs in, nothing is saved across agents.` before `Never write a sentence about traction yourself.`
