# v3.8: delete the old program approval path (land when auto_live is on for everyone)

Plan: decision 25, item 10, section 23.2. Approval: earnkitai/earnkit#159. This is the deletion half of #164 and #165,
split out by E6r (#185) and E7r (#188) so that no program add gets stuck while `auto_live` is off for normal traffic.

## Precondition to merge

`auto_live` is on in production `EARNKIT_FLAGS`, so every write takes the automated lane. Alternatively, every writer
(Jenil AI, Growth) sends the check fields. Until then, the held writes this leaves would have nobody to approve them.

## Deletes

- The approval path: `app/api/programs/approve`, `approveGet`/`approvePost`/`approveWrite`, `APPROVE_TEXT`, the signed
  approve link, `mailPending`/`pendingMailText`/`PENDING_SUBJECT`, `owner_emailed`, `MAIL_FAILED`.
  `no-approval.test.ts` is back to the full ban.
- Mail: `mail.ts`, `RESEND_API_KEY` (env allowlist, test guard). The digest email becomes `recordOwnerDigest`, so the
  cron records the day and `GET /api/programs/digest` reads it. The signed revert link and its confirm page go too;
  revert is the bearer `{ write_id }` only.
- `approval-while-off.test.ts`. Its route flag-context test (owner/test sessions take the automated lane) moves to
  `no-approval.test.ts`.

## Kept

- E6r's lane rule (`auto_live`, which main's owner/test flag preview turns on for those callers, or the check fields).
- The held lane, with no email. A held write is listed in `GET /api/programs/writes` and nothing applies it.
- `escapeHtml` in `programs-pending.ts`, which the install consent page uses.

## Source

`programs-pending.ts`, `owner-digest.ts`, `cron.ts` and their tests are #165's versions. Main has not changed those
files since #164 and #165 were cut. `programs-api.ts` is #165's version with E6r's `automatedLane` added.
