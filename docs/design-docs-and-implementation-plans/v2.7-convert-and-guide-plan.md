# v2.7 Convert and Guide: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Visitors see real open money and install; every program comes with a short guide (difficulty, what won before, what the ecosystem wants, the best bet); the first message gains a Difficulty column and closes on the builder bonus; the submit screen leads with what's missing and always proposes a token on Base; "token" replaces "coin" in every human-facing string; docs.earnkit.com is rewritten for sponsors and builders.

**Architecture:**
- **Program files carry the guide facts.** New optional fields (`logo`, `past_rounds`, `focus`, `best_bet`, `difficulty_override`, `winners_per_round`), each fact with its own `source_url`. They sync to new additive `programs` columns.
- **One pure guide module** (`lib/earnkit/guide.ts`) computes difficulty and renders the guide. `get_program`, the first message's Difficulty column, the landing cards and `/programs/<id>` all read it, so the agent and the web never disagree.
- **The web reads the existing DB server-side,** cached 10 minutes with `unstable_cache` (the `/api/stats` pattern). A failed read never breaks a page and is never baked into a static page.
- **The token step reuses `prepareSubmission`'s readiness.** Not ready: the screen leads with the missing items and has no token, wallet or footnote. Ready: a token on Base is always proposed.
- **docs.earnkit.com** (`earnkitai/earnkit-docs`, Nextra 4 on Vercel) is rewritten in its own clone, never in this repo.

**Tech Stack:** Next.js 16 (App Router), React 19, Tailwind 3, postgres.js, zod v4, node:test via `tsx --test`; the docs site uses Next.js 15 + Nextra 4 + pagefind.

**Spec:** `docs/design-docs-and-implementation-plans/v2.7-convert-and-guide.md` (approved, binding).

**Execution method (chosen by the owner):** subagent-driven. A fresh implementer works on each task, a fresh reviewer checks it before the next task starts, and a whole-branch review runs at the end.

## Plan Rulings (spec gaps)

- **Ruling 1 (plan), a program card with no logo.**
  - The card shows a monogram tile instead: the first letter of each of the title's first two words ("AM" for Arc Microgrants), in `font-funnel-display` on an `bg-ek-navy` circle the size of the logo.
  - Nothing is fetched and no third-party image is used. The guide page uses the same tile.
- **Ruling 2 (plan), odds from past rounds.**
  - `past_rounds` is ordered newest first.
  - Difficulty uses the newest round that has both `submissions` and `winners`. Odds = winners ÷ submissions.
  - Bands: Easy at 0.25 or more; Medium from 0.08 up to 0.25; Hard under 0.08. So exactly 25% is Easy and exactly 8% is Medium.
  - Basis: `20 of ~160 entries won last round` when that round is the newest; `20 of ~160 entries won in <label>` when it is an older one. The "~" always shows, because published submission counts include invalid and duplicate entries.
- **Ruling 3 (plan), past rounds with no submission counts.**
  - With no round that has both counts, difficulty is an estimate (Ruling 4), never odds.
  - Its basis names the winners the newest round does publish: `20 winners last round; entry count not published`.
  - An estimate is never "Easy": without counts, EarnKit doesn't promise good odds.
- **Ruling 4 (plan), the estimate heuristic.** A score starts at 0:
  - winners (the newest round's `winners`, else `winners_per_round`) of 20 or more: +1; 3 or fewer: −1;
  - `tag: "long shot"`: −2;
  - two or more barriers (a video in `each_time`; more than 2 required builder answers or more than one `each_time` item; "mainnet" in the rules or a requirement): +1, since barriers thin the field.

  Below 0 is Hard (estimate); otherwise Medium (estimate). With no winners known and no past round, the basis is `no past results yet`; with only `winners_per_round`, it is `<n> winners per round; no past results yet`.
- **Ruling 5 (plan), the override.** `difficulty_override` is `null` or `{ level, basis, source_url }`, with the basis as short text. When set, it wins, shows as not an estimate, and its basis is shown as written.
- **Ruling 6 (plan), `winners_per_round`.** An optional positive integer, set only when the program's own `source_url` states how many winners a round has ("Twenty microgrants"). It feeds the estimate only. It is the one new fact backed by the program's existing `source_url`.
- **Ruling 7 (plan), the ecosystem in "What <X> wants now".** `focus.ecosystem` (optional, a factual name, at most 40 characters). Without it, the heading uses the first chain's name (`CHAIN_NAMES[chains[0]]`).
- **Ruling 8 (plan), the best bet when the builder has a matching repo.**
  - EarnKit never generates or rewrites it. The web shows the curated line only.
  - `get_program` returns it verbatim, plus an agent note: "If the builder's repo fits (see eligibility), you may add one line in your own words on how their repo fits this best bet; never present it as EarnKit's."
  - `best_bet` is EarnKit's advice, not a fact, so it has no `source_url`. `programs:check` accepts it only when the file has `past_rounds` or `focus`, the facts it must be drawn from.
- **Ruling 9 (plan), guide wording.**
  - The header prize is the program summary's prize part as curated (`500 USDC × 20 grants`), never recomputed "per winner".
  - The end is `ends Oct 14` or `rolling`; a closed program says `closed`.
  - An example renders `Example: <name> — <what>; cited for <why>`. "Cited for" fits both judges and organizers.
  - Theme counts: the first theme is `(3 of 20 winners)`, later ones `(2 of 20)`; without the round's winners, `(3 winners)`, then `(2)`.
- **Ruling 10 (plan), how the first message closes.**

So the bonus sentence comes first, as its own paragraph — "Entries in the other open programs also compete for the builder bonus: …" — and the campaign offer stays the last line.

```ts
/** v2.7 §2: a short guide string, like `ideas` but 1-12 words ("FX" is one): no links, no markup. */
export const ShortText = z
  .string()
  .min(1)
  .max(100)
  .refine((s) => !/https?:\/\/|www\./i.test(s), 'no links')
  .refine((s) => {
    const n = s.trim().split(/\s+/).filter(Boolean).length;
    return n >= 1 && n <= 12;
  }, 'must be 1 to 12 words');

/**
 * v2.7 Ruling 23 (plan): why a program logo file can't be served, or null. Logos render only via
 * <img>, but a file that would run script if opened directly is refused anyway. Pure.
 */
export function logoFileProblem(path: string, bytes: Buffer | null): string | null {
  if (bytes === null) return `logo.path: ${path} not found under apps/frontend/public`;
  if (bytes.length > 200_000) return `logo.path: ${path} is over 200 KB`;
  if (path.endsWith('.png'))
```

```ts
/** "tip jar" from a GitHub repo link (dashes, underscores and dots as spaces), or null. Pure. */
export function repoNameOf(repoUrl: string | undefined): string | null {
  const m = repoUrl ? /^https:\/\/github\.com\/[^/]+\/([^/?#]+)/i.exec(repoUrl.trim()) : null;
  const name = m ? m[1].replace(/\.git$/i, '').replace(/[-_.]+/g, ' ').trim() : '';
  return name || null;
}

/** The first letters of the name's words (else its first 3 letters, padded with X), then 2-9 variants. Pure. */
export function initialsCandidates(name: string): string[] {
  const words = name.toUpperCase().split(/[^A-Z0-9]+/).filter(Boolean);
  if (words.length === 0) return [];
  const initials = words.map((w) => w[0]).join('');
  const base = (initials.length >= 3 ? initials : words.join('').slice(0, 3).padEnd(3, 'X')).slice(0, 6);
  return [base, ...[2, 3, 4, 5, 6, 7, 8, 9].map((d) => `${base.slice(0, 5)}${d}`)];
}

export async function proposeToken(projectName: string, check: TickerCheck = tokensFunTickerCheck, repoUrl?: string): Promise<Proposal> {
  const trimmed = projectName.trim().slice(0, 50);

  const candidates = [...new Set([
    ...tickerCandidates(trimmed), ...(repo ? tickerCandidates(repo) : []),
    ...initialsCandidates(trimmed), ...(repo ? initialsCandidates(repo) : []), ...LAST_RESORT,
  ])].filter((c) => !tickerProblem(c));
  let symbol: string | null = null;
  let note: string | undefined;
  for (const [i, c] of candidates.entries()) {
    if (i === MAX_CHECKS) { symbol = c; note = 'ticker not checked for duplicates'; break; }
    const free = await check(c);
    if (free === null) { symbol = c; note = 'ticker not checked for duplicates'; break; }
    if (free) { symbol = c; break; }
  }
  // Every candidate was checked and taken (a list shorter than MAX_CHECKS): propose the last one anyway.
  if (symbol === null) { symbol = candidates[candidates.length - 1]; note = 'ticker not checked for duplicates'; }
  const named = [trimmed, `${trimmed.slice(0, 44)} Token`, repo ?? '', `${symbol} Token`]
    .map((n) => (n.trim() ? cleanTokenName(n) : { problem: 'empty' }))
    .find((r): r is { name: string } => 'name' in r);
  return { name: named!.name, symbol, ...(note && { note }) };
```
