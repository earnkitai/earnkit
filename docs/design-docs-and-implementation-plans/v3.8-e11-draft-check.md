# v3.8 E11: draft check and draft storage

Plan: v3.8 item 7, cutover A8. Approval: earnkitai/earnkit#159. Stacked on E10 (`v38/e10-track-import`), only for a
linear stack: it does not need E10's code; it shares track.ts's flag-gated argument handling with E8/E9. Flag:
`draft_check`.

## Check (lib/v6/draft-check.ts, pure, no LLM)

`checkDraft(program, fields, record, { proof_links, now })` lists:
- `missing` (a required non-file field empty), `too_long` (`max_chars`), `too_many_words` (`guidance.limit_words`),
  `unknown_field` (not a form key);
- `unsupported_number` / `unsupported_link`: every number and link in the draft must be in the record (any leaf), the
  given proof links, or the program's own title, reward, summary and links;
- `filler`: a fixed phrase list plus em dashes (the style contract);
- `program_not_named`: none of the program's title, short title, organizer, chains or preferred integrations appears;
- `never_claim`: a phrase from the new `policy.never_claim` record list.
Traction: each supported number is `verified` when EarnKit's own usage line (`projects[].last_tier.usage`, written from
public evidence) holds it, else `builder_stated`. `hash` is sha256 of the fields (keys sorted, values trimmed).

Honest limit: it catches unsupported numbers and links, length and listed phrases. It cannot tell whether prose is
true, and a number that appears anywhere in the record counts as supported wherever it is used.

## Storage and gate (lib/v6/drafts.ts, track)

- `track action: check { program_id, fields, proof_links? }` runs the check and stores `draft_text` and `draft_check`
  on the builder's newest unsent (`started`) row for the program; with no such row it answers and stores nothing.
- An agent's `applied` (submitted_by agent or omitted) on a catalog program needs `final` (the fields as sent): refused
  with no stored check, a failing one, or a `final` whose hash is not the checked draft's. On success `final_hash` is
  stored on the sent row. The builder's own send is not gated (their text, their tap); private rows are builder-only.

## Schema

`applications.draft_text jsonb`, `draft_check jsonb`, `final_hash text`: additive, nullable, no backfill.
`policy.never_claim` is optional in the record (jsonb), so EMPTY_RECORD is unchanged.
