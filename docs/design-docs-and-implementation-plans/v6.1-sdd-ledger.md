## Controller rulings (overridable by the owner)

1. The record type is `BuilderRecord` (never shadows TypeScript's `Record`).
2. Task 3 owns `getRecord` and `saveRecord` on `builders.ts`, and `projects[].last_tier`.
3. `code-signals.ts` split out of `repo-facts.ts` to break an import cycle (program-file, integrations, repo-facts).
4. `reviewers_contact` is not writable through the programs write API.
5. An installation already linked to one builder is never re-linked to another: the callback refuses with one line; the legacy primary keys on `applications` and `gaps_done` were dropped for the owner key.
6. The link flow is bound to the browser: GET `/link/<code>` is a confirm page; its POST sets an `ek_link` nonce cookie bound into the signed state; the callback requires both. `Referrer-Policy: same-origin` (no-referrer made browsers send `Origin: null`).
7. A link code is HMAC-derived from a stored nonce, so a live link is reused by later record calls while only hashes sit in the table. Both checks require `expires_at > now`.
8. `policy` (standing approval) is builder-only; an agent patch naming it is dropped with a problem line. `written_by` is forced for agent writes. Record writes run inside `withRecord` (row lock). An unparseable stored record is never overwritten.
9. A builder's own edit keeps an approval; an agent write to an approvable path drops it; on /me an approval is bound to the text seen (`seen` = the path's `set_at`), refused with "This text changed since you opened the page. Read it again." when it moved.
10. Claims are per owner and program, taken under an advisory lock with a conditional upsert; a skip replaces a claim and a claim refuses over a skip; `track unskip` deletes the skip.
11. `applications.auto_applied` is set only for `submitted_by = 'agent'` under `policy.auto_apply`; the find heading reads "Applied under your standing approval".
12. Reviewers: `github_id` wins; an ambiguous login is refused. The daily screen limit is an atomic hit. A budget stop requeues the applicant (exact note match, cap 10); a retryable null tier requeues up to 3 attempts. A triggered cron run works only its job. `SCREEN_DAILY_MS` is 300 s (the workflow's curl allows 540 s).
13. `/me` without a session answers a real 302 to `/docs#record` (Next proxy). csrf is an HMAC of `me-csrf:<builderId>:<day>`, valid today or yesterday. Edits reach only the fields the page lists; `policy.*` only through `/me/policy` except the skip list. The `?problem=` line is signed. Labels are builder words, never a record path.

## Parked (minor, for a later version)

- Stale repo cache rows read `integrations: []` for up to 7 days.
- A rotated `EARNKIT_AUTH_SECRET` leaves a live link row dead for up to 15 minutes; a reused code keeps its original expiry.
- `taken_at` is the run's start time (a take-over window of 21 rather than 30 minutes in a long triggered run); shared-contributor counts are not revised for applicants read earlier; the "others" query is O(n squared) per job.
- Origin is compared to one host; the `?problem=` signature is not bound to a builder or a time (the text is limited to handler-produced lines).
- `/me` cannot remove a project (fields can be cleared); written into the architecture guide's "Not in v6.1".
- No dedicated test for the program id shown in the Applications card (the pages render test covers it indirectly).
- `record_updated_at` is bumped by EarnKit's own writes; nothing may read it as a builder edit.
