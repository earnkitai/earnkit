- Schema: `ALTER TABLE applications ADD COLUMN IF NOT EXISTS sent_by_installation_id bigint;` backfilled once from the newest `application_history` row with status `applied` for the same owner, program and project (`COALESCE(project_id, '')`); `sent_at` backfilled for rows with a SENT status and `sent_at IS NULL` from the newest `applied` history row whose note is not `sent by the builder outside EarnKit` (an outside win keeps null). - `sendTime(db): Fragment` = `CASE WHEN a.sent_at IS NOT NULL THEN a.sent_at WHEN COALESCE(a.submitted_by, 'agent') = 'agent' THEN a.at END` (a builder row with no send time, an outside win, has none; an agent row from before v6.1.9 keeps its own time, as `applicationsOf` reads it at ledger.ts:773).
- `sendRows` selects `${sendTime(db)} AS sent_time` (null for an undated row). `throughEarnkit`: `h.status = 'started'` only (L42-5: a hold is not an EarnKit start).
- `readStats`: `sent_week` = `status = ANY(SENT) AND sent_time >= week` over `sendRows` (L42-1); `applications` (all time) unchanged.
- `programsApiOn`: the token is `env.EARNKIT_PROGRAMS_TOKEN?.trim()`; `secretMatches(given, secret)` compares against `secret.trim()` and its length rule reads the trimmed secret (L42-3; every caller of `secretMatches` and `bearerMatches`, the cron secret too, gets the trim).
- `parseSince(text: string): Date | null` (pure, exported): accepts `YYYY-MM-DD` or `YYYY-MM-DDTHH:MM[:SS[.fff]]` with optional `Z` or `±HH:MM`; no zone is UTC (L42-8, M7); the date and clock parts must round-trip (`Date.UTC(y, m - 1, d, hh, mm, ss)` gives back the same y, m, d, hh, mm), so `2026-02-30` and `T24:00` are null (L42-4). Null answers 400 `since: an ISO date`.
- `applicationsGet` rows: ordered `sent_time DESC NULLS LAST, at DESC, application_id DESC`; `sent_at` is `sent_time` (null for an undated row); a row gains `reported: boolean` (`submitted_by = 'builder'` and not through EarnKit, the totals' `reported`); `submitted_by` is `r.submitted_by ?? 'agent'` (L42-9, the stored null stays); `agent` is the client name of `COALESCE(a.sent_by_installation_id, a.installation_id)` (L42-6). With `since`, a dated row is kept when `sent_time >= since`, an undated one when its `at >= since` (it has no other date and is never lost).
- `ledger.record`: both applied inserts set `sent_by_installation_id = installationId`; the `ON CONFLICT ... DO UPDATE` of the applied path sets it from EXCLUDED; no result, skip, correction or win path writes it (L42-6). A result never writes `sent_at` (already true; pinned).
- Digest (L42-7, L42-10): the block's first line is `{sent} sent yesterday: {agent} by agents, {drafted} drafted here, {reported} from outside. {total} to date.` with `total` = dated sends with `sent_time < dayStart` (through the end of yesterday); the `- {title} ({id}): {k}` lines stay; zero sends adds nothing. Undated rows count in neither number.
