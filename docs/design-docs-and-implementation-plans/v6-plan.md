# EarnKit v6.0: the evidence reader, named tiers and the pilot script. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read a project's public evidence (site, chain, code, team, ecosystem depth) into labelled rows, place it in one of five named tiers with the rule that put it there, and run that over a program's applicant list from a script that writes the sorted report for the two pilots.

**Architecture:** New modules in `apps/frontend/lib/v6/`, each one source of rows (`live.ts`, `onchain.ts`, `code.ts`, `team.ts`, `depth.ts`) behind one assembler (`evidence.ts`) that caches per repo and contract in a new `evidence_cache` table, and one pure `tiers.ts`. The v5 modules are reused where they fit (`github.ts` for API calls, `safe-fetch.ts` for the site probe, `chains.ts` for the registry, `repo-facts.ts` `detectCode` and `repoKey`) and never changed in behavior. No route, no MCP change, no v4 import: v6.0 ships as a script, `pnpm screen`, plus the library the v6.1 tools will call. Every outside read is injectable and tests replay recorded responses, as v5's `fixtures/github.ts` does.

**Tech Stack:** TypeScript, node:test with the per-file test database, postgres.js, zod 4, Etherscan v2 multichain API (`https://api.etherscan.io/v2/api?chainid=...`), Arc Blockscout API v2 (`https://explorer.arc.io/api/v2/...`), GitHub REST, RDAP (`https://rdap.org/domain/<domain>`). No LLM, no new dependency.

**Spec:** `docs/design-docs-and-implementation-plans/v6-design.md` (approved 2026-11-06), sections 7 and 11 for v6.0. SDD ledger: `v6-sdd-ledger.md` beside it.

## Global Constraints

- Branch `v6-the-filter` in worktree `~/ek-v5`, from `origin/main` 5ef29261. One PR for v6.0.
- Tests: `export DATABASE_URL=postgresql://localhost:5432/earnkit_test`; one file: `cd ~/ek-v5 && pnpm -s tsx --test --import ./apps/frontend/lib/v5/fixtures/test-guard.ts apps/frontend/lib/v6/<file>.test.ts`; the suite: `pnpm -s test` (its glob gains `lib/v6`). Never claim a pass without the output. The guard refuses every non-local host: every test injects its fetch.
- `pnpm -s build:frontend` passes at the end of every task.
- Env: the v5 set plus `ETHERSCAN_API_KEY` (added to `ENV_ALLOWED` in `lib/v5/no-v4.test.ts`). Without it the Etherscan client throws `ExplorerError('no key')` and the rows it would fill carry `note: 'not read: no explorer key'`.
- No LLM, no new service, no new dependency, no cron change.
- Copy rules on every string a builder or reviewer may see: no emoji, no em dash, never "score", "rank", "grade", "points", "coin", "token", "streak"; tiers are the words `used`, `live`, `building`, `unverified`, `flagged` and nothing else.
- Every row is a fact with a basis and a read time; no row is an opinion. A failed read is a row with `value: null` and a `note` saying why, never a thrown error out of `readEvidence`.
- Every module in `lib/v6/` has a header comment of at most 6 lines. No version history in comments.
- Budget: a reader stops and marks the rest `not read: budget` when GitHub's `x-ratelimit-remaining` is under 500 or when an explorer answers 429 twice.

Not in v6.0 (v6.1): `xp.applications_90d`, program-reported outcomes, `record` rows, the `screen` tool and its queue, `/me`, GitHub sign-in, the catalog fields. The script computes the cross-applicant counts (identical pitches, shared contributors) inside one list only.

## Review Focus

1. An applicant with no repo, a working site and no contract must land in `live`, not `unverified`, and must not crash any reader (Task 4 test `site only is live`).
2. A contract address that Etherscan does not know (unverified source, or a wallet) must produce `verified_source: false` rows and no exception, and must not count as mainnet usage (Task 1 test `unknown address is not usage`).
3. A fork of a starter with real work after the fork (own share over 0.2) must not be flagged (Task 2 test `fork with own work is not flagged`).
4. A GitHub 403 with `x-ratelimit-remaining: 0` mid-read must leave the rows already read intact and mark the rest `not read: budget`, never cache the partial result (Task 3 test `budget stop keeps what was read and does not cache`).
5. A CSV row with a non-GitHub repo link, a `github.com/<user>` link without a repo, or an address with the wrong length must be reported as unverified with the reason, and the script must finish the rest of the list (Task 5 test `bad rows do not stop the run`).

- Produces `applicants.ts`: `type Applicant = { ref: string; name: string; repo_url: string | null; live_url: string | null; contracts: { chain: string; address: string }[]; pitch: string | null; problems: string[] }`; `parseApplicants(csv: string): Applicant[]` (header row required; recognized columns by case-insensitive name: `ref|id`, `name|project`, `repo|github|repo_url`, `url|website|live_url|site`, `contract|contracts|address` (comma or space separated `chain:0x...` pairs, or bare `0x...` taken as the program's chain passed to the script), `pitch|description|summary`; a non-github repo link, a `github.com/<user>` link, an address not 40 hex characters, an unknown chain slug each add a `problems` line and null the field); `resolveRepo(a: Applicant, live: LiveRows): string | null` (the first `github_links` entry that is a repo when `repo_url` is null); `identicalPitches(apps: Applicant[]): Map<string, number>` (ref to the count of other applicants whose normalized pitch (lowercase, whitespace collapsed, punctuation dropped) shares at least 90 percent of its 5-word shingles); `sharedContributors(logins: Map<string, string[]>): Map<string, number>` (ref to the count of other applicants sharing at least one login).
- Produces `screen-report.ts`: `type ScreenRow = { applicant: Applicant; evidence: Evidence | null; placement: Placement; line: string }`; `markdownReport(program: string, rows: ScreenRow[], now: Date): string` (totals per tier, then one section per tier in the order used, live, building, flagged, unverified, each applicant with its line, its `because` rows, flags and problems; a closing section "What EarnKit could not read" listing budget and key notes), `csvReport(rows: ScreenRow[]): string` (one row per applicant: ref, name, tier, flags, funded_senders_90d, senders_90d, chains_mainnet, last_push_at, contributors_90d, template_name, template_overlap, own_share, url_ok, line, problems).
- Produces `scripts/screen.mts`: `pnpm screen <csv> --program <id> [--chain base] [--out <dir>] [--no-cache] [--thresholds <json>]`; `export async function run(args, deps)` so the test drives it with fakes; writes `<out>/<program>-<date>.md` and `.csv` (default out: the scratchpad path printed at start, or `--out`); prints per-tier totals and the reads used; exits non-zero only when the CSV cannot be parsed at all.
- `docs/screening-pilot.md`: what the pilot is, the CSV columns, the command, what each tier means, what is read and what is never read, the message to send a program, and that results are private to the program.
