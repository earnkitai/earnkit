# v2.12.1 acceptance runbook

This is the one place the production test is written out. The rules it tests are the spec's
"Acceptance test (binding)" section; the order it sits in is the spec's "Owner go-live steps" (this
runbook is steps 7 to 9 in detail). If this file and those disagree, fix this file.

Words used here:
- **Environment**: where the flag goes on. `earnkit-staging` (Railway) if it is set up, else production
  for the test window only (go-live step 8). Write its address as `BASE`, for example
  `BASE=https://earnkit.com`. On staging, `EARNKIT_URL` must equal `BASE` (EarnKit builds the claim
  page's form and the X `redirect_uri` from it, so the `--handoff` check fails otherwise), and the X
  developer app must list `$BASE/x/callback` as a callback.
- **Controller**: the Claude session that runs the scripts. **Owner**: you, with your X login.
- **Flag**: `EARNKIT_BUILDER_SCORE` on the frontend service in Railway.
- The scripts never write to your profile or score. The check script is GET only (its one optional
  POST is the claim button, section D step 5). The metric script runs inside one READ ONLY transaction.

## Owner only (the steps nobody else can do)

Everything else is the controller's. These need you, and all of them work from a phone:
1. Section A: confirm go-live steps 1 to 7 are done and the four Railway variables are set.
2. Section C: set `EARNKIT_BUILDER_SCORE=on` in Railway, redeploy, refresh the EarnKit connector.
3. Section E: in your own agent, ask, tap the claim link, sign in with X, say yes to one step, open
   your page. After every reply, copy the whole reply and paste it into your chat with the controller.
   No file is needed: the controller saves it and runs the check on it.
4. Section F: the same with the fresh target-user account.
5. Section G, only if the controller says "fail, flag off": unset `EARNKIT_BUILDER_SCORE` and redeploy.

Commands run from the repo root:
- Check: `pnpm exec tsx --tsconfig apps/frontend/tsconfig.json apps/frontend/scripts/v2121-prod-check.mts --base $BASE [--flag off] [--reply <file>] [--exempt "<name>"] [--handoff]`
- Metric: `DATABASE_URL=<read-only url of the environment> pnpm exec tsx apps/frontend/scripts/v2121-metric.mts --days 1`

Both exit 0 when everything passes and print one PASS or FAIL line per check.

## A. Before the test (owner)

1. Go-live steps 1 to 4 are done: lawyer review, the X developer app (console.x.com, verified phone,
   credits, callback `https://earnkit.com/x/callback`, `X_CLIENT_ID` and `X_CLIENT_SECRET` in
   Railway), the `earnkit` builder code, hosting.
2. Go-live step 6 is done: you signed off the screenshots of the page, card, leaderboard, claim, done
   and wallet pages.
3. The branch is merged and deployed with `EARNKIT_BUILDER_SCORE` unset (step 7). The deploy ran
   `pnpm db:migrate` and `pnpm programs:sync` (`predeploy`).
4. In Railway, on the environment, these are set: `EARNKIT_EVENT_LOG=on`, `EARNKIT_AUTH_SECRET`,
   `GITHUB_TOKEN`, `X_CLIENT_ID`, `X_CLIENT_SECRET`.

Only you can make the X developer app and only you can log in with X. The controller cannot test a
real X login, and nothing here needs a test X app.

Pass: all four are true. Otherwise stop and finish go-live steps 1 to 7.

## B. With the flag still off (controller)

1. Open a fresh connection to EarnKit (section D step 1) and ask "What can I earn?". Save the reply to
   `off.txt`.
2. Run the check: `... --base $BASE --flag off --reply off.txt`.
3. Open the latest run of the "EarnKit cron" workflow in GitHub Actions (or
   `gh run view --log <id>`) and read the JSON it printed.

Pass:
- The check prints PASS for: the reply has no "Where you stand", "Ways to earn right now" or "How to
  move up" (it is the v2.11 reply); `/leaderboard`, `/claim/x`, `/x/callback` and `/lee` are 404; a
  random name is 404.
- The cron JSON has no `builder_score` key.

Fail: the flag is on already or the deploy is wrong. Stop and fix before C.

## C. Turn it on (owner)

1. In Railway on the environment, set `EARNKIT_BUILDER_SCORE=on` and redeploy.
2. Refresh the EarnKit connector in claude.ai (and in each agent you use). The `find` tool now has
   `identity`; the `tell` tool has `move_up` and `coin`.

Pass: the deploy is live and the connector shows the refreshed tools. From here, if any check in D to F
fails, go to G at once.

## D. With the flag on, no X login needed (controller)

A fresh installation shaped like the target user: a few small apps, little GitHub, no traction.

1. Use a scratch `HOME` (so nothing of yours is reused) and add EarnKit:
   `claude mcp add --transport http earnkit $BASE/mcp`. Sign in through the connector's own OAuth.
2. Make a folder with two small public projects of a throwaway GitHub account (a fresh account, not
   yours). Open the agent in that folder and ask: "What can I earn?". Note how long the call takes
   (the agent's tool timing). Save the reply to `reply.txt`.
3. Run: `... --base $BASE --reply reply.txt --exempt "<each of the two project names>" --exempt "<each program title in the reply>" --handoff`
4. Pass lines (every one must read PASS):
   - `reply`: the three headings in this order, "Where you stand", "Ways to earn right now", "How to
     move up"; at most one question; no banned word (outcome, percentile, verified source, contract,
     wallet address, builder code, repo, commit, onchain, a chain name the builder did not say first,
     any all-caps label, any em dash, any emoji); no v2.12 line (no "You:" line, no "score", no
     `/b/` link); no period right after a link.
   - The reply has a claim link (`earnkit.com/claim/<12 letters>`), and the call was answered within 10 seconds.
   - `GET /claim/<code>`: 200; it says what is public, how to hide the page ("hide my page") and has
     the "Continue with X" button.
   - `claim button hands off to X (not followed)`: 303 to `https://x.com/i/oauth2/authorize` with
     `code_challenge_method=S256` and `redirect_uri=$BASE/x/callback`. The script never follows it.
     This POST makes EarnKit store a sign-in state for 15 minutes; it claims nothing.
   - `GET /leaderboard`: 200 and one plain list (no filter markup); `GET /terms`: 200; `GET /b/terms`
     is a page or 404, never a redirect; `GET /admin` is 404, 401 or 403; a random name is 404.
5. After the next hourly cron run (it runs at 15 past), run the metric: `read_usage` has rows, and
   each provider's reads per day are under its free limit (it prints the percent). Open
   `/admin/scores`: no unexpected hold.

This covers the reply half of acceptance point 1 (what was shipped, a way to earn, one step; the X
tap and the filled page are E.1 and F) and point 6 for this reply. It does not cover point 5: there is
no page before the claim, so "not yet confirmed" on the page is checked only in E.5 and F. Run
`--reply` on each reply saved from now on (section E too).

Pass: every line above. Fail: G.

## E. Your own test (owner, with your X login)

In your own agent, with EarnKit connected. After each reply, copy the whole reply and paste it into
your chat with the controller (on a phone too; no file needed). The controller saves it to a file and
runs the check on it (section D step 3), then answers with the PASS or FAIL lines.

1. Ask: "What can I earn?". The reply:
   - names what you shipped,
   - names a way to earn with one of those projects,
   - ends with one step (one yes).
   Tap "Claim your page with X". The claim page says what is public and how to hide it. Sign in with X.
   After X, `earnkit.com/<your handle>` is your page, already filled. (Point 1.)
2. Reconnect EarnKit in the same agent, then add it to a second agent. Ask again in each and tap the
   claim link in each: both land on the same page, and the next reply in each says "Your page:
   earnkit.com/<handle>". (Point 2.)
3. Say yes to "How to move up". Do nothing else. If the step was a project with past users, the reply
   says "Done. N people who used <name> now count. You're now #N of M." and the page shows the new
   rank on its next view. If it asked for one tap, do the wallet tap, then ask again. (Point 3.)
4. Open your page. Ask the agent again after 11 minutes, then reload the page: the numbers match the
   reply. (Point 4.) Your agent's ask is what re-reads your work; a page view alone re-reads only
   when the last reading is over a day old (the cap that keeps crawlers from spending reads).
5. On the page, what is not yet confirmed is marked "not yet confirmed" and adds nothing. (Point 5.)
6. Read every reply and the page for banned words (list in D step 4). The controller runs the check on
   every saved reply. (Point 6.)
7. The coin is offered only at these moments: right after the yes in step 3, a built app going live, or
   a project with people and no coin. It is never in a program entry's confirm. (Point 7.)
8. The controller runs the metric. It prints the leaderboard's real-builder count against the goal of
   20. That number is reported, not a target.

Pass: every step reads as written and the check passes on every saved reply. Fail: G.

## F. The fresh target-user account (owner's X, or a second X account you hold)

Repeat E.1, E.3, E.5 and E.6 with the throwaway GitHub account's projects from D (a few small apps,
little GitHub, no traction). All four must pass. A reply with nothing to say about traction is fine;
an empty or "nothing found" reply is a fail.

Pass: all four. Fail: G.

## G. If anything fails

1. In Railway, unset `EARNKIT_BUILDER_SCORE` on the frontend service and redeploy (go-live step 9).
   Everything returns to the production behavior at once; the new tables keep their rows and receive
   no writes.
2. Confirm: `... --base $BASE --flag off` prints all PASS.
3. Report (below), fix on a branch, and run this runbook again from C.

## How to report

Send the controller, for each check: its section and number, PASS or FAIL, and for a FAIL the reply
pasted in full (the exact text), what you saw and what you expected. The controller sends back: the
script's output, the metric's output (real builders against 20, reads against limits), and one line:
"pass, leave the flag on" or "fail, flag off, see G". Only a full pass in D, E and F leaves the flag
on.
