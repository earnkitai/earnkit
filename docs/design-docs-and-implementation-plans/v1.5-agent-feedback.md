# v1.5: what agents asked for

Status: shipped 2026-09-30 (items 1 to 8).

The source is an agent (Grok Bot) that used EarnKit for a builder, asked "how can EarnKit be better
for you?". Its asks, and what we do with each. The rule stays the same: 5 tools, builder's words
first, never invent program facts.

## Doing now

1. **The first answer feels like money.**
   - It opens with a headline and the one best move: "Your repos can enter 4 programs. Fastest:
     Arc Microgrants with arc-usdc-tipjar, which only needs a live link."
   - Each repo links to itself, as proof we looked at *their* work.
   - The answer ends with a single offer ("Want me to start on Arc Microgrants?"), not "pick one"
     from five.
2. **Structured next steps.**
   - `list_programs` returns `matches: [{repo, repo_url, program_id, status, missing, effort}]` next
     to the text.
   - `missing` is keys, not prose: `live_url`, `mainnet_deploy`, `new_work`, `real_users`.
   - `effort` is `none | minutes | hours | days | weeks` (the slowest missing step).
3. **Eligibility check without a new tool.** `get_program` takes an optional `repo` and adds
   `eligibility: {status, missing, effort, note}` for that repo.
4. **Smaller replies.** `list_programs` returns short program rows (id, title, summary, deadline,
   tag, new) instead of full records; details stay behind `get_program`.
5. **Memory on EarnKit's side (per installation, no account).**
   - The installation remembers the GitHub username or repos it was last given, so later
     calls don't need them.
   - It remembers which programs it's working on: added when `prepare_submission` is called,
     cleared when `record_submission` is called. Those programs come first, as "You're working on".
6. **Trust marks.** Each program file has `verified_at` (the date its facts were last checked
   against `source_url`). list and get show it, and tell the agent not to re-fetch the source
   unless it is over 7 days old.
7. **Build packs are one command.** `build_help` entries carry a `start` command (e.g.
   `npx degit earnkitai/starter-agent-service my-service`) so the agent doesn't read READMEs to
   begin.
8. **One-click install** on earnkit.com for Cursor and VS Code (their MCP install deep links).

## Not now, and why

- **Private repos / GitHub OAuth:** held back by the owner for now.
- **Push alerts into the agent chat:** MCP servers can't message a client unprompted. The
  alerts offer (the agent schedules its own check) stays the way to do it.
- **Generating wallets:** EarnKit won't create or hold keys. A funding deep link (EIP-681
  payment URI + QR) for an address the agent already has is a good next step.
- **Deploy/status tool ("funded? live? explorer URL?")**: useful, but it would be a 6th tool and
  mostly repeats what the agent's own RPC calls do. Revisit if agents keep asking.
- **Exact submit click paths for DoraHacks/Colosseum:** needs checking against each real form.
  It will be added per program as `submit_steps` when verified, never guessed.
- **Listing in MCP catalogs + a demo video:** outward-facing; needs the owner's go-ahead.
