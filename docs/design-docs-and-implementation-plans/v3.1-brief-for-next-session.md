# EarnKit v3.1: make the founder a power user, then installs, then money

You are picking up EarnKit after v3 shipped. Read this whole brief before touching anything.

## What EarnKit is

EarnKit connects builders with capital. A builder installs the EarnKit MCP (https://earnkit.com/mcp) into the agent they already use (Claude Code, Grok Bot, Cursor, Codex, Muse, OpenClaw). EarnKit signs them in with X, reads one GitHub repo through a read-only GitHub App, writes a weekly ship log from real commits, ranks them against every builder (Shipping 0 to 100 over 12 weeks), and routes them to money: programs and grants with a drafted application, Backing (a tokens.fun coin on Base, builder keeps 40% of trading fees, EarnKit's Safe keeps 50%), and points that convert to $EARN later. The owner is Jenil (X @jenilt, repo earnkitai/earnkit, builder 17 on production). The owner is cash-thin and tests through Grok Bot.

Priority order, fixed by the owner:
1. The owner becomes a genuine power user and gets value every week, apart from the token launch.
2. Installs at launch (nothing works until people install).
3. Money in the bank.

## The honest assessment after building it

Cut or hide (distracts from money):
- Originality: hide it from the page and replies.
- Points before $EARN exists: keep the ledger, remove the points line from replies and the page until $EARN is real.
- Leaderboard-as-game copy ("+14 points, enough to pass #2") and the 52-week grid: rank matters, the arithmetic does not.
- The v2 entry machine (`prepare`/`confirm` submit kits, campaign pages, starters, ideas, token-at-submission): hide every surface; the agent should only see find, tell and "draft my application".
- Off-thesis programs (Avalanche, in-person ETHGlobal, Arc-only Circle) on a Base-first product.

Missing and essential:
- The first ranked reply must lead with money every time: the single best fit for the repo and "want me to draft it", rolling programs included (today the apply step waits for a deadline inside 30 days, so a new Base builder sees no money step).
- The transcript as an application: one button per program, "Apply with this page", that prefills the real form from the ship log (start with Base Builder Grants, Circle, Alliance).
- Outcomes actually collected: run the published-results path (`programs/outcomes/*.json`), ask after every application, build the "top-decile builders get in at Nx the base rate" line that sells to selectors later.
- Distribution: the Monday reply drafts the X post with the page link, ready to paste (EarnKit never posts for the builder).
- Base Builder Codes check: Base's grant says "first step: integrate Builder Codes"; detect it and tell the builder.

Underutilized, should be the real product:
- `/api/builders/<handle>.json` is the selectors' product: document it for selectors, add a per-program shortlist filter.
- Backing has no demand side: tokens.fun coin page should render the builder JSON (verified dev activity is the trader thesis), a Backed section on the landing, the ticker in the Monday post. Until then revenue is zero by design.
- The Monday email should carry money ("Alliance closes in 9 days, your draft is ready", "someone backed you"), not only the week.

What makes a cash-thin solo builder a power user:
- Money finds you; you only say yes: a finished draft from the ship log every week, one yes sends it, no forms.
- One ritual with a payoff: the Monday email as cue, one tap as action, an application sent or a rank move or a backer as reward.
- One link that is your resume: the page in every application, DM and tweet; the badge in the README; outcomes on the page as a track record.
- Compounding you can feel: streak unlocks ("your four weeks qualify you for Nitro's interview"), rank moves, recorded outcomes.
- Zero shame: no nags, no points math, no token in default flows.
