# v2.12.1: Where you stand, from the first message

Status: spec for owner review (2026-10-13). Replaces v2.12's onboarding, replies, scoring, profile,
card and leaderboard. v2.12's storage, readers, anti-farming, archives and terms stay unless this file
changes them. `EARNKIT_BUILDER_SCORE` stays off in production until the owner's own install passes the
acceptance test.

## Why this exists

The owner tested v2.12 on production on 2026-10-13: "This is the worst update thus far both in terms of
functionality and usage." It started empty, asked for proofs, used random slugs, and showed a
leaderboard of "Builder 0" rows. This update follows the owner's flow (below) step by step.

**The rule that settles every conflict:** the first message fills the page. When proof and a filled
page pull apart, show the number as an estimate instead of hiding it.

**Copy rule:** plain sentences a person understands on first read. Sentence case. No all-caps labels,
no eyebrow labels, no jargon ("outcome", "verified source", "percentile" never appear in builder or
public text). No emojis, no em dashes.

## The flow (owner's, binding)

### 1. Connect
The builder adds EarnKit to their agent. Nothing is asked. In the first `find`, the agent passes what it
can already see, in a new optional `identity` input: GitHub login (git config, `gh auth status`), local
projects (existing `local_repos`), wallets, live sites, packages. The tool description tells the agent
to fill it and never to ask the builder.

### 2. The first reply to "What can I earn?"
EarnKit reads everything inside that call (10-second budget; anything slower finishes on the next page
load or reply) and answers in three short parts ending in one yes:

```
Where you stand
You're in the top 34% of people building with AI. You've shipped 6 projects, and 2 of them have real
people using them.
Claim your page with X: earnkit.com/claim/<code>

Ways to earn right now
Your tip jar qualifies for Arc Microgrants. It pays 500 USDC and closes tomorrow.
Avalanche Team1 gives up to $10K to apps on Avalanche, and it's open all year.

How to move up
tokens.fun has users I can't count yet. If I add one line of tracking, you'd likely jump to the top 20%.
Want me to add it?
```

If nothing is found:
```
Where you stand
I couldn't find anything you've shipped yet, so you're not ranked.

Ways to earn right now
Arc Microgrants pays 500 USDC for a small app, and I can build one with you in about an hour.

How to move up
Tell me your GitHub or wallet and I'll rank you right now.
```

Rules:
- At most 3 programs, each with the reason it fits. Programs the person already entered, closed
  programs, and programs an agent can't complete are never shown.
- "How to move up" is the single step worth the most points. It always ends the reply with one yes.
- **The page link is the X sign-in (owner ruling, 2026-10-13).** "Claim your page with X" opens Sign in
  with X (OAuth 2.0 with PKCE, `GET /2/users/me`, about $0.01 a confirmation on X's pay-per-use API).
  One tap confirms the handle and lands them on `earnkit.com/<x-handle>`, already filled. It is a link,
  not a question, so the reply still ends in one yes. The claim page says what is public and how to
  hide before the tap. Once claimed, later replies show "Your page: earnkit.com/<x-handle>".
- Before the claim, the score and rank are computed and shown in replies, but there is no public page.
  Nothing is public under a name that isn't confirmed.
- "Projects" = distinct things shipped (Score, Shipped). "Real people using them" = projects with at
  least one counted user.
- The estimated jump ("you'd likely jump to the top 20%") comes from the score with the project's likely
  users counted at a conservative floor; never shown when it would not change the rank band.

### 3. They say yes: one step of tracking on an existing project
The agent adds one line to the project and EarnKit confirms: "Done. People using tokens.fun now count
toward your rank."

- **Base:** the builder's Base builder code plus the `earnkit` code as an ERC-8021 suffix on every
  transaction the app sends (the agent adds `dataSuffix` to its viem or wagmi client). The builder's
  code comes from `POST https://api.base.dev/v1/agents/builder-codes` with their wallet, called once
  and stored (owner: "Option 1"). EarnKit's own Base deploys for them carry it too.
- **Other chains (Arc, Monad, Tempo):** an EarnKit code in the same ERC-8021 suffix format (schema 0,
  the string `ek_<person code>`). EarnKit decodes it itself.
- **Websites:** a small EarnKit snippet that reports users, not visitors (see "Website users").
- "Done" is said only after EarnKit sees the line working: the next tagged transaction or snippet
  event. Until then: "Added. Your rank updates as soon as the first person uses it."
- If they pick a program instead, the agent prepares the entry from the existing project and they
  submit it themselves (today's flow).

### 4. Their rank changes
EarnKit messages only when something real happens, through the existing daily check and `find`'s
"Since you last checked" opener: "12 new people used tokens.fun this week, and you moved up to the top
21%. Want a card to share it?"

### 5. They share
X is already confirmed from the claim, so sharing is one yes: "Want a card to share it?" The card
(`earnkit.com/<x-handle>/card.png`) shows the X avatar and handle and links to the page and the
leaderboard. Someone who never claimed gets the claim link first ("Claim your page with X to get your
card"), then the card.

### 6. Later, only when it fits
- A new program they qualify for. A win or a payout.
- The token offer, only once they have real users: "Want to launch a coin for tokens.fun? You'd get 40%
  of its trading fees."
- An opt-in email when their rank changes (the existing digest).

## Identity

- **One page per person, even across agents.** A confirmed X is the main key: every installation that
  claims with the same X account (immutable X user id) joins one person. Before a claim, installations
  also join when their agents report the same GitHub login or the same wallet with EarnKit deploys. The
  owner's split record is merged by this rule.
- **The page is `earnkit.com/<x-handle>`**, case-insensitive with a redirect to the canonical case. A
  handle equal to a site route is served at `/b/<handle>`. An X rename updates the page at the next
  sign-in or daily refresh; the old handle redirects for 90 days.
- **Verified vs estimate.** Every number on the page and in replies is one of two kinds, shown plainly
  ("12 people used it" vs "about 40 people, estimate"):
  - Verified: onchain reads, data EarnKit hosts or deploys, tagged transactions, a GitHub account the
    person proved (sign-in or proof line) or whose X field matches their confirmed X.
  - Estimate: anything from what the agent reported but not yet proven (a GitHub login the agent
    supplied, a wallet with no EarnKit deploy) and website snippet counts.
  Estimates count toward the score at a reduced, capped weight so the first message can rank someone.
  A confirmed X or a proven GitHub turns them into verified numbers.

## Score

0 to 100 in four parts (owner's guide). Shown to people as a rank ("top 34% of people building with
AI"), never as "0/100".

| Part | Max | Counts | Sources in this update |
|---|---|---|---|
| Shipped | 20 | Live site, deployed contract, published package, hosted demo. Front-loaded so the first ship lands real points | EarnKit deploys and hosting; contracts by the person's wallets; repo homepages that resolve; npm and PyPI |
| Used | 40 | Unique real users, repeat users, transactions. Self-use and linked wallets never count | Callers of the person's contracts; tagged transactions; website users (capped); package downloads (capped) |
| Earned | 20 | Fees, revenue, grants and prizes won | tokens.fun creator fees; fees into their contracts; wins from `programs/outcomes` matched to entries |
| Consistency | 20 | Weeks with a ship or with users, and streaks, from any source | EarnKit's event log; commit weeks from GitHub; deploy and transaction weeks |

- Stars, forks and merged PRs no longer score (they aren't use). They still show on the page as work.
- v2.12 anti-farming carries over (self-exclusion, one per account, spread over days, fresh accounts,
  rings, review hold).
- Points fade with a 90-day half-life from the last week that earned them.
- Score 0: "not ranked yet" plus the one step. The first verified ship ranks them at once.
- Rank is the percentile among everyone with a score above 0. "Top N%" is shown only when N is 50 or
  less; otherwise "You're ranked" plus how far to the top half.
- **Updates within minutes:** a person's score and rank are recomputed whenever their data changes (a
  new reading, a tagged transaction, a website user, a deploy) and when their page is viewed, at most
  once a minute per person. No new schedule.

## Website users, not visitors

The snippet (`<script src="https://earnkit.com/t.js" data-ek="<project code>">`) never counts page
views. It counts a user only when the site reports one:
- `ek('user', id)` when someone signs up, logs in or connects a wallet (the id is hashed in the browser;
  EarnKit stores only the hash), or `ek('action', name)` for a real action (payment, post, send).
- A user counts once per project. Website users are always shown as estimates and capped at 15 of the
  40 Used points, because a site can invent ids.
- Writes are batched per project per minute and rate-limited per project, so cost stays flat.

## Profile `earnkit.com/<name>` (the design is the deliverable)

The owner: "I want the profile to be amazing and look well designed... No AI slop, capital letter
subheadings or anything that can't be well understood by humans. Simplicity in communication."

- EarnKit's navy design system with the orange and purple accents from v2.12. One dominant thing at the
  top: the rank in words ("Top 21% of people building with AI") with the score ring beside it.
- Under it, one sentence: "Shipped 6 projects. 2 have real people using them."
- Then the projects, each as a plain card: name, what it is in a few words, people using it (verified
  or estimate, labeled), money earned, programs entered and won. Most-used first.
- A quiet line of where the numbers come from ("From GitHub, Base and earnkit.com"). No badges, no
  labels in capitals, no jargon.
- Loading: the header renders at once; project cards show skeletons while readings finish.
- A design review against these rules, and owner sign-off on screenshots, before the flag goes on.

## Card and leaderboard

- **Card:** X avatar, @handle, the rank in words, the best project in one plain line ("1,100 people used
  tipjar"). Funnel Display, readable at X's mobile preview size. Offered only with a rank in the top
  half.
- **Leaderboard `/leaderboard`:** one list. Rank, avatar and @handle, the rank in words, the best
  project in plain words. Only people with a confirmed X and a score above 0. No filters, no tabs, no
  capital labels. Goal: 20 or more real builders at launch, measured, never seeded.

## Acceptance test (binding)

On production, with the flag on, the owner installs EarnKit in their own agent, asks "What can I
earn?", and checks each launch requirement:
1. The page and rank are filled on the first message.
2. One page per person, even across agents (reconnect, and a second agent).
3. Tracking takes one step on an existing project.
4. Ranks update within minutes.
5. The page shows which numbers are verified and which are estimates.
6. The reply reads like the owner's example: three short parts, one yes.
The leaderboard's real-builder count is reported against the goal of 20.

## Out of scope

Store and Farcaster or Base App listings, badges, boards by chain or tool, a newcomers group.
