# v2.12.1: Where you stand, from the first message

Status: built on branch v2.12.1 (2026-10-15); final review and owner go-live steps next. Spec
approved by the owner 2026-10-13. Replaces v2.12's onboarding, replies, scoring, profile,
card and leaderboard. v2.12's storage, readers, anti-farming, archives and terms stay unless this file
changes them. `EARNKIT_BUILDER_SCORE` stays off in production until the owner's own install passes the
acceptance test.

## Who this is for (owner, 2026-10-13)

A person who uses AI to build now and then. Lazy. Has a GitHub with little activity. Ships a project
every now and then, with no traction or revenue. Builds for fun, often apps for themselves, but still
wants to earn from what they make. Not technical. Often has several projects.

What that means for every screen and reply:
- **They have shipped things but little traction.** So the first thing they see is what they made, not
  a rank they lose on. Rank is shown only when it reads well ("#3 of 40", "top 20%"); otherwise the
  reply leads with their projects and money.
- **They do nothing technical.** Every step is done by their agent after one yes. Builder text never
  says contract, wallet address, builder code, repo, commit, onchain or chain names unless the builder
  used the word first.
- **They ship rarely.** What they shipped keeps counting; it never fades to nothing because they took a
  month off.
- **They want money, not metrics.** Every reply has a way to earn with a project they already have, and
  the token is offered at the moments in step 3b.

## What EarnKit measures (owner, 2026-10-13)

> I don't want us to become analytics for every user's projects. I want the cheapest and fastest most
> reliable ways to track their outcomes. We're not an analytics company. We track what can be measured
> as outcomes to score a builder from onchain data, GitHub, and traction that can cheaply be read or
> skipped since we want to scale to 10k+ projects. Remember each builder might have multiple.

So EarnKit reads only public data it can fetch cheaply and in bulk, and skips anything else:

| Source | What it gives | How it's read |
|---|---|---|
| Onchain (Base, Arc, Monad, Tempo) | Contracts shipped, distinct people calling them, fees, builder-code tagged transactions to tracked contracts, token trading and creator fees | Block explorer APIs and the existing RPC reads, one call per contract per day |
| GitHub | Repos shipped, live homepages, weeks with commits, outside interest (stars and forks by other people) | One GraphQL query per person per day covering all their repos |
| Packages | npm and PyPI downloads | npm's bulk endpoint (up to 128 packages per call), pypistats |
| Live links | Whether a site is up | One HEAD request per site per day |
| EarnKit itself | Deploys, hosting, entries, wins, tokens | Its own database |

Not measured: website visitors, sign-ups, revenue behind logins, anything that needs a script on the
builder's site or a paid indexer. A website project still counts as shipped (it's live); its use is
simply not scored unless it has an onchain or package side.

## Why this exists

The owner tested v2.12 on production on 2026-10-13: "This is the worst update thus far both in terms of
functionality and usage." It started empty, asked for proofs, used random slugs, and showed a
leaderboard of "Builder 0" rows. This update follows the owner's flow step by step.

**The rule:** the first message shows the builder what they made, how they can earn from it, and one
step up. One tap with X makes it a public page. Nothing waits on the builder doing work first.

**Honesty rule (owner's guide):** only confirmed data moves the score and the leaderboard. Anything the
agent reported but EarnKit could not confirm is still shown, marked "not yet confirmed", and adds
nothing.

**Copy rule:** plain sentences a person understands on first read. Sentence case. No all-caps labels,
no eyebrow labels, no jargon ("outcome", "verified source", "percentile" and the technical words above
never appear in builder or public text). No emojis, no em dashes.

## The flow (owner's, binding)

### 1. Connect
The builder adds EarnKit to their agent. Nothing is asked. In the first `find`, the agent passes what it
can already see, in a new optional `identity` input: GitHub login (git config, `gh auth status`), local
projects (existing `local_repos`), live links it can find (deploy configs, Vercel, Netlify, Lovable,
Replit, GitHub Pages), packages, and any wallet and the contracts it deployed. The tool description
tells the agent to fill it and never to ask the builder.

### 2. The first reply to "What can I earn?"
Inside that call (10-second budget) EarnKit reads the person's public data. Anything slower finishes on
the next reply or page view. Three short parts, ending in one yes.

The typical target user (a few apps, little traction):
```
Where you stand
You've shipped 3 apps with AI: a recipe planner, a budget tracker and a tip jar. You're #31 of 40
builders on EarnKit.
Claim your page with X: earnkit.com/claim/<code>

Ways to earn right now
Your tip jar fits Avalanche Team1 mini grants: up to $10K, open all year. I can prepare the entry.

How to move up
Your tip jar has a payment side people could use. Want me to make it count the people who pay you? You
won't have to do anything.
```

Someone with traction:
```
Where you stand
You're #3 of 40 builders on EarnKit. You've shipped 6 projects, and 2 of them have people using them.
Claim your page with X: earnkit.com/claim/<code>

Ways to earn right now
...

How to move up
tokens.fun has people using it who aren't counted yet. Want me to count them? Your rank goes up today.
```

If nothing is found:
```
Where you stand
I couldn't find anything you've made yet.

Ways to earn right now
Arc Microgrants pays 500 USDC for a small app, and I can build one with you in about an hour.

How to move up
Send me a link to something you've made and I'll add it.
```

Rules:
- **Lead with the work.** "You've shipped N apps" names them in a few plain words. The rank line is
  added only when it reads well: "#N of M builders on EarnKit" while fewer than 50 are ranked, then
  "top N% of people building with AI" when N is 50 or less. Otherwise no rank line.
- At most 3 programs, each tied to one of their projects with the reason it fits. Programs that need
  traction they don't have, programs they already entered, closed programs, and programs an agent
  can't complete are never shown.
- "How to move up" is the single step that helps most now, and it only promises what EarnKit can
  deliver. It ends the reply with one yes.
- **The page link is the X sign-in (owner ruling).** "Claim your page with X" opens Sign in with X
  (OAuth 2.0 with PKCE, `GET /2/users/me`, about $0.01 a confirmation on X's pay-per-use API). One tap
  confirms the handle and lands them on `earnkit.com/<x-handle>`, already filled. It is a link, not a
  question. The claim page says what is public and how to hide before the tap. Once claimed, later
  replies say "Your page: earnkit.com/<x-handle>".
- Before the claim, everything shows in replies only; there is no public page.

### 3. They say yes: the agent makes a project's use countable
One yes, and the agent does the work, then reports in one line. The steps, cheapest and most reliable
first:
- **Count past users now.** The project has a contract EarnKit isn't tracking yet (named by the agent,
  or found through the person's wallet). Tracking it counts every past caller at once. Reply: "Done. 140
  people who used tokens.fun now count. You're now #3 of 40."
- **Count future users (builder codes).** For an app that sends transactions, the agent adds the
  attribution line:
  - Base: the builder's Base code plus the `earnkit` code (ERC-8021). The builder's code comes from
    `POST https://api.base.dev/v1/agents/builder-codes` with their wallet, called once and stored
    (owner: "Option 1").
  - Other chains (Arc, Monad, Tempo): an `ek_<person code>` code in the same format, which EarnKit
    decodes itself.
  - Tags are read only on contracts EarnKit tracks; replies never promise more. Reply: "Added. People
    using it will count as they come in."
- **Give a website app a way to be used onchain.** For a web app with no onchain side, the step is the
  one the build path already does: a small payment or tip on Arc or Base through EarnKit's kit, which
  is countable for free. Offered only where it fits the app.
- **Every app built through EarnKit** has the attribution line from the start.
- If they pick a program instead, the agent prepares the entry from the existing project and they
  submit it themselves (today's flow).

### 3b. The token offer (where EarnKit earns)
The token is where EarnKit earns (owner, 2026-10-13). A coin is also onchain traction EarnKit can read
for free (trades and creator fees count toward Used and Earned). It is offered as that reply's one yes
at these moments:
- **Built through EarnKit:** in the reply that confirms the app is live and counting: "It's live. Want
  to launch a coin for it? You'd get 40% of its trading fees."
- **Existing project:** the reply that confirms its use is countable (step 3), or the reply that
  reports its first 5 people.
- **A project with people using it and no coin**, when no bigger step exists, gets the offer as the
  first reply's one yes.
- At most once per project; never again after two declines (existing rule). The wallet is shown before
  the yes (existing rule) when EarnKit knows one; when it knows none, the offer asks only the yes and
  the next reply asks for the wallet (final review: never a yes and a wallet in one reply). Shared
  clients and held profiles never see it.
- v2.12's score-20 gate is replaced by these moments.
- Measured weekly in the metric script: offers shown, accepted, launched.

### 4. Their page changes
EarnKit messages only when something real happens, through the existing daily check and `find`'s
"Since you last checked" opener: "12 new people used tokens.fun this week, and you moved up to #3. Want
a card to share it?" No nudges when nothing happened.

### 5. They share
X is confirmed from the claim, so sharing is one yes: "Want a card to share it?" The card
(`earnkit.com/<x-handle>/card.png`) shows the X avatar and handle and links to the page and the
leaderboard. Someone who never claimed gets the claim link first.

The card is offered at moments worth bragging about, not only rank: their first claimed page ("Shipped
3 apps with AI"), their first people using something, a rank change into a range that reads well.

### 6. Later, only when it fits
- A new program they qualify for. A win or a payout.
- An opt-in email when something real happens (the existing digest).
- When the flag goes on, existing installs get one message in their next daily check: "Your EarnKit
  page is ready. Claim it with X: <link>."

## Identity

- **One page per person, even across agents.** Installations join one person only on proven ties: the
  same confirmed X account (immutable X user id), the same proven GitHub login (sign-in or proof line),
  or the same EarnKit deploy wallet. An agent-reported login or wallet never merges anyone.
- **The page is `earnkit.com/<x-handle>`**, case-insensitive with a redirect to the canonical case. A
  handle equal to a site route is served at `/b/<handle>`. An X rename updates the page at the next
  sign-in or daily refresh; the old handle redirects for 90 days.
- **Confirmed vs not yet confirmed**, shown plainly on the page:
  - Confirmed: apps EarnKit hosts or deploys, contracts deployed by EarnKit or by a wallet that signed
    once on the claim page, a GitHub account proven by sign-in or proof line or whose public X field
    matches the confirmed X, and what that GitHub account links (repo homepages and Pages sites).
  - Not yet confirmed: anything else the agent reported. Shown, never scored.
  - The claim page offers two optional one-tap upgrades: sign a message with the wallet, and sign in
    with GitHub.

## Score

0 to 100 in four parts (owner's guide), confirmed data only. Shown in plain words, never as "0/100".

| Part | Max | Counts | Sources |
|---|---|---|---|
| Shipped | 20 | Live sites and apps, deployed contracts, published packages, hosted demos. Front-loaded so the first ship lands real points | Repos with a live homepage; EarnKit deploys and hosting; contracts by confirmed wallets; packages of confirmed repos |
| Used | 40 | Distinct people using it, repeat use, transactions. The builder's own use never counts | Callers of tracked contracts and tagged transactions to them; coin trades; package downloads (capped); stars and forks by other people (capped at 5) |
| Earned | 20 | Fees, revenue, grants and prizes won | Coin creator fees; fees into their contracts; wins from `programs/outcomes` matched to entries |
| Consistency | 20 | Weeks with a ship or with use, from any source | EarnKit's event log; commit weeks of confirmed GitHub; deploy weeks; weeks with counted use |

- **What they shipped doesn't vanish.** Shipped points keep at least half their value forever; Used and
  Consistency fade with a 90-day half-life. Taking a month off never resets someone to nothing.
- v2.12 anti-farming carries over (self-exclusion, one per account, spread over days, fresh accounts,
  rings, review hold, merged-PR and package caps).
- **Ranked = at least one confirmed ship** (owner's guide: "their first ship lands them in a starter tier
  right away"). The leaderboard lists ranked people with a confirmed X.
- **Fresh within minutes for the person asking.** `find` and `score` re-read that person's sources
  when the last reading is older than 10 minutes, then rescore. A page view (anyone can open a page)
  re-reads only when the last reading is over a day old, at most 200 such refreshes an hour across
  all pages and 20 an hour from one address (final review: crawlers must never spend the daily
  reads). The page always shows the newest numbers the person's own asks produced. Everyone else is
  read daily.

## Scale: 10,000+ projects, several per builder

- **One budget per project per day.** Every tracked project costs at most one read per source per day
  (one explorer call per contract, one HEAD per site, a share of one npm bulk call). GitHub is one
  GraphQL query per person covering all their repos.
- **Bulk where the API allows.** npm downloads in batches of 128; GitHub in one query per person;
  explorer calls queued and spread across the day under each provider's free limit.
- **A cap per builder.** At most 25 tracked projects per person (most recently active first); the rest
  show on the page as "not tracked" until a tracked one goes quiet for 90 days.
- **Skip, don't chase.** A source that errors or needs a paid tier is skipped for that day, never
  retried in a loop, and the page shows the last good number.
- **On-demand refresh** is limited to the person asking, at most once every 10 minutes. Page views
  refresh only after a day, under a global hourly cap (200) and a per-address cap (20).
- Measured: reads per day per source against each free limit, in the metric script.

## Card and leaderboard

- **Card:** X avatar, @handle, the headline that fits ("Shipped 3 apps with AI", "140 people use
  tokens.fun", "#3 of 40 builders on EarnKit"). Funnel Display, readable at X's mobile preview size.
- **Leaderboard `/leaderboard`:** one list. Rank, avatar and @handle, the best project in plain words.
  Only ranked people with a confirmed X. No filters, no tabs, no capital labels. Goal: 20 or more real
  builders at launch, measured, never seeded.

## Acceptance test (binding)

On production, with the flag on, the owner installs EarnKit in their own agent, asks "What can I
earn?", and checks:
1. The first message names what they shipped, a way to earn with it, and one step; one tap with X makes
   the page.
2. One page per person, even across agents (reconnect, and a second agent).
3. One yes makes a project's use countable, with the builder doing nothing; a tracked contract with
   past users moves the rank at once.
4. The page updates within minutes for the person viewing it.
5. The page shows which numbers are confirmed and which are not.
6. No technical word appears in any reply or on the page.
7. The token offer appears at the moments in step 3b and nowhere else.
The leaderboard's real-builder count is reported against the goal of 20.

A second test with a fresh account shaped like the target user (a few small apps, little GitHub, no
traction) must also pass 1, 3, 5 and 6.

## Before launch (owner)

1. An X developer app at console.x.com: verified phone, a few dollars of credits, `X_CLIENT_ID` and
   `X_CLIENT_SECRET` in Railway, callback `https://earnkit.com/x/callback`.
2. The `earnkit` builder code on base.dev, and a note to Base asking whether issuing a code per builder
   through the agents API is fine.
3. Programs: the owner adds more once this version is shown ready. Until then "Ways to earn right now"
   uses the rolling programs already in EarnKit.

## Out of scope

Website analytics of any kind, read-only connections (Stripe, Lemon Squeezy, analytics tools, GitLab,
Vercel and Netlify), Chrome Web Store and Farcaster or Base App listings, badges, boards by chain or
tool, a newcomers group, a paid indexer for builder-code tags on other contracts.

## Cost

About $0.01 per X confirmation. All other reads use free APIs within their limits, at most one read per
source per project per day plus on-demand refresh for the person asking. No new schedule.
