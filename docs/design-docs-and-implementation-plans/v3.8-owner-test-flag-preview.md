# v3.8 owner/test flag preview

Approval: Jenil approved switching features on after the tests pass (earnkitai/earnkit#159). This change lets the v3.8
gates run on production for owner and test accounts only, while `EARNKIT_FLAGS` stays unset, so a real builder sees
exactly what main serves.

## Contract

- No new env var, no schema change.
- `lib/v5/flags.ts`: a per-request flag context (`AsyncLocalStorage<boolean>`). `withFlagPreview(on, fn)` runs `fn`
  with the preview on or off; inside a preview request `flagsOn()`/`flagOn()` add `PREVIEW_FLAGS` to what
  `EARNKIT_FLAGS` names. Outside any context (cron, scripts, the screen worker, tests) and in a non-preview request the
  result is exactly `EARNKIT_FLAGS`, as before. `process.env` is never written.
- `PREVIEW_FLAGS` = `install_signin`, `x_signin`, `track_v2`, `draft_check`, `form`, `reply_fields`, `copy_v38`,
  `screen_v2`. `auto_live` and `private_rows` have no code on main (no `flagOn` reader), so they are left out.
- `lib/v6/flag-preview.ts` decides who is a preview caller, once per request:
  - a person of theirs has `test_reason` owner, test, persona or dogfood (not repro: the repro scripts check what a
    builder sees);
  - or their GitHub login / X handle is on `EARNKIT_OWNER_LOGINS`, the built-in `OWNER_LOGINS` (jenil04, jenilt) or
    `EARNKIT_DOGFOOD_LOGINS`, or the installation id is on `EARNKIT_TEST_INSTALLATIONS` (`envListReason`).
  - MCP (`app/mcp/route.ts`): by the token's installation: its person, its linked builder and the builder's person.
  - /me, sign-in and install consent routes and the /me, /me/start, /privacy pages: by the browser's `/me` session
    (`sessionBuilderId`, read only, no `last_seen_at` write) -> the builder's person and their installations' people.
  - No token/session: no lookup, `EARNKIT_FLAGS`.
  - The lookup throws: logged (`[flags] preview lookup failed`), `EARNKIT_FLAGS`. The request is still served.
  - `EARNKIT_FLAGS` already turns on every preview flag: no lookup (no cost after the global switch).

Cost: one indexed read per MCP request, and one per /me or sign-in request that carries a session cookie.

## Coverage: what the preview covers and what needs the global flag

| Step | Flag(s) | Preview covers? |
| --- | --- | --- |
| find, record, track, screen replies, tool list and descriptions (catalog, v2 statuses, draft check, reply fields, new copy, screen v2 order and packages in results) | track_v2, draft_check, reply_fields, copy_v38, screen_v2 | Yes, for an owner/test installation (by its person, linked builder, or env lists) |
| /me form redirect, /me/start, /me/consent, /privacy, delete-on-request clearing the person | form | Yes, for a signed-in owner/test builder |
| Install sign-in: authorize -> GitHub (or the X chooser) -> callback -> /install/consent -> Connect | install_signin, x_signin | Only when the browser already holds an owner/test `/me` session (sign in on /me first, then install in the same browser). The session cookie is SameSite=Lax, so it reaches authorize and the GitHub/X callbacks (top-level GETs) and the consent POST |
| Install sign-in from a fresh browser (no /me session) | install_signin, x_signin | No. Nobody is known before sign-in; this follows `EARNKIT_FLAGS` (anonymous approval). The first-install-from-nothing check needs the global flag |
| A persona's first install with a test client name (`Lane 1h`, `claude_test`) | all MCP flags | Yes from its first MCP call: the person is flagged at install, before the first tool call |
| A brand new GitHub persona whose only signal is its login | all | Only after the login is on an env list (or the person is flagged) |
| Screen worker / cron / scripts (`workQueue`'s `packages`) | screen_v2 | No: background work has no caller and follows `EARNKIT_FLAGS`. Screen results read in an owner's MCP call are previewed |
| Public pages (home, programs, docs, /api/stats) | none read a flag | Unchanged |

A preview flow that crosses identities follows each request's own caller: e.g. an owner's browser session previews the
install consent even if the GitHub account signed in on that page is someone else's.

## Counts

The preview writes nothing about who is a test. Owner and test people keep their `test_reason`, so every public and
real count (`/api/stats`) still leaves them out; the test checks the real and verified counts are unchanged after owner
and test traffic.

## Tests

`lib/v6/flag-preview.test.ts`: the preview flag set; `isPreviewCaller` per reason and env list (repro and real: no);
installation and builder/session lookups (normal, each reason, built-in owner logins, env lists, dead session); the
context per request and in parallel; a failing lookup follows `EARNKIT_FLAGS`; MCP replies for a real unlinked and
linked builder are byte-identical to the server with no flag context for tools/list, find, record, track, screen; owner
and each test reason get the flags; authorize and /me/consent with no, real and owner sessions; stats unchanged.
Every existing route test (MCP, /me, link, OAuth, install consent, X sign-in) runs with normal builders and
`EARNKIT_FLAGS` unset and passes unchanged.
