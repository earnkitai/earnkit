> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "What can I earn" gets one reply with the money, the one gap in plain words and one question. The full list (`more: true`) never contradicts itself, and no reply data invites the agent to read out points or a missing rank.

**Architecture:** The ranked Bench reply's qualify branch (bench-reply.ts `rankedReply`, fed by bench-find.ts `benchView`) gets new copy and an "Also open" line. `find {more: true}` for a profiled builder goes through the same Bench reply with the full program table in place of "Also open", so it keeps the stored ask and its move_up. The old present.ts table path (shared clients, non-ranked states) loses its contradictory lines. The find reply drops `points_total`, sends `rank_lines` only when non-empty and adds a `standing` fact.

**Tech Stack:** Next.js 16, TypeScript, Postgres, node:test via tsx.

**Spec:** the owner-approved proposal in this conversation (2026-10-29), saved as memory `earnkit-first-answer-carries-all.md`; evidence is the owner's live CTO chat replayed on a prod snapshot (`find {}` and `find {more: true}` for installation 27).

## Exact copy (owner-approved)

For the owner's state (project EarnKit, Base Builder Grant, only Builder Codes missing; Arc Microgrants and Circle open):

```
Base Builder Grants: $5,000, rolling. EarnKit is one step away: add Builder Codes, a one-line tag that credits your app's Base transactions to you.

Also open: Arc Microgrants, 500 USDC × 8 grants, closes Nov 1. Circle Developer Grants, $5,000 to $100,000 USDC grants.

Want me to add Builder Codes to EarnKit?
```

Rules behind it:
- Head: `${grantProgramName(card.title)}: ${grant.amount}, ${when}.` where `when` is `rolling` for no deadline, else `closes ${Mon D}` (e.g. `closes Nov 1`).
- Gap, every remaining step known missing (n = steps): `${name} is ${n === 1 ? 'one step' : `${n} steps`} away: ${andList(needs)}.`; otherwise `To qualify, ${name} needs to ${andList(needs)}.` NEEDS stays `put the app on Base` / `add Builder Codes` / `get people using it`. When `codes` is among the steps: if it is the last item, append `, a one-line tag that credits your app's Base transactions to you` right after `add Builder Codes`; if not last, add the sentence ` Builder Codes are a one-line tag that credits your app's Base transactions to you.` after the gap sentence.
- Also open: up to 2 open grants (never an investment, a sponsor campaign, an EarnKit campaign, a hidden program or the qualify program), in `byRelevance` order. Each item `${title before the first ':'}, ${amount cell}${when === 'rolling' ? '' : `, ${when}`}.` joined by a space after `Also open: `. No line when none.
- Question by first step: `codes`: `Want me to add Builder Codes to ${name}?`; `base`: `Want help putting ${name} on Base?`; `use`: today's `qualifyAsk` text.
- The qualify reply carries no ship line and no money line; the standing line keeps today's once-shown rule, above the head.
- The yes to the codes question: `Adding Builder Codes to ${name}. Base's guide: https://${BUILDER_CODES_GUIDE}` with no question, and an agent_note telling the agent to add Base's Builder Code to the builder's app here following the guide, show the change, and not ask again. Yes to the other first steps keeps `qualifySteps`.
