## Review Focus

1. The default view never hides a program silently. Shown step rows are numbered 1, 2, 3 as shown, and the heading keeps the true count. `And {n} more in the full list.` follows whenever rows are hidden. Every hidden program is in the full list.
2. One sign-in sentence per reply, the closing's; the proof line reads `I read your repo for proof once you sign in.` with no link.
3. `filter.all` lists every open program (names, money, `closes {date}`, `in person`), with no cap and no rule Says, for a project, a name-only project and no project.
4. Input errors (an unknown category, a project with no name, an unknown top-level key) return `isError: true` with no builder text.
5. A tied co-founder's join yes moves the name-keyed rows onto the repo key in one transaction, and the join question is never asked again for that project; when another builder holds the repo, the reply says so once and the send stays under its name (L35-1).
6. One application per project per program across a rename, a dropped repo and a send with no project; the former-builder guard holds when the key is empty (L35-2).
7. A fork never takes a second application for its parent: the one-per-repo rule reads the parent's repo id (L35-3).
8. A co-founder's second `started` on a repo another tied builder holds is refused and writes nothing; a tied builder's real send over the other's live claim is recorded and clears that claim (L35-4).
9. Thirty-one cache-busting authorize requests from one address block never stop a vendor's CIMD sign-in for anyone else, and a fresh process serves a stored good document without a fetch (L35-5).
10. `#3`, `3.`, `No. 3` and `three` mean list number 3 of the last list; a token that is not a list number is never used to write by a title match (L35-6).
11. A refused call writes nothing: after `Already sent on {date}.` and `Nothing was recorded.`, the stored application is byte-identical to before (L35-7).
