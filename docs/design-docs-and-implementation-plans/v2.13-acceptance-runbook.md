Use a fresh agent install for 1 and 2 (remove EarnKit from the agent first). Have a GitHub repo you own with a remote, and an empty folder.

## 1. With a project

Do: open your agent in the project folder. Install EarnKit fresh. Ask: "What can I earn?" Tap the claim link in the first reply and sign in with X.

| Where | You should see |
|---|---|
| First reply | Three parts: "Where you stand", "Ways to get funded", "How to move up". It names your project. It says the project joins the Bench as soon as it is confirmed (a minute or two). The claim link reads as a line: "Your page: claim it with X at https://earnkit.com/claim/<code>". "Ways to get funded" always shows: a program that fits, else up to 2 open programs with what each needs ("Base Builder Grant Program: up to $5K for a Base app, once it's live."). The last line asks to enter the best fit; with nothing that fits, once confirmed, it offers a community round. |
| An older agent (v2.13.3) | An agent that sends `github_user` and `repos` (or local remotes, or a live link) instead of `identity` gets the same reply: the first repo is the project, the login is stored. |
| Your repo | The agent pushed one proof line (the `earnkit.txt` line) to the default branch of the repo the reply's `proof.repo` names. If it cannot push, or the repo belongs to an organization or to another GitHub account than the one your agent reported, the reply has a GitHub sign-in link instead ("joins the Bench as soon as you show it's yours"). |
| An hour later, still not confirmed | The next reply has the sign-in link. Without sign-in it says the project joins once confirmed and that EarnKit checks again every day; never "a minute or two". |
| Second reply (ask "where do I stand?") | "<project> is on the Bench: ..." with a rank or your weeks shipping. |
| `earnkit.com/<your x handle>` | Your X photo, a "Started tracking <project>." card with its facts, and a Project tab. |

If it fails, check the database:

```sql
SELECT main_project_key, updates_on_at FROM builder_profiles WHERE x_handle = '<handle>';
SELECT chains, streak, weeks_shipping, confirmed FROM builder_projects WHERE project_key = '<key>';
```

Not on the Bench? The proof is not read yet. The fast check runs for one hour after the proof line is issued, then the daily check applies.

## 2. Without a project

Do: open the agent in an empty folder with a fresh install. Ask: "What can I earn?"

| Where | You should see |
|---|---|
| First reply | "You're not on the Bench yet." Then ways to get funded (always shown: up to 2 open programs with what each needs). The last line, v2.13.3 (owner ruling A), one question: "I'll put your work on the Bench and find money it can win. What's your GitHub, or a link to something you've made?" Never the generic tip jar. Only when an open program has its own starter that can compete (program file `fresh_build`), the same question adds "Or want me to build <offer> for <program>?" |
| Send your GitHub or a link | The agent calls find with it; the next reply names that project (section 1). |
| After a yes to a build | The agent builds that program's starter, puts it online and enters it. A later reply says it is on the Bench. |
| `earnkit.com/<handle>` | The new project, live, with a ship log entry. |

If it fails: `SELECT main_project_key FROM builder_profiles WHERE x_handle = '<handle>'`. Empty means the build did not finish.

## 3. Weekly update

Do: tell the agent yes when it asks "Want me to post what you ship here every week?" Then say: "post this week's update now."

| Where | You should see |
|---|---|
| Agent | It writes one short paragraph (280 characters at most) and posts it. |
| Your profile, Ship log tab (at once) | A long card for this week with the text and chips (for example "12 commits", "Went live"). No label about an agent. |
| `/feed` and the landing carousel | Not at once. They show finished weeks only, ranked by the Monday step (from 15:00 UTC), and only an update with at least one fact. Check them after the next Monday ranking. |

```sql
SELECT id, week, text, facts, points FROM project_updates WHERE project_key = '<key>' ORDER BY week DESC;
SELECT main_project_key, updates_on_at FROM builder_profiles WHERE x_handle = '<handle>';
```

`updates_on_at` empty means the yes was not recorded. Also try: say "stop posting updates", then "post my updates every week again". The agent should confirm each time.

## 4. Bench filters

Do: on your phone open `earnkit.com/bench?chain=base`. Then `earnkit.com/bench?chain=base&raising=1&weekly=1`.

| Where | You should see |
|---|---|
| `/bench?chain=base` | Only Base projects. The Base logo on the chip and on each row. |
| The filtered link | Fewer rows, and the link keeps the filters if you bookmark it. |
| A Base builder's profile | "Top N% on Base", or "#N of M" when fewer than 20 are ranked on Base. |
| A chain with under 10 ranked projects | No chip for it. That is on purpose. |
| `/leaderboard` | Goes to `/bench`. |

If a chain shows nothing: `SELECT chains FROM builder_projects WHERE project_key = '<key>'`. A project is on a chain by a confirmed contract, an EarnKit deploy, a launched coin or a program entry.

| Where | You should see |
|---|---|

## 8. Private and org repos (v2.13.3, v2.13.4)

Needs "Before you start" step 6. Do: in a private repo (yours, or an org's where you are an admin), with a fresh install, ask "What can I earn?" Claim your page with X, then ask again.

| Where | You should see |
|---|---|
| First reply (not claimed yet) | "<Project> is private, so I can't count it yet." (the project's display name: your site's spelling, else the repo name title-cased; never "EarnKit can't see earnkit"). Ways to get funded. Last two lines: "Claim your page with X (it's your name and photo on the Bench): <link>" and "Want me to put <Project> on the Bench once that's done?" The claim link is the one link. |
| Next reply (claimed) | "Your page: earnkit.com/<handle>" (no https, so the install link stays the one link), Ways to get funded, then "<Project> is private, so I can't count it yet. Install the read-only EarnKit app on it (one click): <link>" and "Want me to count it once that's done?" No claim link. |
| The link | GitHub sign-in, then GitHub's install page: pick only that repo. The done page says it worked. |
| Next reply | "I'll check <Project> is yours with a quick temporary branch on GitHub." The agent pushes the branch; the reply after says "<Project> is on the Bench", then one way to move up. |
| Your page | The project shows as "Private project" unless your agent named it itself. Its commits count each week. |
| App env unset | "I can't see <Project>. EarnKit can only see public repos right now." and, once claimed, "Want to use a different project?" |

```sql
SELECT via, repo_key, github_installation_id FROM github_verifications WHERE repo_key = '<owner/repo>' ORDER BY id DESC LIMIT 1;
SELECT state, proof FROM builder_sources WHERE kind = 'repo' AND lower(ref) = '<owner/repo>';
```

No `via = 'app'` row: the install did not finish on the setup URL (check the App's setup URL). A token is never stored: it is made per read and dropped.

## 9. One page per person: a second agent or a reconnect (v2.13.4)

Do: with a page already claimed (section 1), remove and add the EarnKit connector again (or add EarnKit to a second agent), and ask "What can I earn?"

| Where | You should see |
|---|---|
| First reply in the new agent | Where you stand, Ways to get funded, then the claim line and one yes or no. Nothing about another agent. |
| The claim link, after Sign in with X | The same page shows "This X account already has an EarnKit page.", "This agent: <client name>, connected <when>." (for example "Claude Desktop, connected 3 minutes ago"; the name is the one the agent app chose for itself when it registered, so treat it as a hint, not proof), "Only continue if your own agent gave you this link." and one button: "Add this agent to your page earnkit.com/<handle>". |
| After the click | "This agent is on your page now" and your page's address. No other agent is asked anything. |
| An agent that already has data (a wallet, a GitHub sign-in, a confirmed project, a hosted site or deploy, another linked agent; what it only reported, such as your repo or GitHub login, doesn't count) | No button. The page says "This agent already has its own data, so it can't join your page. Reconnect EarnKit in this agent (a fresh connection) and sign in with X again." Nothing is joined and no other agent is asked. Reconnect and sign in again: a fresh connection gets the one click. |
| Next reply in the new agent | "Linked to your page: https://earnkit.com/<handle>" once, then "Your page: ..." in later replies. Never a claim link again. |
| Your old agent, every reply until you answer | Its last line: "A new agent was added to your page on <date>. If that wasn't you, want me to remove it?" It shows even if that reply had another question waiting. Say no to keep it (asked of each of your agents separately). |
| Say yes instead (on a test join) | "Done. That agent is off your page, and its updates since it joined are hidden." then "Want me to show where you stand now?" The new agent's next reply asks for X again. |
| The new agent, its first day | It can post this week's update (never over one your other agent posted). Anything else (another project, a community round, an entry, a build, hiding the page, the card, turning updates off) gets "This agent was just added to your page, so ..." and "Want me to post this week's update instead?" |
| The new agent answering the notice | It can't: "Only an agent that was on your page before that one joined can answer that." |

```sql
SELECT count(*) FROM builder_profiles WHERE x_handle = '<handle>';  -- 1
SELECT type, detail FROM builder_events WHERE type = 'page_joined' ORDER BY id DESC LIMIT 1;  -- when EARNKIT_EVENT_LOG=on
```

## 10. A live link counts as live (v2.13.4)

Do: in a project whose agent passes a live link (identity.project.live_url or local_repos' live_url) that loads, ask "What can I earn?" No line says "once it's live" for that project and nothing asks to put it online. A parked, placeholder or "coming soon" page, or a link that doesn't load, is not live. This changes wording and which programs fit only; the score is unchanged.

## Roll back

Unset `EARNKIT_BENCH` on the frontend service and redeploy. Replies, landing, profile and leaderboard are v2.12.2 again, `/bench` and `/feed` return 404, and the weekly and feed steps stop. Updates, the main project, `raising_at` and the new columns stay in the database for next time.
