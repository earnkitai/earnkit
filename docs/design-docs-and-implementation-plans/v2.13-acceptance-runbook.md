# v2.13 The Bench: acceptance runbook

You run this on production with your own agent and a phone. It follows the spec's acceptance test, 1 to 7.

## Before you start

| Step | Who | What |
|---|---|---|
| 1 | You | Lawyer approves the word "Raising", the raise line ("Want to raise for X? I'll launch $X on tokens.fun and you get 40% of its trading fees.") and the pill. |
| 2 | You | Optional now: brand SVGs for Arc and Robinhood Chain at `apps/frontend/public/images/chains/arc.svg` and `robinhood.svg`. They are monograms today. |
| 3 | You | Deploy EarnKit first (it claims fees from both the old and the new split). Then merge the tokens.fun split change (branch `earnkit-split-v213`, commit 12a2874). The other order means creator fees on new coins are not claimed. |
| 4 | You | Set `EARNKIT_BENCH=on` on the frontend service and redeploy. |

Already done: `X_CLIENT_ID` and `X_CLIENT_SECRET` are set on Railway (2026-10-15) and the claim redirect to x.com was checked.

If any check fails, unset `EARNKIT_BENCH` and redeploy: every surface is v2.12.2 again. Nothing is lost; the new data waits.

Use a fresh agent install for 1 and 2 (remove EarnKit from the agent first). Have a GitHub repo you own with a remote, and an empty folder.

## 1. With a project

Do: open your agent in the project folder. Install EarnKit fresh. Ask: "What can I earn?" Tap the claim link in the first reply and sign in with X.

| Where | You should see |
|---|---|
| First reply | Three parts: "Where you stand", "Ways to get funded", "How to move up". It names your project. It says the project joins the Bench as soon as it is confirmed (a minute or two). |
| Your repo | The agent pushed one proof line (the `earnkit.txt` line) to the default branch. If it cannot push, the reply has a sign-in link instead. |
| Second reply (ask "where do I stand?") | "<project> is on the Bench: ..." with a rank or your weeks shipping. |
| `earnkit.com/<your x handle>` | Your X photo, a "Started tracking <project>." card with its facts, and a Project tab. |

If it fails, check the database:

```sql
SELECT main_project_key, updates_on_at FROM builder_profiles WHERE x_handle = '<handle>';
SELECT chains, streak, weeks_shipping, confirmed FROM builder_projects WHERE project_key = '<key>';
```

Not on the Bench? The proof is not read yet. The fast check runs for one hour after the proof line is issued, then the daily check applies.

## 2. Without a project

Do: open the agent in an empty folder with a fresh install. Ask: "What can I earn?"

| Where | You should see |
|---|---|
| First reply | "You're not on the Bench yet. Pick something to build and you're on it today." Then ways to get funded phrased as ideas (for example "Arc pays up to $10K for payment apps."), and one build offer as the last line. |
| After one yes | The agent builds a starter, puts it online and enters it. A later reply says it is on the Bench. |
| `earnkit.com/<handle>` | The new project, live, with a ship log entry. |

If it fails: `SELECT main_project_key FROM builder_profiles WHERE x_handle = '<handle>'`. Empty means the build did not finish.

## 3. Weekly update

Do: tell the agent yes when it asks "Want me to post what you ship here every week?" Then say: "post this week's update now."

| Where | You should see |
|---|---|
| Agent | It writes one short paragraph (280 characters at most) and posts it. |
| Your profile, Ship log tab | A long card for this week with the text and chips (for example "12 commits", "Went live"). No label about an agent. |
| `/feed` | The update, only if it has a fact and the week is finished. The feed shows finished weeks, so it appears after the next Monday's step. To show it at once, run `pnpm feed:pin <id>` locally against production (find the id below). Only do this if you want it shown now. |

```sql
SELECT id, week, text, facts, points FROM project_updates WHERE project_key = '<key>' ORDER BY week DESC;
SELECT main_project_key, updates_on_at FROM builder_profiles WHERE x_handle = '<handle>';
```

`updates_on_at` empty means the yes was not recorded. Also try: "stop posting updates", then confirm the weekly note returns when you turn it back on.

## 4. Bench filters

Do: on your phone open `earnkit.com/bench?chain=base`. Then `earnkit.com/bench?chain=base&raising=1&weekly=1`.

| Where | You should see |
|---|---|
| `/bench?chain=base` | Only Base projects. The Base logo on the chip and on each row. |
| The filtered link | Fewer rows, and the link keeps the filters if you bookmark it. |
| A Base builder's profile | "Top N% on Base", or "#N of M" when fewer than 20 are ranked on Base. |
| A chain with under 10 ranked projects | No chip for it. That is on purpose. |
| `/leaderboard` | Goes to `/bench`. |

If a chain shows nothing: `SELECT chains FROM builder_projects WHERE project_key = '<key>'`. A project is on a chain by a confirmed contract, an EarnKit deploy, a launched coin or a program entry.

## 5. Raise

Do: when the agent asks "Want to raise for <project>?" (after going live, or at the fifth week in a row), say yes. Later say "stop raising".

| Where | You should see |
|---|---|
| Agent | It names the ticker, launches the coin on tokens.fun and links it. |
| Profile, Bench row, card | The "Raising $SYMBOL" pill, linking to the tokens.fun page. |
| After "stop raising" | The pill is gone. The coin stays. |

```sql
SELECT token_status, raising_at, coin_tx, coin_chain_id FROM projects WHERE repo_url ILIKE '%<repo>%';
```

`raising_at` set but no pill: the coin is not launched yet (`token_status`). A coin that launched before v2.13 shows no pill until its builder says yes.

## 6. Landing page

Do: open `earnkit.com` on your phone.

| Where | You should see |
|---|---|
| Hero | "Ship every week. Get funded." and an "Add to your agent" button. |
| The Bench | The top 10 with chain chips and Raising as filters. "See the Bench" opens `/bench`. |
| This week on the Bench | A carousel of square cards: photo, handle, project, first line of the update, up to two chips. |
| Grants open now | The program carousel, without a bonus pill. |
| How it works | Three steps. |
| Labels | No all-caps labels. "Backed by" is in sentence case. |

Empty carousel? No finished week has an update with a fact yet. Check `/feed` and the query in step 3.

## 7. Builder bonus is gone

Look for the words "builder bonus", "bonus ticket" or a bonus pill in each place:

| Place | Expect |
|---|---|
| A fresh agent reply (find, and after confirming) | None. The coin is pitched as 40% of trading fees. |
| `/` | None. |
| `/programs/<id>` (open a few) | None. |
| `/terms` | Fee table 40 / 10 / 50, no bonus paragraphs. |
| `/llms.txt` | The Bench section, no bonus text. |
| `/bonus/<round>` and `/admin/bonus/<round>` | 404. |

## Roll back

Unset `EARNKIT_BENCH` on the frontend service and redeploy. Replies, landing, profile and leaderboard are v2.12.2 again, `/bench` and `/feed` return 404, and the weekly and feed steps stop. Updates, the main project, `raising_at` and the new columns stay in the database for next time.
