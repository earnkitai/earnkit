# v2.5 Ride Programs: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** EarnKit matches builders to open money in external programs. Every entry gets a coin by default, with a new fee split. Coin fees fund a per-program builder bonus that is scored on real traction and paid automatically.

**Architecture:**
- **Program files** gain `ideas` and `submission_proof`.
- **`list_programs`** leads with "$X in open money".
- **tokens.fun** sets a 4-way reward split for EarnKit launches.
- **The existing hourly cron** gets new jobs: collecting each EarnKit coin's Clanker rewards and booking the bonus wallet's WETH deposit to the program round open at that moment; claiming the bonus wallet's and the Safe's fees; scoring open rounds on traction signals; freezing, reviewing and paying the top 10 in WETH (reusing v2.4's payout engine, generalized to per-winner amounts); and sweeping post-round deposits to the Safe.

**Tech stack:** Next.js 16, postgres.js, zod v4, viem 2.57, node:test via `tsx --test`. tokens.fun uses vitest.

**Spec:** `docs/design-docs-and-implementation-plans/v2.5-ride-programs.md`

**Plan format note (ruling at plan time):** this plan gives exact interfaces, behaviours, values and test cases for every task, plus full code only for the novel arithmetic (`T1`'s recipients, `T4`'s attribution parsing, `T7`'s split). Implementers write the remaining code to these interfaces, following the v2.4 code they extend. Reason: most tasks extend v2.4 modules that already set the pattern. Cost if wrong: more review rounds.

## Review Focus

1. **A coin collected in one tx that deposits to several owners.** Expected: only the bonus wallet's WETH `StoreTokens` amount is booked, once (keyed by tx hash and log index). Owned by T4.
2. **A program whose window ends between collection and claim.** Expected: the booking uses the collection block's timestamp, so it goes to the round or to the Safe sweep accordingly. Owned by T4.
3. **Rolling programs at a month boundary.** Expected: the deposit goes to the month of its block time; the round for the old month freezes and the new month's round opens. Owned by T4.
4. **A round with 0, 1 or 3 eligible entries.** Expected: the split renormalizes; with 0 eligible, the whole pool goes to the Safe. Owned by T7.
5. **A builder who skipped the coin.** Expected: never in any round, and the coin row said "skip: no builder bonus". Owned by T8.

```ts
export const EARNKIT_REWARD_BPS = { platform: 3000, creator: 4000, miniBuyback: 1000, bonus: 2000 } as const;

/**
 * EarnKit launches (v2.5): platform = EarnKit's Safe 30 / creator 40 / MINI buyback 10 / builder
 * bonus 20, of the post-cut pool. Index 0 stays the platform slot (the revenue indexer reads it).
 * The Safe administers every slot but the creator's, so a leaked bonus-wallet key can't redirect fees.
 */
export function buildEarnKitRewardRecipients(w: { safe: Address; creator: Address; miniBuyback: Address; bonus: Address }): ClankerRewardRecipient[] {
  const slot = (recipient: Address, admin: Address, bps: number): ClankerRewardRecipient => ({ admin, recipient, bps, token: "Paired" });
  const r = [
    slot(w.safe, w.safe, EARNKIT_REWARD_BPS.platform),
    slot(w.creator, w.creator, EARNKIT_REWARD_BPS.creator),
    slot(w.miniBuyback, w.safe, EARNKIT_REWARD_BPS.miniBuyback),
    slot(w.bonus, w.safe, EARNKIT_REWARD_BPS.bonus),
  ];
  if (r.reduce((a, x) => a + x.bps, 0) !== 10000) throw new Error("EarnKit reward bps must sum to 10000");
  return r;
}
```

```ts
export function bonusDeposits(logs: { address: string; topics: string[]; data: string; logIndex: number }[], bonusWallet: string) {
  const out: { logIndex: number; amount: bigint }[] = [];
  for (const l of logs) {
    if (l.address.toLowerCase() !== FEE_LOCKER || l.topics[0] !== STORE_TOKENS) continue;

    const [, amount] = decodeAbiParameters([{ type: 'uint256' }, { type: 'uint256' }], l.data as Hex);
    out.push({ logIndex: l.logIndex, amount });
  }
  return out;
}
```

```ts
export const BONUS_SPLIT_BPS = [2500, 1800, 1400, 1100, 900, 700, 600, 400, 300, 300];
export function splitPool(pool: bigint, n: number): bigint[] {
  if (n <= 0 || pool <= 0n) return [];
  const bps = BONUS_SPLIT_BPS.slice(0, Math.min(n, 10));
  const total = BigInt(bps.reduce((a, b) => a + b, 0));
  const out = bps.map((b) => (pool * BigInt(b)) / total);
  out[0] += pool - out.reduce((a, b) => a + b, 0n); // rounding dust to first place
  return out;
}
```

- Lifecycle per round:
  1. open;
  2. at the end: score final and freeze, then open the review (48h, top 10 public, veto);
  3. pay: one WETH transfer per winner, with the amount frozen in the terms at review open;
  4. done.
  - With no eligible entries, the round's booked total is moved to `'safe'` (state `empty`).
- `payWinner` and `payCampaign` are generalized:
  - the token and the per-row amount come from the frozen terms;
  - every v2.4 safety rule is kept (store before broadcast, stale-send handling, sanctions, idempotency, 503 to the owner).
