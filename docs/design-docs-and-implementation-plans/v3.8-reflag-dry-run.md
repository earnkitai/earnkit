# v3.8: reflag dry run at deploy (read only, visible without credentials)

Approval: earnkitai/earnkit#159. No flag (read-only, logs only).

## Why

`people-backfill.mts --reflag` reads `EARNKIT_OWNER_LOGINS`, `EARNKIT_DOGFOOD_LOGINS`, `EARNKIT_TEST_INSTALLATIONS`
from the shell that runs it, so seeing what it would change on production needs the production DB URL and the lists.
Running it inside the deploy (which already has both) and printing a safe summary to the deploy log makes it visible
without handing out credentials.

## Design

- `reflagScan` (internal) is the old `reflagPlan` query plus each person's public handle (`builders.login`, else
  `people.github_login`, else `@` + `builders.x_handle`/`people.x_handle`) and the number of people read. `reflagPlan`
  returns the same rows as before (handle stripped), so `--reflag` output is unchanged.
- `reflagReport(out, env)`: `inMode(false, ...)` (BEGIN READ ONLY ... rolled back), plus explicit
  `SET TRANSACTION READ ONLY` and `SET LOCAL statement_timeout = '30s'`. Prints, each line prefixed `[reflag dry-run]`:
  env list sizes, people scanned, `test_reason` changes with `old -> new` counts, owner changes (`false -> true`
  counts), verified changes (always 0: reflag never touches `verified_by`/`verified_at`), then at most 200 handle lines
  and a "N more not listed" line. Handles that are not handle-shaped print `(no public handle)`.
- `people-backfill.mts --reflag-report`: catches every error and prints `skipped: <code or class>` (never the
  message, which can carry a host), a 60 s unref'd timer prints `skipped: timeout`, always `process.exit(0)`.
- `package.json`: `people:reflag-report`; `predeploy` = `pnpm db:migrate && pnpm programs:sync && (pnpm
  people:reflag-report || true)`. The `|| true` also covers a failure before the script's own try (e.g. tsx).

## Tests (lib/v6/reflag-report.test.ts)

Seeded people (owner, dogfood over test, persona by client name, unchanged): exact output lines, row checksums of
people/installations/builders equal before and after, no `@`, email, name, wallet, URL or token in the output; 206
changes list 200 handles plus "6 more"; the script with an unreachable DB exits 0 with one `skipped:` line and no
host; `predeploy` order and `|| true`.

## Production effect

No schema change, no writes. Each deploy log gains a `[reflag dry-run]` block after programs:sync. A slow DB adds at
most ~60 s to predeploy.
