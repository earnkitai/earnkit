# v6.1.18.1: patch, the license read on old cache rows, license rule behind repo steps, started and sent asks (live lane, lane 41)

**Goal:** Close the regression a live persona lane found on v6.1.18 and two items from lane 41. After this patch, a repo GitHub reports as MIT, GPL-2.0, AGPL-3.0 or Unlicense never gets the license rule (HeroDevs, GitHub Secure, PayPal, QNX, Sovereign Tech) because of a repo read cached before v6.1.18; the license rule never shows beside a repo step; `track started` never asks a license rule the repo read settled; and a builder-submits program started in its last hour is asked about after it closes, for 7 days.

**Spec:** the controller's dispatch for v6.1.18.1 and `journeys/lane-41-report.md` (L41-1, L41-10).

## Tasks

1. `complete()` (`lib/v5/repo-facts.ts`) requires the `license` field: a cached row from before v6.1.18 (no `license` key) is incomplete and re-read; a row with `license: null` (no license file) is complete.
2. `evaluate` (`lib/v5/eligibility.ts`): a license-check rule is hidden while any repo step stands (`repo:public`, `repo` for code, `repo:archived` for a live repo). Tests: a private repo on each license program shows the public-repo step and no license rule; an empty repo on HeroDevs shows the code step (with a live link) and no license rule; a public MIT repo on HeroDevs is ready; a public repo with no license shows only `a license file`.
3. L41-1: `openRules` (`lib/v5/track.ts`) treats a license-check rule as confirmed when the repo's cached read (`cachedRepoFacts`, never a fetch) shows an OSI license on a live repo, as find does. Test: GitHub Secure on an MIT repo starts with no rule question; on a repo with no license the rule is still asked.
4. L41-10: `askSent` (`lib/v5/ledger.ts`) asks about a started builder-submits program while it is open and for `SENT_ASK_AFTER_CLOSE_DAYS` (7) after its `ends_at`; after that neither the ask nor the kept claim's release line is said. Tests in `ledger.test.ts` and `find.test.ts` (closed an hour after the start). Finding: the find path already asked after the close (`withOwn` reads programs outside the open list); the lane's missing ask was not reproduced, so this task adds only the 7-day bound.
5. Version: a patch keeps 6.1.18 (a fourth part is not semver; the L1j-8 gate ignores it), as v6.1.14.1 and v6.1.16.1 did. The release list in the architecture guide names 6.1.18.1.
