# v4.6 Verified Stripe revenue: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A builder connects Stripe once, read-only, through a page on earnkit.com. After that, EarnKit reads the last 30 days of money they received, every day. Grant drafts and the builder's own replies carry that figure as a verified fact. It never appears anywhere public.

**Architecture:**
- **Connect page.** `/connect/stripe?t=<token>` follows the wallet-proof link pattern (`wallet-proof.ts` `upgradeToken` / `upgradeOf`, 30-minute TTL, X cookie check). The builder pastes a restricted key there, never in chat.
- **Key storage.** The key is checked, then stored encrypted (AES-256-GCM). The encryption key is derived with HKDF from `EARNKIT_AUTH_SECRET`, so there's no new env var.
- **Daily read.** `runStripeRevenue` reads balance transactions and active subscriptions, then writes `stripe_revenue`.
- **Drafts and replies.** `tractionFacts` gains a `stripe` field. `shipLogBlock` and `replyFacts` print it next to the onchain line, never summed with it.
- **The ask.** A one-time ask of kind `stripe` offers the link.

**Tech Stack:**
- Next.js 16, TypeScript, Postgres, node:test via tsx.
- Stripe REST over `fetch`; no SDK and no new dependency.
- Node `crypto` for AES-256-GCM and HKDF.
- Frankfurter (ECB rates, free, no key) for balances not settled in USD.

**Spec:** the owner-approved scope (2026-10-30, "scope out 1 and 2 ... both can be sep releases"), built on v4.5 (`v4.5-plan.md`):
- Read-only.
- Never in chat.
- Net of refunds and disputes.
- Private: drafts and replies only.
- Shown from $100.
- Fresh reads only.
- Test keys refused.
- Costs flat.

## Exact copy

- **Ask (kind `stripe`, once; a no is permanent, `declined['stripe']`):** two lines, so the question is the last line.
  ```
  Connect Stripe read-only here: {link}
  Want grant drafts to show {name}'s Stripe revenue?
  ```
- **Connect page heading:** `Connect Stripe, read-only`
- **Connect page steps:**
  1. `In Stripe, open Developers, API keys, and create a restricted key.`
  2. `Give it Read on Balance transactions, Charges, Subscriptions and Account. Nothing else.`
  3. `Paste it here. EarnKit only reads, never shows the number publicly, and you can disconnect any time.`
- **Connect page outcomes:**
  - Saved: `Connected. Your next grant draft shows your Stripe revenue once it reaches $100 in 30 days.`
  - Full secret key: `That's your full secret key. Make a restricted key with Read only and paste that instead.`
  - Test key: `That's a test key. Paste a live restricted key.`
  - Missing permission: `This key can't read {what}. Add Read on {what} and paste it again.`
  - Site mismatch: `Stripe lists {host} as this account's website, which isn't one of your projects. Set your project's site in Stripe, Settings, Business details, then paste again.`
- **Ship-log line:**
  `${usd} received through Stripe in the last 30 days, verified from Stripe`
  - Then, when MRR ≥ $100: `, ${mrr} a month in subscriptions`
  - Format `usd` as v4.5 does, whole dollars with en-US grouping (`$1,240`).
- **Reply facts:** `stripe_30d_usd: number` and `stripe_mrr_usd: number`, with the same thresholds and freshness as the line. They're absent otherwise.
- **Disconnect:** the builder says "disconnect Stripe", the agent calls `tell {stripe: 'disconnect'}`, and the reply is `Stripe disconnected. EarnKit deleted the key.`

## Rules

- **Net figure.** `net_usd` = Σ over balance transactions created in the last 30 days:
  - Plus: `charge` / `payment`.
  - Minus: `refund` / `payment_refund`.
  - Minus disputes: `adjustment` whose `reporting_category` is `dispute`, plus `dispute_reversal` back in.
  - Counted on `amount`, which is before Stripe fees; fees are not subtracted.
  - The result is clamped at 0.
- **MRR.** Σ over `status=active` subscriptions of each item's `price.unit_amount × quantity`, normalized to a month (`year ÷ 12`, `week × 52 ÷ 12`, `day × 365 ÷ 12`). Trialing, canceled and past-due subscriptions don't count.
- **Currency.**
  - Balance transactions are in the balance's currency. USD counts as is.
  - Any other currency converts at that day's Frankfurter rate (`https://api.frankfurter.app/latest?from=<CUR>&to=USD`), cached per currency per UTC day.
  - If there is no rate, store nothing.
- **Real customers.** A figure shows only when the paying charges come from ≥ 3 distinct payers (`payment_method_details.card.fingerprint`, else `customer`, else `billing_details.email`), and the top payer is ≤ 50% of gross.
  - Otherwise the row stores `shown = false`, and drafts skip it.
  - Charges whose `billing_details.email` equals an email EarnKit holds for the builder (the `digest` opt-in email) are dropped before the count.
- **Ownership.** `GET /v1/account`: `business_profile.url`'s host must equal the host of one of the builder's verified `site` sources. A subdomain of the same registrable domain also counts.
  - Without a match the key is refused: the site-mismatch copy, and nothing stored.
  - This is the line that stops pasting a friend's account.
- **Platforms.** An account with `controller` set or Connect application fees is read on its own balance only. That's what the balance transactions already are, so there's no special case.
- **Failed reads.** A failed or partial read stores nothing. A read that hits the page cap (`STRIPE_PAGES = 10` × 100) stores `capped = true`, and the figure gets `+`.
- **Bad keys.** A `401` / `403` on the daily read marks the connection `broken`. The ask then re-offers once with the same copy and a fresh link (`declined` untouched). After that, it's quiet.

## Review Focus

1. A pasted key never reaches logs, events, `cron_runs`, an error message, a route response or a test snapshot. A test seeds a key and greps every one of those outputs for it.
2. A friend's Stripe account (website host not one of the builder's verified sites) is refused at paste, so no row is ever stored.
3. Revenue from one or two payers, or one payer above 50%, never prints. A refund issued after the read drops the next day's figure.
4. An `sk_live_` paste is refused with the restricted-key copy and never stored, not even encrypted.
5. Disconnecting deletes the encrypted key row, so the next cron reads nothing. Old `stripe_revenue` rows stop printing once they're stale (`USED_STALE_DAYS`).
