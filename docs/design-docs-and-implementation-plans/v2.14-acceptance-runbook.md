# v2.14 One account: acceptance runbook

You run this on production with your own agent and a phone. No coding is needed: where a step needs an engineer, it says "send the result to your engineer". Sections 1 to 5 are the spec's acceptance items. Section 0 is the human client checks that code cannot do.

## Hard prerequisites

v2.14 does not work without these. Sign in with X is how a builder gets a page, and the read-only GitHub App is the only way a repo is proven. If any of them is missing after deploy, the hourly cron lists it as `env-missing:<NAME>` (or `env-invalid:GITHUB_APP_PRIVATE_KEY`) and keeps alerting until it is set.

| Variable (Railway, frontend service) | Needed for |
|---|---|
| `X_CLIENT_ID`, `X_CLIENT_SECRET` | Sign in with X at install. Without them every install is anonymous and nobody gets a page. |
| `GITHUB_APP_ID`, `GITHUB_APP_SLUG`, `GITHUB_APP_PRIVATE_KEY` | The read-only GitHub App, the only proof. Without them no repo can be counted. |
| `GITHUB_OAUTH_CLIENT_ID`, `GITHUB_OAUTH_CLIENT_SECRET` | The GitHub step of the App install. Without them the App is off too. |
| `EARNKIT_URL` | Every public link, and the sign-in redirect (production errors without it). |
| `EARNKIT_AUTH_SECRET` | The one-time sign-in link and its paste code. |

Leave `EARNKIT_RAISING` off until the lawyer has reviewed the community round.

## 0. Client preflight (human)

Run once on production. Five clients: Claude Desktop, Claude Code, claude.ai, Cursor, ChatGPT. If a client cannot finish, its first reply must show the sign-in link and the paste code must work (see "If a client can't finish").

| Check | Do | You should see | If not |
|---|---|---|---|
| 1. Full round trip, in each of the five clients | Add the connector, start sign-in, sign in on X, wait 2 minutes on the X approval screen, then approve. | The client returns to its own chat with the connector connected. | Write down the client and the error, and send it to your engineer. A hidden timeout means that client uses the fallback link. |
| 2. Browser (Claude Desktop, Cursor) | Start the sign-in in each. | X opens in your normal browser, already signed in. | A small window inside the app instead: you type your X password once. Write it down; nothing to fix. |
| 3. ChatGPT registration | Add the connector from two users in one workspace; try on a Plus account. | Each user connects on their own. Plus either adds it or shows no option. | If both users end up as one connection, or Plus can't add it, send the details to your engineer. |
| 4. Reconnect prompt (claude.ai) | Ask your engineer to revoke your token, then use the connector. EarnKit issues no refresh tokens and its tokens don't expire, so this prompt only ever appears after a revoke. | A reconnect prompt. | Remove and re-add the connector, and send what you saw to your engineer for the docs. |
| 5. Landing | Finish sign-in in each client, then send any message. | Connected, and a first reply with one link to your page. | Use the fallback for that client and send what happened to your engineer. |
| 6. Which address ChatGPT uses | Add the connector in ChatGPT. | Sign-in goes straight to X. | If you see a page "You're connecting EarnKit to chatgpt.com" first, that is expected once: continue. Send a screenshot of that page to your engineer. |

### If a client can't finish

The first reply says "You're not on the Bench yet." and ends "Sign in with X to get your page (one click): <link>". Open the link, read the agent name it shows, continue with X. The page shows "Signed in as @handle." and a code like `ABCD-EFGH-JKMN`. Paste it into the same agent. The next reply starts "Signed in as @handle."

## 1. Fresh agent

Do: in Claude Code, remove EarnKit, add it again, and sign in with X when asked. Then type: "What can I earn?"

| Where | You should see |
|---|---|
| The install | A sign-in with X step (the warning page only for an unknown address). |
| First reply | "Signed in as @handle." then your stand line, "Your page: https://earnkit.com/<you>" (or "You're not on the Bench yet."), "Ways to get funded", and one question. |
| `earnkit.com/<you>` | Your X name and photo. |

## 2. Second agent, same X

Do: add EarnKit to a second agent (for example Cursor) and sign in with the same X. Then type: "What can I earn?"

| Where | You should see |
|---|---|
| The install | Nothing to approve or merge. |
| First reply | The same page link. |

A second agent attaches alone: its old data (if any) is never merged into the page.

## 3. The App

Do: open Claude Code (the agent from section 1) in your local copy of `earnkitai/earnkit` and type: "What can I earn?"

| Where | You should see |
|---|---|
| Reply | "EarnKit isn't counted yet." with the install link for the read-only app. |
| Install | Open that link and install the app on earnkitai/earnkit. The confirm page names your page ("This adds github.com/earnkitai/earnkit to earnkit.com/<you>"). |
| Next reply | Type "What can I earn?" again: "EarnKit is on the Bench: #N of M builders." |

Do: for every reply above, count the https links and read the last line.

## If a check fails

Send your engineer: the reply text, the time, the agent, and the client.

## Known behaviours

| Behaviour | What to expect |
|---|---|
| Pre-v2.14 unclaimed agents that reconnect (D11) | They start fresh: a new installation, old data stays behind. The App install is one click. |
| No merge | A second agent attaches alone; its old group and data never merge into the page. |
| Shared clients (Grok Bot) | No App links, no coin launches, nothing remembered per builder. They keep the anonymous approval. |

| An App proof | Replaces another person's discovery-derived hold on the same repo. |
| Deploy caps | Per repo owner. |
| Titles-only weeks | Stay off the feed. |
| Unknown addresses | See a warning page naming the host. Straight to X: the three documented callbacks (claude.ai, chatgpt.com, www.cursor.com), local addresses, and the apps Cursor, VS Code, Windsurf and Claude. |
| Unanswered v2.13.4 joins | Detached at deploy (none on production). |
| A refused re-authorization | Keeps the token the agent already had. |
| Rolling deploy | For a few seconds while old and new servers both run, a sign-in can wait on the other's lock. It finishes; nothing to do. |
| `build_offer` | Still the v2.11 short reply (shared clients and agents with no page). |
| Builder bonus rounds | No longer pay out. Coin fees still go to the Safe and the builder's 40%. |
