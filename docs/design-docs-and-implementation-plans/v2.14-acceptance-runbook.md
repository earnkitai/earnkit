# v2.14 One account: acceptance runbook

You run this on production with your own agent and a phone. Sections 1 to 5 are the spec's acceptance items. Section 0 is the human client checks that code cannot do.

## Before deploy

| Step | What |
|---|---|
| 1 | Railway env, frontend service. Set or confirm: `EARNKIT_URL` (needed at authorize: the redirect carries `iss`; production errors without it), `X_CLIENT_ID` and `X_CLIENT_SECRET`, `EARNKIT_AUTH_SECRET`, and the GitHub App vars `GITHUB_APP_ID`, `GITHUB_APP_SLUG`, `GITHUB_APP_PRIVATE_KEY` plus `GITHUB_OAUTH_CLIENT_ID`, `GITHUB_OAUTH_CLIENT_SECRET`. Leave `EARNKIT_RAISING` off. |
| 2 | GitHub App settings: "Redirect on update" on; setup URL `https://earnkit.com/github/verify/app`. |
| 3 | Read-only prod checks the controller ran: open `page_joins` = 0, empty eligible = 0, overlapping = 0. The S4 migration is a no-op on production. |
| 4 | Check unpaid bonus rounds (Task 3 removed `roundsCovered`). Expect no rows. Rows mean a deposit was booked to a round that never paid: tell the controller before deploying. |
| 5 | Deploy. `pnpm db:migrate` runs on every deploy and is safe to rerun. |
| 6 | After deploy, check the bind: the second query below should be at least 1 for your own installations. |
| 7 | After deploy, remove `EARNKIT_BUILDER_SCORE` and `EARNKIT_BENCH` from Railway. Nothing reads them. |

```sql
-- step 4: bonus_ledger rows for a round that is not paid or empty
SELECT l.*, r.state
FROM bonus_ledger l
JOIN bonus_rounds r ON r.round_key = l.round_key
WHERE l.destination = 'round' AND r.state NOT IN ('paid', 'empty');

-- step 6
SELECT count(*) FROM installations WHERE x_user_id IS NOT NULL;
```

Rollback: redeploy the previous release. New columns and tables wait; nothing was dropped.

Use a fresh agent install for sections 1 and 2 (remove EarnKit from the agent first). Have a GitHub repo you own and `earnkitai/earnkit`.

## 0. Client preflight (human)

Run once on production. Five clients: Claude Desktop, Claude Code, claude.ai, Cursor, ChatGPT. If a client cannot finish, its first reply must show the sign-in link and the paste code must work (see "If a client can't finish").

| Check | Do | You should see | If not |
|---|---|---|---|
| 1. Full round trip, in each of the five clients | Add the connector, start sign-in, sign in on X, wait 2 minutes on the X approval screen, then approve. | The client returns to its own chat with the connector connected. | Note the client and the error. A hidden timeout means that client uses the fallback link. |
| 2. Browser (Claude Desktop, Cursor) | Start the sign-in in each. | X opens in the system browser, already signed in. | Embedded window: you type your X password once. Record it; no code change. |
| 3. ChatGPT registration | Add the connector from two users in one workspace; try on a Plus account. | A separate client id per user. Plus either adds it or shows no option. | One shared client id: treat ChatGPT as a shared client (no person binding). Plus can't: drop Plus from the supported list. |
| 4. Reconnect prompt (claude.ai) | Revoke a token on our side, then use the connector. | A reconnect prompt. | Remove and re-add the connector; note it in the docs. |
| 5. Landing | Finish sign-in in each client, then send any message. | Connected, and a first reply with one link to your page. | Use the fallback for that client and file the behaviour. |

Read the `redirect_uris` from the authorize URL or the warning page. | `https://chatgpt.com/connector_platform_oauth_redirect`: sign-in goes straight to X. | If it is `https://chatgpt.com/connector/oauth/<callback_id>`, you see the warning page once before X. ### If a client can't finish

The first reply says "You're not on the Bench yet." and ends "Sign in with X to get your page (one click): <link>". Open the link, read the agent name it shows, continue with X. The page shows "Signed in as @handle." and a code like `ABCD-EFGH-JKMN`. Paste it into the same agent. The next reply starts "Signed in as @handle."

## 1. Fresh agent

Do: remove EarnKit from a fresh agent. Add it. Sign in with X when asked. Then ask: "What can I earn?"

| Where | You should see |
|---|---|
| The install | A sign-in with X step (the warning page only for an unknown redirect). |
| First reply | "Signed in as @handle." then your stand line, "Your page: https://earnkit.com/<you>" (or "You're not on the Bench yet."), "Ways to get funded", and one question. |
| `earnkit.com/<you>` | Your X name and photo. |

## 2. Second agent, same X

Do: add EarnKit to a second agent and sign in with the same X.

| Where | You should see |
|---|---|
| The install | Nothing to approve or merge. |
| First reply | The same page link. |

A second agent attaches alone: its old data (if any) is never merged into the page.

## 3. The App

Do: ask in the earnkitai/earnkit folder.

| Where | You should see |
|---|---|
| Reply | "EarnKit isn't counted yet." with the install link for the read-only app. |
| Install | Install the app on earnkitai/earnkit from that link. The confirm page names your page ("This adds github.com/earnkitai/earnkit to earnkit.com/<you>"). |
| Next reply | "EarnKit is on the Bench: #N of M builders." |

## 4. The ship log

Do: wait for the next Monday after 15:30 UTC. Schedule nothing.

| Where | You should see |
|---|---|
| `earnkit.com/<you>` | That week's entry from the week's commit and PR titles (up to 3). |
| A private repo | Facts only, unless you told the agent "show my commit titles" (`tell updates { titles: true }`). |

## 5. One link, one question

Do: for every reply above, count the https links and read the last line.

| Check | You should see |
|---|---|
| Links | Exactly one https link. |
| Last line | The reply's only question. |
| Words | No "raise", "raising" or "fundraise". |

## If a check fails

Send back: the reply text, the time, the agent, and the client.

## Known behaviours

| Behaviour | What to expect |
|---|---|
| Pre-v2.14 unclaimed agents that reconnect (D11) | They start fresh: a new installation, old data stays behind. The App install is one click. |
| No merge | A second agent attaches alone; its old group and data never merge into the page. |
| Shared clients (Grok Bot) | No App links and no coin launches. They keep the anonymous approval. |
| Pre-v2.14 proofs | Count on the Bench, but need the App before a coin, a deploy or hosting. |
| An App proof | Replaces another person's discovery-derived hold on the same repo. |
| Deploy caps | Per repo owner. |
| Titles-only weeks | Stay off the feed. |
| Unknown redirects | See a warning page naming the host. Straight to X: the three documented callbacks (claude.ai, chatgpt.com, www.cursor.com), loopback, and the app schemes cursor, vscode, vscode-insiders, windsurf, claude. |
| Unanswered v2.13.4 joins | Detached at deploy (none on production). |
| A refused re-authorization | Keeps the token the agent already had. |
