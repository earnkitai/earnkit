## Rulings

- R1 A `links` field is filled from exactly one URL: `project_field` decides when set (`live_url`, `repo_url`, `demo_url`). Otherwise the key and label decide: site, website, live, product, app, url (alone) take `live_url`; repo, github, code, source take `repo_url`; a text field whose label is only "links" or "relevant links" may take both joined by a space. A key or label naming x, twitter, linkedin, farcaster, discord, telegram, deck, pitch, other is the builder's: `value: null, from: 'builder'`. A url-type field never receives two URLs.
- R2 Linked or not, `contact`, `traction` and `raised` fields, and any field whose key or label matches amount, budget, consent, birth, phone, age, citizen, gender or ethnic, are the builder's (`from: 'builder'`). `from: 'agent'` is only for prose kinds and `other` text drafted from the repo and the field's sources. The builder line becomes "Drafted: N of M answers from the repo, the rest your agent asks you once." and the agent note says "'agent' fields you draft from the repo and the field's sources; 'builder' fields you ask once, all together. Never invent a personal fact, an amount or a number."
- R3 Unlinked `find` applies `tierGate` with a provisional tier from `RepoFacts`: `live` when `live_url_basis === 'code'` or a contract with `basis === 'code'` on a mainnet chain; `building` when the public repo was read (`public && !as_reported`); `null` (no gate) when the repo could not be read. A program gated out goes to gaps with the line "Link GitHub so EarnKit can confirm your product is live." The provisional tier never reaches `evidence_summary`, which stays null unlinked.
- R4 Unlinked `find` runs `blockersOf` with an empty record (a default `BuilderRecord` with no sign-ins and default policy), so `sign_in`, `needs_click` and `needs` blockers are named exactly as when linked; `outside_approval` is never set unlinked. `in_person` programs keep their block.
- R5 When unlinked and a sign-in link exists, the reply ends with one call to action: the sign-in line replaces `closingLine` instead of following it.
- R6 Docs copy: "Approve it when the page opens. No account needed." becomes "It connects at once. No account needed." in all three places; step "2 Approve the connection" becomes "2 It connects on its own". The authorize endpoint is a 302 with the code (oauth-routes.ts authorizeGet).
- R7 `screen` unlinked answers "Sign in once at <link> so EarnKit knows which program you review for." with the installation's link (as `find` and `record` give it); `notReviewer` becomes "You are not yet a reviewer for that program here. Ask EarnKit to add you.".
- R8 `record` with `set` while unlinked answers "Not saved. Sign in once at <link>, then tell me again." instead of the plain sign-in line; `get` keeps the current line.
