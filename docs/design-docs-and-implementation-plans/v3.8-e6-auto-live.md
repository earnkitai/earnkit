# v3.8 E6: official-page check, organizer status, approval deleted

Plan: `/workspace/cto/earnkit-power-user-plan-v3.8.md` item 5, decisions 21 and 25, cutover A1. Approval: earnkitai/earnkit#159.

## What changes

- **No owner approval of any kind.** `app/api/programs/approve`, `approveGet`/`approvePost`, the signed approve link
  (`approveToken`, `approveUrl`, `approveTarget`, `approveExpiry`), the pending email (`mailPending`,
  `pendingMailText`, `PENDING_SUBJECT`, `owner_emailed`, `MAIL_FAILED`) and the approve confirm page are deleted.
  `no-approval.test.ts` fails if any returns. The revert link and its confirm page stay until E7 moves revert to a
  bearer-token read.
- **`auto_live` on** (`EARNKIT_FLAGS`): an upsert must carry `amount_quote`, `deadline_quote`, `found_by_query`,
  `found_by_source` (optional `handle`, `evidence_url`). `official-page.ts` fetches `official_url ?? source_url` with
  `safeProbePage` (guarded GET, 64 KB, one same-site redirect, 5 s). The visible text (hidden elements dropped, so a
  quote hidden from people never counts; entities decoded; whitespace folded) must contain each quote verbatim, case
  kept. Each quote must also name the record: the amount quote one of `pool_usd`/`max_award_usd`/`min_award_usd`, the
  deadline quote `ends_at`'s day (ISO date, or month and day; ±1 day for zones) or "rolling" words when `ends_at` is
  null. Without the tie, a real "$5" line on the page could carry a $5M write. A failure is 400, audited with its
  found-by fields, mailed to no one.
- **Organizer status (decision 21 step 2).** Confirmed when the page's registrable domain is: the `tracked_handles`
  profile domain for the sent handle (Growth fills it through `action: handle`), a domain of an earlier program of the
  same organizer (name case/space-folded) that is not itself new organizer, or a domain linked from `evidence_url`
  when that page is itself on a domain already confirmed for the organizer (fetched and checked by the API). Otherwise
  `new_organizer: true`. Rule 4 (host platform page linked from the handle's own X post) needs X reads and is not
  checked; such pages stay new organizer, which is the safe side.
- **Information only (step 6).** `submission_url` or `form.url` not linked from the fetched page (and not the page
  itself) sets `info_only: true` and drops `form` (no prefill).
- **Enforcement.** Either label forces the stored record's `submit` to `builder`. Every existing builder-submit path
  then applies: find's blockers mark it `needs_click`, so it is never sendable and never on the standing-approval
  list; guide says "You send it." Track additionally refuses it as a standing send (`NEW_ORGANIZER_SEND`,
  `INFO_ONLY_SEND`) and find's program agent note says never submit and never connect a wallet. EarnKit has no
  wallet-connect code today; the note and `agentMayAct` are the contract any future one must read.
- **Clearing.** The check re-runs on every write, from the caller's record, so the label and the forced `submit`
  clear as soon as a rule holds. Writers cannot send `new_organizer`/`info_only` (refused).
- **`auto_live` off** keeps today's held lane: same pending rule, no email, no approve link, nothing applies it.
