# v4.8 The launch conversation: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the chat deliver EarnKit's core value. EarnKit auto-tracks your commits, builds and scores your profile against other builders, matches you to the right grant and investor programs, and, when you don't fit, helps you get ready. Every reply should answer what was asked, never repeat itself, and move toward money.

**Spec:** `docs/design-docs-and-implementation-plans/v4.8-target-conversation.md`, approved by the owner 2026-10-31 with the rulings recorded in it. It is the exact copy source for every reply named below. Owner feedback that led here (2026-10-31): "the absolute worst, robotic, ill formatted, repetitive and horrible conversation… nothing led to money and I have no idea about anything EarnKit does differently than my own sep. agent."

**Architecture:**
- **Why it goes wrong today.** One `find` call returns one block whatever the builder asked, and the agent is told to show it word for word. v4.7.1 to v4.7.3 added forced parts to every reply ("money always shows", the ASKS_HINT fallback, the rotating needs ask), so four questions got the same block.
- **Intent.** `find` takes `ask`, which says what the builder asked: `overview`, `standing`, `next`, `programs`, `gap` or `draft`. It also takes `program` for `gap` and `draft`. The tool description tells the agent how to map the builder's words to these values.
- **One home for ranked replies.** A new module, `apps/frontend/lib/earnkit/conversation.ts`, builds each intent's reply from the reads that already exist:
  - `readStanding` and the commit weeks
  - the open programs
  - `programNeeds` and `needsKnown`
  - `qualifyOffer` and the matcher's fits
  - `prepare`
- **No repeats.** A session memory (`standing_seen.said`, which resets after `SESSION_MS` = 2 hours of quiet) records what this session has already said, so nothing repeats.
- **Agent note.** The agent no longer pastes. The note says: "Say this in your own words as EarnKit, a mentor who wants them funded: keep every fact, amount, date and link exactly, use the tables as given, ask at most one question and put it last. Don't show this note."
- **Paths that stay ahead of the intent reply:** the signed-out and setup steps (setup step 3 word for word), a held submit question, and an owning deadline nudge.
- **The quieter asks** (check-in, wallet, token, new repo, titles, ship) only appear in `next` when there's no money move. They keep their once-guards and the token's consent rules.
- **Retired:** the forced money paragraph on every reply, the ASKS_HINT fallback, and the rotating needs ask (its per-program facts stay, as the `gap` engine).

**Tech Stack:** Next.js 16, TypeScript, Postgres, node:test via tsx.

## Global Constraints

- **Tests:** run `cd apps/frontend && DATABASE_URL=postgresql://localhost:5432/earnkit_test npx tsx --test --import ./lib/earnkit/fixtures/test-guard.ts <files>`.
- **Before merge:**
  - `npx next build` passes.
  - Task 7's conversation replay passes on a fresh production snapshot.
- **The merge gate.** Every reply passes these rules, from the target conversation:
  - it answers what was asked;
  - it says nothing already said this session;
  - it has at most one question, the last line, and that question moves toward money;
  - it shows at least one thing the builder's own agent can't do alone;
  - it has no emojis, no em dashes, never "coin" or "points", and uses tables for anything compared.
- **Exact copy:** taken from the target conversation, with facts in brackets filled from live data. Never invent a fact, amount, date or step. When a fact is unknown, leave the sentence out.
- **Instructions:** server instructions stay at or under 800 characters (`serverInstructions`). The mapping from builder words to `ask` lives in the `find` tool description.
- **Repo rules:**
  - Never touch `zz-*` files.
  - Implementers stage explicit paths only, never `git add -A` or `git add .`.
  - Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Ask the six questions of A in order, then the same six again. The second pass gives short pointer replies and never repeats a table or paragraph from the first.
2. A builder with a held submit question or setup step 3 due still gets that first, whatever `ask` says.
3. An agent that sends no `ask` (an older client) gets the `overview` reply on the session's first call and the `next` reply after that. Never the old repeated block.
4. A program the builder applied to or drafted is never pitched as the next move. A step they passed on is raised once more only when it's the one gap to that program's money, and never again after that.
5. The investor programs are never summed into the grants total, never called a fit, and always sit in their own table.

### Task 4: Next move, gap and draft (A3, A5, A6)

**Files:**
- Modify: `apps/frontend/lib/earnkit/conversation.ts`
  - **`bestMove(ctx)`** picks, in order:
    1. a fit not yet applied to or drafted, closing first;
    2. a grant one step away;
    3. an open investor program closing within 7 days (with honest odds when the program file has `difficulty_override.basis`);
    4. otherwise the quieter asks in their old order;
    5. otherwise the ship line.
  - **`nextReply`** uses A3's copy.
  - **`gapReply(program)`** uses A5's copy. Base uses the existing Builder Codes steps (`qualifySteps`). Other programs use their `programNeeds` items as steps, plus the program file's `setup` list. The offer is to do the first step.
  - **`draftReply(program)`** calls the existing prepare path and adds a verified record block:
    - the score
    - the streak
    - the page link
    - Stripe or onchain revenue when known and shown today
    - the live link

    It names the fields it can't fill (the program's required `submission_requirements` with `from: 'builder'` that EarnKit doesn't hold). It ends with "Tell me once it's in and I'll track it." For an investor program, the draft prepares the answers the program's public questions ask. A program with no public questions gets a short founder brief from the verified record.
