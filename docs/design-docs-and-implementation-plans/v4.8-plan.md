# v4.8 The launch conversation: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** EarnKit leads a lazy, money-motivated builder from install to a submitted application, then on to the next program. EarnKit speaks first and ends every message with one easy reply. A yes means EarnKit does the work. Along the way, the core value shows on its own: commits tracked automatically, a profile scored against other builders, verified matches, and help closing the gap.

**Spec:** `docs/design-docs-and-implementation-plans/v4.8-target-conversation.md`, approved by the owner 2026-10-31. It is the exact copy source.

Owner feedback that led here, 2026-10-31:
- "the absolute worst, robotic, ill formatted, repetitive and horrible conversation… nothing led to money."
- "Most builders will need to be led where the agent drives the conversation and encourages a reply. By default, assume no one cares about EarnKit… most builders are motivated by money in the end."

**Architecture:**
- **The path.** Each builder has a path stage, kept in `standing_seen.path`: `{ stage, program_id, at }`. The stages are:
  - `hook`: an open program named for them
  - `gap`: closing a missing step
  - `draft`: the draft is out, with blanks to fill
  - `submit`: waiting for "sent"
  - `track`: applied, and the next program is lined up
- **One reply per stage.** `conversation.ts` builds the reply for the stage. The reply always has:
  - the money line, at most once per session (see Repeats)
  - one proof line, which shows a fact only EarnKit holds
  - one easy reply: a yes, a number, or "sent"
- **`find` with no question (session start).** A new session opens on the path's current step. If something changed since last time (new shipped weeks, a new fit, a deadline under 48 hours, an outcome), that change leads.
- **A yes advances the path.** The existing `tell` answers move the stage on. In `gap`, the agent note tells the agent to do the step itself and then call find. In `draft`, it fills the draft through the existing prepare path. In `submit`, "sent" is recorded with `tell program_status applied`.
- **Direct questions.** `find` takes `ask` (`standing` or `programs`), plus `program` when the builder names one. The answer comes first, then the path's step. When `ask` is missing, the reply is the path.
- **Picking the program, `bestMove`**, in this order:
  1. a real fit not applied to or drafted, closing first
  2. a grant one step away (a passed step is raised once, only when it's the one gap)
  3. an investor program closing within 7 days, with honest odds when the program file states them
  4. the closest grant by number of gaps
  5. otherwise the quieter asks in their old order (check-in, wallet, token by its consent rules, new repo, titles), then the ship line
- **New builders.** Before GitHub is connected, the first reply is B's numbered pick plus the connect link. A pick is stored as the path's program.
- **The agent note.** "Say this in your own words as EarnKit, a mentor who wants them funded: keep every fact, amount, date and link exactly, ask for only the one reply given and put it last. When they say yes to a step you can do, do it, then call find. Don't show this note."
- **What still goes first:** setup step 3 (word for word), a held submit question, and an owning deadline nudge.
- **Retired:**
  - the forced money paragraph on every reply
  - the ASKS_HINT fallback
  - the rotating needs ask, whose per-program facts stay as the gap engine
  - the v4.7 money-first apply loop, which the path's `hook` and `draft` stages replace
- **Repeats.** `standing_seen.said` resets after `SESSION_MS` (2 hours) of quiet. A part already said in this session is never said again. The same step a second time gets a one-line pointer.

**Tech Stack:** Next.js 16, TypeScript, Postgres, node:test via tsx.

## Global Constraints

- **Tests:** run `cd apps/frontend && DATABASE_URL=postgresql://localhost:5432/earnkit_test npx tsx --test --import ./lib/earnkit/fixtures/test-guard.ts <files>`.
- **Before merge:**
  - `npx next build` passes.
  - Task 6's conversation replay passes on a fresh production snapshot.
  - The owner reads the replayed transcripts and says go.
- **The merge gate.** Every reply:
  - ends in exactly one easy reply (a yes, a number, or one named word), never an open question;
  - repeats nothing already said this session;
  - carries one proof line;
  - heads toward a submitted application;
  - has no emojis, no em dashes, never "coin" or "points".
- **Exact copy:** taken from the target conversation, with facts in brackets filled from live data. Never invent a fact, amount, date or step. If a fact is unknown, the sentence is left out.
- **Instructions:** the server instructions stay at or under 800 characters (`serverInstructions`).
- **Repo rules:**
  - Never touch `zz-*` files.
  - Implementers stage explicit paths only, never `git add -A` or `git add .`.
  - Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A lazy builder.** A builder who only ever replies "ok", "yes", "1" or "sent" reaches a submitted application in A and in B. A builder who says nothing and comes back days later is opened with what changed and the next money step.
2. **"No" is respected.** A no to a step parks that program for `DECLINE_MS`, and the path moves to the next program. It never asks the same thing again that session.
3. **What still goes first.** A held submit question and setup step 3 still come before the path.
4. **Programs are classed right.** An investor program is never called a fit and never summed into the grants total. A program already applied to or drafted is never the hook.
5. **Older agents.** An older agent that never sends `ask` and never calls find at session start still gets the path on each call, never the old repeated block.

### Task 6: Conversation tests as the merge gate
