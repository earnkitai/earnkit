# v2.7: Convert and guide — landing programs, odds and winner insights, tokens, docs

Status: implemented on branch v2.7-convert-and-guide (2026-10-07); plan: v2.7-convert-and-guide-plan.md. Docs site: branch v2.7-docs in /Users/jenil/earnkit-docs-v27 (not pushed). Builds on v2.6 (`main` 5c68a03).

## Goal

- **The landing page** turns visitors into installs by showing real money that is open now.
- **Every program comes with a simple guide:** your odds, what won before, and what the ecosystem wants. Builders pick the right thing and raise their odds.
- **docs.earnkit.com** tells a sponsor everything about EarnKit.
- **"Token"** replaces "coin" everywhere a person reads, because tokens.fun is part of EarnKit's flow.

## Decisions (owner, 2026-10-06)

- **Starting phrase:** "What can I earn?" everywhere (install modal, site description, campaign pages, the agent's tool description).
- **Logos:** program and ecosystem logos are allowed.
  - Remove "EarnKit isn't affiliated with or endorsed by any program's organizer" from the first message.
  - Factual names stay.
- **Stats:** open money, agents earning (installs), and builder bonus.
  - Installs stay hidden until they pass 100.
  - Builder bonus shows total pools; once anything is paid, it shows paid.
- **Wording:** coin → token in all builder-, sponsor- and visitor-facing text.
- **First message:**
  - The per-row builder bonus column is gone (it was repetitive).
  - The token step never mentions Clanker's fees.
- **Docs:** written for sponsors and builders.
  - Sponsor campaigns are presented as "EarnKit builder campaigns: talk to us".
  - Contact: X @jenilt, j@earnkit.com.
- **Every program shows a simple difficulty:** Easy, Medium or Hard.
- **Past winners and ecosystem focus** are researched as part of listing a program, and shown as a short guide.

## 1. Landing page (`/`)

The order of the page:

1. **Hero.**
   - Headline: "Your agent finds money you already qualify for."
   - A live figure: "$60,500 open right now".
   - A button, "Add to your agent", that opens the existing modal.
   - Under the button: "Then ask: *What can I earn?*"
2. **Open programs.** Cards in the EarnKit design system.
   - Each card shows:
     - the ecosystem or program logo;
     - the title and chain;
     - the prize per winner;
     - difficulty (Easy / Medium / Hard);
     - the deadline countdown;
     - the builder bonus pool ("0.42 ETH so far" or "new pool").
   - Sorted by prize. The first 6 show, then "See all".
   - Card actions:
     - "Ask your agent" opens the install modal, with the prompt "What can I earn on <program>?";
     - "Guide" opens `/programs/<id>`.
3. **Stats strip:** Open money · Agents earning (hidden under 100) · Builder bonus.
4. **How it works, in 3 steps:**
   1. Add EarnKit.
   2. Ask "What can I earn?"
   3. Your agent builds and submits. "Your entry gets a token and joins the builder bonus."
5. **Backed by, then the footer**, which links to Docs, Policy and Programs.

**Data and cost:**
- Read server-side from the existing DB with 10-minute revalidation. No new services.
- Logos are stored in the repo under `apps/frontend/public/programs/<id>.svg|png`, taken from each program's or ecosystem's official brand kit or site. The source URL is recorded in the program file.

## 2. Program guide (`/programs/<id>`, and `get_program` in the agent)

One screen, in this order. No paragraphs.

```
Arc Microgrants · 500 USDC per winner · ends Oct 14
Difficulty: Medium — 20 of ~160 entries won last round

What won last time
- USDC payroll and payouts for small teams (3 of 20 winners)
- Agent wallets paying for APIs (2 of 20)
- Example: PayStream — streamed salaries in USDC; judges cited a live mainnet demo

What Arc wants now
- Stablecoin payments · FX · agentic commerce

Your best bet
- A USDC payout tool with a live mainnet demo

Builder bonus: 0.18 ETH so far · leaderboard
```

- **Difficulty** is computed from each program's own data:
  - **Odds:** the past round's winners ÷ submissions.
    - Easy: 25% or more.
    - Medium: 8–25%.
    - Hard: under 8%.
    - These bands are chosen by EarnKit (the owner delegated the choice). A builder only sees the label plus one clause of basis, such as "20 of ~160 won last round".
  - **No past round:** a heuristic from winners per round and the requirements (a video, forms, a mainnet deploy), shown as "Medium (estimate)".
  - The basis is always one short clause next to the label.
- **What won last time:** the top 2–3 themes by count, plus one example winner with what it did and why it won, as judges or organizers said. Facts only, cited in the program file.
- **What the ecosystem wants now:** up to 3 focus tags, taken from the program's current tracks and the ecosystem's published priorities.
- **Your best bet:** one line combining winner themes and focus areas.
  - Curated at listing time and re-verified weekly.
  - Never generated at request time.
  - When the builder has a repo that fits, the agent tailors it.
- **In the first message:** each program row gets a Difficulty column. The full guide comes from `get_program` and the web page.

### Program file additions (schema)

```json
"logo": { "path": "programs/arc.svg", "source_url": "https://…brand kit…" },
"past_rounds": [
  { "label": "Arc Microgrants 2026 Q2", "source_url": "https://…", "submissions": 160, "winners": 20,
    "themes": [ { "theme": "USDC payroll and payouts", "count": 3 } ],
    "examples": [ { "name": "PayStream", "what": "streamed salaries in USDC",
                    "why": "live mainnet demo", "source_url": "https://…" } ] }
],
"focus": { "areas": ["Stablecoin payments", "FX", "Agentic commerce"], "source_url": "https://…" },
"best_bet": "A USDC payout tool with a live mainnet demo",
"difficulty_override": null
```

- `programs:check` validates the shape:
  - every fact has a `source_url`;
  - submissions ≥ winners;
  - at most 3 themes, 1–2 examples and 3 focus areas;
  - short strings (under 12 words, like `ideas`).
- **Listing process:** `programs/README.md` gains a "Past winners and focus" step. The agent researches past rounds on the program's own winner announcements, DoraHacks, Colosseum, Devfolio and the ecosystem's blog or X. It records only what the sources state, never invents counts, and leaves a field out when it can't source it.
- **The weekly re-verification routine** also refreshes `focus` and adds new `past_rounds` when a round's winners are announced.
- **Backfill:** research and fill the 5 open programs (Arc, Colosseum, Monad, Base Builder Grants, Circle) as part of this release.

## 3. First message and the token step

**First message:**
- No per-row Builder bonus column. The builder bonus closes the message instead, joined to the offer, so it is the last thing the builder reads:
  - With repos: "Want me to start on Base Builder Grants with tipjar? Every entry also competes for the builder bonus: 0.60 ETH so far, paid to the top 10 on each program."
  - With no repo: "Pick one and I'll start. Every entry also competes for the builder bonus: 0.60 ETH so far, paid to the top 10 on each program."
  - While every pool is empty: "…competes for the builder bonus, paid to the top 10 on each program from its entries' token fees."
  - It is shown only when at least one shown program has a bonus. "0.60 ETH so far" is the sum of the open rounds' pools.
- A Difficulty column on every row.
- The affiliation line is removed.

**Token step (the confirmation screen, from the owner's test run):**
- **Not ready first.**
  - When the entry can't be submitted yet (for example, it needs a live Arc mainnet link), the screen leads with what's missing, in one line: "Before you submit: a live link on Arc mainnet."
  - It shows no wallet or token row until the entry is ready.
  - `prepare_submission` returns `ready: false` plus `missing: [...]`.
- **A token name is always proposed.**
  - The name comes from the project name. The ticker comes from the v2.3 rules, falling back to the repo name, then the first letters.
  - The builder never has to come up with one; they can change it.
- **Token chain is explicit.**
  - tokens.fun launches on Base (Arc isn't supported), so the row says it plainly: "Your entry gets a token on Base, $TIPJAR: you earn 40% of its trading fees, and it joins the builder bonus."
  - It never mentions Clanker or the protocol cut.
- **Footnote:** "Fees in WETH; tokens.fun pays gas. Terms · Risks." No Clanker.

## 4. Coin → token

- **Every human-facing string becomes "token":** builder messages, agent instructions and tool descriptions, the web pages (landing, `/bonus`, `/policy`, `/programs`), alerts, the docs and the runbook text.
- **Internal identifiers keep their names:** `coin_address`, `coin_launched_at`, function names, SQL. Renaming them would need a risky migration for no visible gain.
- **The copy-review test** fails on the word "coin" in human-facing text, except inside identifiers and URLs.
