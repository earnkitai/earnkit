## Global Constraints

- Builder text (`show_to_builder`, pages, problem lines): no emoji, no em dash, never score, rank, grade, points, coin, token, streak; every builder line ends with a full stop; never a tool, field or file name. Agent notes may name tools, fields and items.
- Refusals are one plain sentence for the builder; the technical detail goes to the agent note or the server log, never to the builder.
- Pinned reply texts are updated to the new text, never loosened.
- Commit messages start with `v6.1.7:`.
- After the last task: `docs/codebase-context/architecture-guide.md` and `code-map.md` describe the ledger invariants, the hosted-tier rule and the /me problem-line words.

## Review Focus

1. Two agents of one builder: A `started`, B `applied`, A `applied`: exactly one application row, the second told it was already sent.
2. A win then a rejection from another agent: the win stays.
3. A tool call nested 10,000 levels deep answers the plain "I could not read that." line, never a 500.
4. A client registered with a hosted-service redirect from an address already over its per-IP limit is still refused.
5. A `/me/policy` post with one bad value changes nothing and names the field.
