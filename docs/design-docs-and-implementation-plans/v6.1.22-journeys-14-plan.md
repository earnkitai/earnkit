## The reply grammar (v6.1.20, the voice of every new line)

1. **Opening sentence**, one line, the state, the project named when given: `For {name}, {n} program{s} {is|are} ready to send now.` (with the shared action: `...; I apply once you say yes.`), `Nothing is ready to send for {name} yet. The closest:`, nothing at all `Nothing fits {name} yet. Tell me more about it, or its repo link, and I look again.` (the whole reply). No name: drop `For {name},` and capitalise.
2. **Blank line, then the programs**, numbered in JSON order, one full sentence each: ready `{n}. {short title} ({money}). {what EarnKit does}.`; one gap `{n}. {short title} ({money}) needs {gap words} first.`; one rule `... needs one yes from you: {rule}.`; several `... needs {first}, then {k} more steps.`; the close inside the parentheses after the money within 14 days; `shortTitle` for every title.
3. **Blank line, then one Also sentence** (in person by name with money, `in person with long odds`, then `{n} more in the full list; {X} closes in {d} days.`).
4. **Blank line, then the closing**, one line, one Say, last: `Say yes and I apply to {short title}.`; signed out `Sign in at {link} so I know the repo is yours, then say yes and I apply to {short title}.`; draft `... and I draft it for you to send.`; rule `Say {n} if the {short title} rule fits you and I draft it.`; users `Do real people use it? Say yes and I check.`; step `Tell me when {step} and I look again.`; sent ask `Did you send {short title}? Say sent and I note it.`; Next one rule away `Next: {short title} ({money}) needs one yes: {rule}. Say yes if that fits and I apply.`
5. Other lines (results, since, report, repo notes) sit between the programs and the closing, a line each.
6. **One program:** `{short title} ({money}{, closes ...}). {state sentence}.`, a blank line, the closing. (Task 2 changes the ready state sentence.)
7. **track:** `Sent {short title}.`, `Tracked: that rule fits you.`, `Noted: {short title} said no.`, `{short title} is back in your list.`

## Review Focus

1. A sent ask is per project: two projects with the same builder-sent program are each asked once, and an old program-only row neither repeats nor silences an ask (Task 1).
2. An earlier-round win never blocks the new round and is never lost or counted twice: the public `won` numbers are the same before and after the new round starts, and higher by one only when the new round is won (Task 1).
3. No reply offers `I apply` on a repo EarnKit cannot read or confirm, and a linked builder off GitHub always has a draft offer when EarnKit can fill the form (Task 2).
4. A rule Say only ever names a row under one step away, and an empty repo is never asked a license step or rule before its code (Task 2).
5. A project with no contracts read or reported never sees an audit program; one with contracts still does (Task 4).
