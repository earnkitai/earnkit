# v3.8 E13: reply fields (status, state) and JSON errors

**Approval:** Jenil, "Yes, build v3.8" (Nov 24 2026), logged in earnkitai/earnkit#159. Plan: power-user plan v3.8
section 23.6 (how a tool reply is built) and 23.7 (one test that every reply has `status` and `state`); build plan row E13.

**Goal:** a host branches on data, not on the builder line. Every tool reply carries `status` and `state`; errors that
were one plain text line are the same JSON shape. Behind `reply_fields`; off, every reply is byte for byte main's.

**Contract (`lib/v5/reply-fields.ts`):**

- `status`: `ok`, `needs_builder` (the reply asks the builder for something: sign in, a yes, a result), `refused` (a
  refusal, an input error, a rate limit, an unknown or old tool name) or `error` (EarnKit failed: busy).
- `state`: where the builder is after the call, one of `REPLY_STATES` (the 23.5 journey: `not_signed_in`,
  `signed_in`, `nothing_ready`, `ready`, `needs_fact`, `needs_build`, the track stages `found` to `delivered`,
  `on_hold`, `skipped`, plus `listed`, `checked`, `screening`, `screened`). A refusal or error changed nothing: `unchanged`.
- Derived from the reply and the arguments (`replyFieldsOf`, pure): track from the status sent (a refusal is
  `unchanged`); find from `linked`, `ready`/`you_send`, `gaps`, `ask_outcome`/`ask_sent`, the one-program `verdict`;
  record from `linked`; screen from `job_id`/`results`.
- The two keys are appended last; no existing key changes. `next` stays track's own until E15 (plan risk 2: do not
  reshape `next` while the flag is off).
- JSON errors, flag on: busy is `{ show_to_builder: BUSY, agent_note: BUSY_NOTE, status: 'error', state: 'unchanged' }`;
  a ZodError is an `inputError` (refused); the rate limit is the limit line plus `LIMIT_NOTE` and
  `retry_after_seconds` (structuredContent unchanged); the route's too-deep, not-an-object and not-UTF-8 answers gain
  the fields; an unknown tool's line and the old-tool refresh text become `errorReply` JSON with no builder line (the text, naming tools, is the agent note). `isError` is unchanged.

**Not in this PR:** a general `next` on every tool and money as `{ amount, currency }` (E15, with the new copy).

**Tests:** `reply-fields.test.ts`: 17 calls across the four tools (refusals, input errors, a start, skips, record
get/set, screen) through the real MCP server: flag on, each has a valid `status` and `state`; flag off, neither key,
and each flag-on reply minus the two keys deep-equals the flag-off reply; busy, limit, route-level and old-tool answers
on and off. The existing suite is the flag-off check against main.

**Rollback:** `reply_fields` off. No schema change.
