# v4.10 Ready-made applications: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At session start, EarnKit picks up to 3 programs, has every one drafted before it speaks, and opens with the finished set. The builder answers once: yes, no, or the numbers to skip.

**Spec:** `docs/design-docs-and-implementation-plans/v4.10-target-conversation.md`. The owner approved it on 2026-11-01. Its copy and rules are binding.

**Architecture:**
- A pure selector `readySet` (new `ready-set.ts`) ranks the programs.
- A pure copy module (`ready-copy.ts`) writes the opener and the answers.
- The set lives in `builder_profiles.standing_seen.ready`. It sits beside the single-program `path`, which stays for builders with no set.
- `benchView` puts the set ahead of `pathPlan` on a fresh session. A new `move_up` kind `ready` answers it.
- Drafting splits two ways:
  - EarnKit pre-fills every deterministic answer server-side: verified record, answer bank, X handle, wallet, contact.
  - The agent writes the free-text answers from that record before it shows the opener. The agent note tells it to do so.
- The server still makes no LLM call, so costs stay flat.

**Tech Stack:** Next.js 16, TypeScript, Postgres (jsonb in `standing_seen`, no new table), node:test via tsx.

## Rulings (controller, 2026-11-02; the owner can reverse them before merge)

- **R1. Who gets a set.**
  - A signed-in person on a fresh session, with a ranked project and a non-shared client, who has no held question, and for whom setup step 3 is not due. These are the same conditions as the path today.
  - With 0 programs in the set, the v4.8.2 path runs unchanged. With 1 to 3, the set opens.
  - A set already shown this session is not reshown. A later plain find gives the ready-status reply (Task 4).
- **R2. Ranking.**
  - Order is fit (real fits, then one-step grants, then investor programs, then long shots), then money (`max_award_usd`, larger first), then soonest close.
  - Investor programs count only when they close within 7 days (`INVESTOR_WINDOW_MS`). Long shots are `tag === 'long shot'` or `fitBar` `long_shot`. The Circle-on-Arc case is a long shot labelled with its `fitCell` reason.
  - A program is left out when it closes before its step can be done, using the same check the path's `pathSkip` and closing logic use. It is also left out when it is declined, parked, applied or drafted in the last 30 days, or unlisted or upcoming.
- **R3. "Worth up to"** is the sum of each program's `max_award_usd`, formatted like the money line ($1.1M, $105.5K). Programs with no number add nothing. When none has a number, the clause is left out: "I've got 2 applications ready for you:".
- **R4. What "ready" means.**
  - The opener says "ready" only after the agent has the draft in hand. `find` returns `ready.programs[]` with each program's requirements, the pre-filled answers and the record facts, plus `READY_NOTE`.
  - `READY_NOTE`: "Before you show this, write each program's remaining answers from the record in this result. Never invent facts. Keep them for the builder's yes; on yes call prepare for each program with those answers. Show show_to_builder only after that."
  - On a yes, the agent calls `prepare(program, answers)`, which already exists, for each program. EarnKit never says "sent".
- **R5. What only the builder can give.**
  - A required field that matches `mustAsk` and is not held (a pitch video, a legal entity, a team list) makes the line "Needs your {what} first." That program waits; the others go.
  - At most one such ask is folded into the opener: "Reply yes, and send your {what} for {program} when you can."
  - Answers the builder gives go into the answer bank for every program (`saveBank` by kind), so nothing is asked twice.
- **R6. Steps.**
  - A non-hosted agent with a doable gap (Builder Codes) reads "Ready once I add Builder Codes (10 minutes, I'll do it)."
  - A hosted agent reads "Ready once you add Builder Codes ({guide})."
  - A program waiting on a step opens on the next find, after the existing `codesConfirmed` re-check. The yes reply says so: "Adding Builder Codes now, then I'll open all three."
- **R7. The one easy reply.** The opener's last line is the approved "Reply yes and I'll finish and open each one for you to submit, or tell me the numbers to skip." The gate learns one exception: `easyReply` accepts exactly this ready ask (a constant exported from `ready-copy.ts`). Every other reply keeps today's rule.
- **R8. Answers.** `tell({move_up:{kind:'ready', project_key, answer}})`, where `answer` is one of the following:
  - **`yes`.** Run the steps, then return the submit kits for the programs that need no step.
  - **`no`.** Park every program in the set for `DECLINE_MS`, using the same `declined` keys as the path. The next find runs the path or a quiet reply.
  - **`skip`, with `skip: number[]`** (1-based). Drop those programs, park them, and confirm with "Done, {names} {is|are} skipped. I'll finish {rest} now." Then act as a yes on the rest. A skip of every program acts as a no.
  - **`sent`.** Mark every opened program applied (the existing applied path). With `sent_ids`, mark only those.

## Review Focus

1. A builder who declined, applied to or drafted a program in the last 30 days never sees it in a set. A set never names a program closing before its step can be done. (Task 2's tests cover both.)
2. A yes never produces "sent", "submitted" or "in", and a program waiting on Builder Codes is never given a submit link before the re-check. (Tasks 4 and 5.)
3. "skip 2" with a 2-program set, "skip 4" with a 3-program set, and "skip 1 3" all do the obvious thing. An out-of-range number is ignored with the rest kept, and skipping every program acts as a no. (Task 4.)
4. A hosted agent's set never says "I'll do it". (Task 3.)
5. A second plain find in the same session never repeats the opener paragraph, and walk S (five silent finds) passes the gate. (Task 5.)
