# v6.1.6: programs are ready again, with their rules shown

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Undo the over-correction the second live first-run audit (2026-11-09, after v6.1.5) found: the 52-file catalog encodes thirty free-text program rules as `feature` eligibility items, and `evaluate` turns every one into a gap only `gap_done` can clear, so no remote program is ever "Ready to apply". Then close the audit's other new findings (19 to 26) and the install-copy errors the per-client docs check found.

**Architecture:** A new eligibility kind `rule`: a requirement EarnKit cannot check. It never gates; the verdict carries its text and every reply line shows it as `Their rule: ...` so the builder judges it and the agent confirms it before applying. The thirty catalog items migrate from `feature` to `rule`. The rest is reply text, one money rule for cards, one prefill rule, one track check, and copy.

## Global Constraints

- Builder text (`show_to_builder`, pages): no emoji, no em dash, never score, rank, grade, points, coin, token, streak; every builder line ends with a full stop; never a tool, field or file name. Agent notes may name tools and fields.
- The first reply stays money first, gap, one action ("say yes"). The drafted line shapes (R2c) and the closing block do not change except where a task says so.
- Pinned reply texts are updated to the new text, never loosened to a regex that passes on the old text.
- Catalog edits are mechanical and reversible: a script changes `kind` only; no other field of any program file moves. `pnpm -s programs:check` passes.
- Commit messages start with `v6.1.6:`.
- After the last task: `docs/codebase-context/architecture-guide.md`, `docs/codebase-context/code-map.md` and `programs/README.md` describe `rule`, the cards' money rule and the gap_done check.

**Files:**

- Test: `apps/frontend/lib/v6/link-routes.test.ts`, `me-routes.test.ts`, `me-view.test.ts`, `apps/frontend/lib/v5/find.test.ts`

**Findings (security review, `scratchpad/security/review.md`):**
- H1: an attacker's agent asks for a link, the attacker sends `/link/<code>` to a victim, the victim clicks "Continue with GitHub" once (GitHub auto-approves a known app) and the attacker's installation is linked to the victim's account: `record get` hands over the record and `track` applies in the victim's name. The confirm page's footnote is the only gate.
- M2: the other direction: a leaked code lets an attacker bind the victim's agent to the attacker's account; the victim's agent then writes the victim's facts into the attacker's record and nothing in any reply says a link happened.

**Rulings:**
- The link is confirmed after sign-in, inside the account. `callbackGet` verifies the state and the nonce as today, exchanges the GitHub code, upserts the builder, creates the session, and redirects to `/me?link=<code>` without linking and without marking the code used. The code stays live (15 minutes, single use).
- `meGet` with `?link=<code>` and a live unused code renders a banner above the record: heading `Link an agent to this account?`, text `The agent calling itself {client_name}, first seen {Mon D}, asked for this link. Only link an agent running on your own computer. If someone sent you this link, choose Not me.`, two forms posting to `/me/link` with the session's csrf: `Link this agent` (`action=link`) and `Not me` (`action=deny`). A dead code renders the banner text `This link has expired. Ask your agent for a new one.` with no buttons. `client_name` null reads `your agent`.
- `POST /me/link`: session and csrf as every /me post; `action=link` marks the code used and links the installation to the session's builder in one transaction (reuse the existing transaction; `LinkRefused` answers the existing OTHER text as a 400 page), then 302 to `/me`; `action=deny` sets the code's `expires_at` to now and 302 to `/me`. A used or expired code: 302 to `/me` (the banner shows expired on the next render only if `?link=` is kept; keep it simple: redirect to `/me` with no param).
- `/link/<code>` first page: the footnote becomes `After you sign in, you confirm the link on your record page. Only continue if you asked your agent for this link just now. If someone sent you this link, close this page.`
- The linked notice (M2): the first `find` after a link (the installation's `linked_at` is later than its `last_find_at`, or `last_find_at` is null) adds to the closing block the sentence `This agent is now linked to GitHub account {login}. Unlink any time at earnkit.com/me.` (`login` from `builders.login`; `FindReply` gains `linked_notice: string | null`). It shows once because `markFind` moves `last_find_at`.
