# Code map (v5)

One line per file. Orientation and flows are in `architecture-guide.md`. Tests sit beside the code as `<name>.test.ts` (30 files in `lib/v5`); `lib/v5/journey.test.ts` is the end-to-end walk.

## apps/frontend/lib/v5 (the product)

- `apps/frontend/lib/v5/agents.ts`: Install steps per agent: pure data read by the install sheet, /docs and /llms.txt
- `apps/frontend/lib/v5/api-text.ts`: Text and link rules for the write API: plain visible text, https links on named domains
- `apps/frontend/lib/v5/chains.ts`: Chain registry: slug, ids, RPC and explorer hosts, explorer API (Blockscout or null), EVM or not
- `apps/frontend/lib/v5/confusables-table.ts`: Generated Unicode confusables table (UTS #39); do not edit
- `apps/frontend/lib/v5/confusables.ts`: Look-alike full stops, so link detection reads a hidden domain as one
- `apps/frontend/lib/v5/cron.ts`: POST /api/cron handler: freshness probe, repo cache sweep (and `project_reports` over 180 days), the screen queue's share (`SCREEN_BATCH`), then the owner digest; a JSON body `{ job_id }` runs only that job's queue (300 applicants or 10 minutes) v6.1.14: a `CRON_SECRET` under 32 characters answers 503 with an ops log line (L13-11).
- `apps/frontend/lib/v5/db.ts`: Postgres pool and transaction helpers
- `apps/frontend/lib/v5/deadline.ts`: A program's close in words: close day in its time zone and time left
- `apps/frontend/lib/v5/eligibility.ts`: Repo facts against a program's eligibility items: ready, gap, or no fit; a `rule` is a confirmation gap `rule:<hash8>` outside the two-gap limit (`ruleItem`, `itemKey`, `rulesOnly`); `unlikely`: a rule whose `keywords` the project names nowhere (v6.1.10); `keywordHit`: one whose keywords it names, the two sharing `keywordsNamed` (N1, v6.1.12); `proseOf`: keywords read from prose only, links and code removed (C3, v6.1.13), and `wordsOf`: identifiers dropped too, unless a keyword (L12-2, v6.1.14) v6.1.13 L1e-6: a `needs_repo` grant for existing code is one step (`NEEDS_CODE`, "code in a repo") from a project with nothing to show; the project's chains count as its words for keywords. v6.1.14: `PUBLIC_REPO` (an `open_source` program and a private repo, L1f-1) and `ARCHIVED_REPO` (an archived repo for a program wanting code or users, never the users question, L1f-3), each with its `setup`.
- `apps/frontend/lib/v5/find.ts`: The find tool: ready, gaps, since, ledger, one program's details, or the open list; `shownReadyOf` caps remote and in-person ready apart; saves gaps to `last_gaps`; re-keys a name-only project on the first find with its repo and saves the parsed report per project key (v6.1.13); a claim for another project reads `held_for` (C1); a closed program is one line (v6.1.13) v6.1.13: gap lines carry `keyword_hit` and `closes_in` within 14 days for every kind; the one-program detail keeps the after-yes closing for programs the builder submits. v6.1.14: a gap's `setup` leads the gap program's setup; a failed read falls back to `reportOnlyFacts`, never marked private. v6.1.14 Task 6: `FindArgs` (registered leniently) and `findInputOf` (`readLoosely`, L13-4); a no-project claim holds on every list (L13-8); one `tonight` list over every ready program (L13-9); stamps `last_find_auto` (L13-7).
- `apps/frontend/lib/v5/github.ts`: Public GitHub reads with EarnKit's server token; `ghResponse` and `ghPage` expose the link and rate-limit headers
- `apps/frontend/lib/v5/guide-page.ts`: Data for /programs/[id]: the guide plus page context, as plain JSON
- `apps/frontend/lib/v5/guide.ts`: A program's guide: money, close, who can apply, form fields, rules, sources; no submit line when closed or not open yet (v6.1.13). v6.1.15 (#9): `sentence()`; eligibility, field to-dos, focus (joined with "and"), past rounds, best bet and source labels each read as a sentence, dates as `30 Oct 2026`; a feature item reads its `note`; the header money is `moneyOf`'s, as the tile
